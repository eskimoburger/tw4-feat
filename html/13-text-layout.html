Page 13 · Utilities

Text, forms & layout

The utilities you use every day to wrap text, size form fields, build grids and keep components correct in any writing direction, with what v4.0 to v4.3 added: field-sizing, wrap-anywhere, logical block and inline utilities, safe alignment and bare grid values.

Typography demos load Inter, Roboto Flex and EB Garamond from Google Fonts. Without them the browser falls back to another font, and some effects (font width, OpenType features) will not show.

Balanced and pretty text wrapping

core

text-balance evens out line lengths so a short heading does not end on one stranded word. text-pretty stops a paragraph's last line from being a lone word, and text-nowrap switches wrapping off.

  • text-balance
  • text-pretty
  • text-nowrap
  • text-wrap
  • md:text-balance

Browsers only balance blocks of about six lines or fewer, so use it on headings, not articles. A browser that does not know a value wraps normally, so both are safe to ship. Balancing moves the line breaks, not the box: add mx-auto max-w-* if you also want the block centered.

Docs: text-wrap

line-clamp-* and truncate

core

line-clamp-3 cuts text after three lines and adds an ellipsis. truncate is the single-line version. Use them to keep cards the same height whatever the copy length.

  • line-clamp-2
  • line-clamp-none
  • line-clamp-[7]
  • line-clamp-(--lines)
  • truncate
  • text-ellipsis
  • text-clip
  • min-w-0

line-clamp-* sets display: -webkit-box, so it replaces flex or grid on the same element. truncate works on a flex child by itself, but a wrapper around the truncated text needs min-w-0 (last example).

Docs: line-clamp · text-overflow

wrap-break-word, wrap-anywhere, wrap-normal

v4.1

These set overflow-wrap, which lets a very long unbroken string (an email, URL or hash) break instead of overflowing. wrap-anywhere also counts those break points when sizing, so a flex child can shrink without min-w-0.

  • wrap-break-word
  • wrap-anywhere
  • wrap-normal
  • break-all
  • break-keep
  • break-normal

break-words from v3 is now wrap-break-word (the upgrade tool renames it). break-all is a different property (word-break): it splits every word at the edge, not only the ones that would overflow.

Docs: overflow-wrap · word-break

hyphens-auto, hyphens-manual, hyphens-none

core

hyphens-auto lets the browser add hyphens where a word breaks, using the language's dictionary. hyphens-manual only breaks at soft hyphens you place with &shy;, and hyphens-none ignores even those.

  • hyphens-auto
  • hyphens-manual
  • hyphens-none
  • lang="de"
  • &shy;
  • text-justify

Set lang on the text or an ancestor, or the browser has no dictionary. Safari and Firefox hyphenate out of the box; Chromium needs a hyphenation dictionary and may not hyphenate on every platform. Soft hyphens work everywhere, and wrap-break-word is a good safety net.

Docs: hyphens

tabular-nums and numeric figures

core

tabular-nums gives every digit the same width so columns of prices and live counters line up and do not jitter. The other font-variant-numeric utilities pick fractions, ordinals, zeros and figure styles, and they stack.

  • tabular-nums
  • proportional-nums
  • slashed-zero
  • diagonal-fractions
  • stacked-fractions
  • ordinal
  • lining-nums
  • oldstyle-nums
  • normal-nums

The font must contain the feature. Some UI fonts already use equal-width digits by default, so tabular-nums changes nothing there. These demos use Inter, whose digits are proportional until you ask for tabular ones.

Docs: font-variant-numeric

font-stretch-*

v4.0

Picks a width (condensed to expanded) from a font that has one. Use the nine keywords, a whole-number percentage like font-stretch-75%, a variable, or an arbitrary value.

  • font-stretch-condensed
  • font-stretch-expanded
  • font-stretch-75%
  • font-stretch-[87.5%]
  • font-stretch-(--wdth)
  • sm:font-stretch-normal

It only does something when the font has a width axis (wdth) or separate condensed and expanded faces; otherwise the browser picks the closest face and nothing changes. Percentages must be whole integers: font-stretch-87.5% generates nothing, so write font-stretch-[87.5%]. Out-of-range values clamp to the font's range.

Docs: font-stretch

font-features-[…]

v4.2

Sets font-feature-settings directly, so you can switch on any OpenType feature (small caps, stylistic sets, slashed zero, case-sensitive forms) without a dedicated utility. It also accepts a CSS variable.

  • font-features-['smcp','c2sc']
  • font-features-['ss01','cv11']
  • font-features-['salt'_0]
  • font-features-(--ff)

Reach for the dedicated utilities first (tabular-nums, slashed-zero, diagonal-fractions). The font must define the feature tag, and font-feature-settings wins over font-variant-* when both set the same feature. Use underscores for spaces inside the brackets, and single quotes inside a double-quoted class attribute.

Docs: font-feature-settings

field-sizing-content vs field-sizing-fixed

v4.0

field-sizing-content makes a textarea, input or select size itself to what is typed or selected, so a composer can grow with no JavaScript. field-sizing-fixed restores the normal fixed size.

  • field-sizing-content
  • field-sizing-fixed
  • max-h-[8lh]
  • min-h-[1lh]
  • supports-[field-sizing:content]:*

Supported in Chrome and Edge 123+, and in recent Safari and Firefox releases (check caniuse for the exact versions). Older browsers ignore it and show a normal fixed-size field, so treat it as an enhancement. An explicit w-* or h-* beats content sizing, and rows still sets the minimum height. Also see the variants page.

Docs: field-sizing

appearance-none custom controls

core

appearance-none strips the browser's native look from a checkbox, radio or select so you can draw your own with checked:, peer-checked:, has-checked: and before:. The input stays a real, accessible form control.

  • appearance-none
  • checked:bg-indigo-600
  • peer-checked:visible
  • has-checked:border-indigo-500
  • before:inset-s-0.5
  • forced-colors:appearance-auto

Always add forced-colors:appearance-auto (and hide any custom icon with forced-colors:hidden) so Windows high contrast users keep a visible control. accent-* has no effect once appearance-none is set.

Docs: appearance

accent-* and caret-*

core

accent-* tints native checkboxes, radios, range sliders and progress bars. caret-* sets the text cursor color. It is the cheapest way to match form controls to your brand while keeping native behavior.

  • accent-indigo-600
  • accent-(--brand)
  • accent-[#50d71e]
  • accent-auto
  • caret-pink-500
  • caret-(--c)

accent-* only affects native controls and does nothing on appearance-none ones. The opacity modifier (accent-indigo-600/50) is not supported in every browser. Also see the variants page.

Docs: accent-color · caret-color

placeholder: and file: variants

core

placeholder: styles the hint text inside an input or textarea, and file: styles the native "Choose file" button. They stack with hover: and dark:.

  • placeholder:text-slate-400
  • placeholder:italic
  • file:rounded-full
  • file:bg-violet-50
  • hover:file:bg-violet-100
  • file:me-4

In v4 the default placeholder is the current text color at 50% opacity, and the old placeholder-opacity-* utilities are gone: put the opacity in the color, such as placeholder:text-slate-500/70. Prefer file:me-4 over file:mr-4 so the gap flips in RTL. More on both variants on the selector variants page.

Docs: ::placeholder · ::file

resize-*

core

Controls the drag handle on a textarea, or on any element with overflow other than visible: resize-none, resize-y, resize-x, or resize for both directions.

  • resize-none
  • resize-y
  • resize-x
  • resize
  • min-h-24
  • max-w-full

The both-directions class is resize, not resize-both. Pair it with min and max sizes so a panel cannot collapse or break the layout. Touch browsers often hide the handle.

Docs: resize

Logical spacing and borders

v4.2

v4.2 adds block-axis padding, margin and border utilities (pbs-*, mbs-*, border-bs-* and their -be- twins) next to the inline ones you already had (ps-*, me-*, border-s-*). Build a component once and it lays out correctly in LTR, RTL and vertical writing modes.

  • pbs-3
  • pbe-4
  • mbs-3
  • mbe-1
  • border-bs
  • border-be-2
  • border-bs-indigo-500
  • ps-4
  • pe-10
  • ms-auto
  • me-2
  • border-s-4

Inline runs along the text direction (left to right, right to left, or top to bottom in vertical-rl). Block is the perpendicular axis (top to bottom in horizontal text, right to left in vertical-rl). There is no rounded-bs; corner radius uses rounded-ss, -se, -es and -ee.

Docs: padding · margin · border width

Logical sizing: inline-* and block-*

v4.2

inline-* sets inline-size and block-* sets block-size, plus min- and max- versions. In horizontal text they are width and height; in vertical text they swap. They take the spacing scale, fractions, container sizes, keywords and arbitrary values.

  • inline-32
  • block-16
  • inline-1/3
  • inline-full
  • inline-md
  • min-inline-48
  • max-inline-[65ch]
  • min-block-24
  • max-block-48
  • block-lh

inline-32 and block-16 are sizes; the bare inline and block are still the display utilities. Percentages and fractions are relative to the container's inline or block size. There is no max-inline-prose: write max-inline-[65ch].

Docs: inline-size · block-size · max-inline-size

Logical inset: inset-s-*, inset-e-*, inset-bs-*, inset-be-*

v4.2

Position an absolutely placed element from the start or end edge of its container: inset-s-* and inset-e-* on the inline axis, inset-bs-* and inset-be-* on the block axis. They replace start-* and end-*, which are deprecated.

  • inset-s-0
  • inset-e-4
  • inset-bs-2
  • inset-be-0
  • -inset-s-2
  • inset-s-1/2
  • inset-s-full
  • start-0 (deprecated)

start-* and end-* were deprecated in 4.2.0. They still compile in 4.3.3, and @tailwindcss/upgrade rewrites them to the inset-s-* and inset-e-* form. Bare start and end without a value stopped generating CSS in 4.3.0.

Docs: top / right / bottom / left

Logical scroll offsets

v4.2

scroll-pbs-* and scroll-pbe-* set scroll padding on the block axis, scroll-mbs-* and scroll-mbe-* set scroll margin. With the older scroll-ps-* and scroll-ms-* they keep snap offsets and anchor offsets correct in any direction.

  • scroll-pbs-12
  • scroll-pbe-8
  • scroll-mbs-6
  • scroll-mbe-4
  • scroll-ps-6
  • scroll-pe-6
  • scroll-ms-4
  • scroll-me-4

Scroll padding goes on the scroll container (it shrinks the area snapping aligns to), scroll margin goes on the snap target or anchor target. Both examples below are live: scroll them.

Docs: scroll-padding · scroll-margin

size-* and dynamic spacing values

v4.0

Every spacing-based utility (w, h, size, p, m, gap, inset and more) accepts any number and computes calc(var(--spacing) * n). w-17, size-22 and mt-29 just work, with no config. size-* sets width and height together.

  • size-17
  • w-17
  • h-13
  • p-13
  • size-1/2
  • size-fit
  • size-(--avatar)
  • size-[3rem]

size-* itself arrived in v3.4; the any-number behavior is what v4.0 added. Change --spacing in @theme to rescale every one of these at once. The browser build compiles a class the moment it appears in the DOM, so classes added by JavaScript work too.

Docs: width · customizing the scale

aspect-8.5/11 and ratio utilities

v4.2

aspect-<n>/<m> takes any whole-number ratio, and from v4.2 either part can also be a multiple of 0.25, so US Letter is aspect-8.5/11. aspect-video and aspect-square stay as named shortcuts.

  • aspect-8.5/11
  • aspect-210/297
  • aspect-3/2
  • aspect-2.5/1
  • aspect-video
  • aspect-square
  • aspect-(--ratio)
  • aspect-[2.35/1]

Only multiples of 0.25 compile as bare values: aspect-8.3/11 and aspect-2.35/1 generate nothing, so use aspect-[2.35/1]. Whole numbers such as aspect-210/297 (A4) always worked.

Docs: aspect-ratio

Viewport units: h-dvh, min-h-svh, h-lvh

core

The small (svh), large (lvh) and dynamic (dvh) viewport units fix full-height layouts on phones whose browser toolbars slide in and out. v4 offers them on every width, height and size utility.

  • h-dvh
  • h-svh
  • h-lvh
  • min-h-svh
  • max-h-dvh
  • w-dvw
  • size-dvh
  • h-screen

svh is the smallest viewport (toolbars showing), lvh the largest (toolbars hidden), dvh follows the toolbars as they move. Prefer min-h-svh for page shells: it never gets cut off by a toolbar and does not jump while scrolling. On a desktop all three are equal.

Docs: height · width

Line-height sizing: h-lh

v4.1

h-lh sets a height of exactly one line of the element's own line-height (the lh unit), so skeleton bars and icons match the text next to them at any font size. min-h-lh, max-h-lh and the logical block-lh follow, and arbitrary values like min-h-[3lh] size boxes in lines.

  • h-lh
  • min-h-lh
  • max-h-lh
  • block-lh
  • min-h-[3lh]
  • max-h-[8lh]

Added in v4.1.5. There is no size-lh or w-lh. The lh unit resolves against the element it is set on, so put h-lh where the text size is inherited. Supported in current Chrome, Safari and Firefox (Chrome 109, Safari 16.4, Firefox 120).

Docs: height

Dynamic grid: grid-cols-15, col-span-7

v4.0

Grid track counts and spans are no longer capped at 12. Any positive integer works: grid-cols-15, grid-cols-24, col-span-7, col-start-14, row-span-9.

  • grid-cols-15
  • grid-cols-24
  • grid-rows-15
  • col-span-7
  • col-start-9
  • col-end-13
  • row-span-9

Values must be positive integers: grid-cols-0 generates nothing. For template syntax such as repeat(auto-fill, minmax(8rem, 1fr)) you still write an arbitrary value.

Docs: grid-template-columns · grid-column

grid-cols-subgrid and grid-rows-subgrid

core

A grid item can borrow its parent's tracks instead of making its own. Cards that span the parent's rows then share row heights, so titles, feature lists and buttons line up across siblings with no fixed heights.

  • grid-rows-subgrid
  • grid-cols-subgrid
  • row-span-3
  • col-span-2

The subgrid item must also span the tracks it adopts (row-span-3 for three rows). Added in v3.4; supported in all current browsers (Chrome 117, Firefox 71, Safari 16).

Docs: implementing a subgrid

Bare auto-rows-12 and auto-cols-16

v4.3

auto-rows-* and auto-cols-* take bare numbers from the spacing scale, so implicit rows and columns can be a fixed size without an arbitrary value. They first shipped in v4.3.2.

  • auto-rows-12
  • auto-cols-16
  • auto-rows-24
  • auto-rows-min
  • auto-cols-max
  • auto-rows-[3rem] (old)

They size only the implicit tracks, the ones created beyond grid-template-*. auto-rows-px and auto-cols-px generate nothing, so use auto-rows-[1px]. Another example is on the v4.3 utilities page.

Docs: grid-auto-rows · grid-auto-columns

Safe alignment: justify-center-safe, items-center-safe

v4.1

Safe alignment centers or end-aligns content only while it fits. Once it overflows, it falls back to start alignment, so the content is never pushed off the unreachable side of a scroll container.

  • justify-center-safe
  • justify-end-safe
  • items-center-safe
  • items-end-safe
  • self-center-safe
  • justify-self-center-safe
  • place-content-center-safe
  • place-items-center-safe

Only the center and end values have -safe versions. To see a difference the content must really overflow: give the children shrink-0 or a fixed size, and the container overflow-auto so the content can be scrolled to. Browsers that do not know the safe keyword ignore the declaration and fall back to earlier alignment.

Docs: justify-content · align-items

items-baseline-last and self-baseline-last

v4.1

items-baseline-last aligns flex or grid items on the last line of their text instead of the first, so a note, price or timestamp sits level with the end of a multi-line description.

  • items-baseline-last
  • self-baseline-last
  • items-baseline
  • self-baseline

Items need text to align on; an item without a baseline falls back to end alignment. self-baseline-last only lines up items that all opt in, so put it on every item you want aligned (or use items-baseline-last on the container). Supported in current Chrome, Firefox and Safari.

Docs: align-items · align-self

Scroll snap carousels

core

Put snap-x snap-mandatory on a scrolling row, snap-start or snap-center on its children, and the browser builds a swipeable carousel with no JavaScript. scroll-ps-* keeps a gap at the start edge.

  • snap-x
  • snap-y
  • snap-mandatory
  • snap-proximity
  • snap-start
  • snap-center
  • snap-always
  • scroll-ps-6
  • scrollbar-none

Snap alignment goes on the children, which need shrink-0 in a flex row; scroll padding goes on the container. scrollbar-none arrived in v4.3 (see the v4.3 page); hiding the scrollbar means you should offer buttons, as below. scroll-smooth does not animate scrollBy calls that pass their own behavior.

Docs: scroll-snap-type · scroll-snap-align

overscroll-contain and scroll-smooth

core

overscroll-contain stops a scroll from carrying over to the page once an inner list reaches its end. scroll-smooth animates anchor jumps and scrollTop changes instead of snapping.

  • overscroll-contain
  • overscroll-none
  • overscroll-auto
  • overscroll-y-contain
  • scroll-smooth
  • motion-reduce:scroll-auto

overscroll-contain only matters on an element that scrolls itself, and overscroll-none also removes the bounce effect. Put scroll-smooth on the scrolling element (usually html), and add motion-reduce:scroll-auto for people who ask for less motion.

Docs: overscroll-behavior · scroll-behavior

columns-* masonry with break-inside-avoid

core

columns-3 flows content into three CSS columns, and columns-xs picks as many columns as fit a width. Add break-inside-avoid to each card so it is never split between columns: a simple masonry with no JavaScript.

  • columns-2
  • columns-3xs
  • columns-xs
  • columns-[30vw]
  • gap-4
  • break-inside-avoid
  • break-inside-avoid-column
  • break-after-column

Items fill one column top to bottom before starting the next, so reading order differs from a row layout. Space cards with mb-*, not gap-y-* (column gap only separates the columns).

Docs: columns · break-inside

bg-size-[…], bg-position-[…] and bg-top-left

v4.1

bg-size-[…] and bg-position-[…] take any CSS value, or a variable with the (--name) form. bg-top-left, bg-top-right, bg-bottom-left and bg-bottom-right are the corner names (vertical first).

  • bg-size-[16px_16px]
  • bg-size-[200%_100%]
  • bg-size-(--tile)
  • bg-position-[center_top_1rem]
  • bg-position-[100%_0]
  • bg-top-left
  • bg-bottom-right

Underscores become spaces. The older bg-left-top, bg-right-top, bg-left-bottom and bg-right-bottom still compile as legacy names for v4.0 and earlier, but new code should use the vertical-first form. Animate position with transition-[background-position].

Docs: background-size · background-position
