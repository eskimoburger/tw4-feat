Gradients

Linear, radial and conic gradients, colour stops and positions, interpolation modes, and the patterns people build from them: gradient text and borders, mesh backgrounds, animated pans, spinners and striped bars. Most of it was renamed or extended in v4.

Linear gradient directions

v4.0

bg-linear-to-r and its seven siblings point a gradient at a side or corner. They replace v3's bg-gradient-to-*. The colours come from from-*, via-* and to-*, and v4 interpolates in oklab by default.

  • bg-linear-to-t
  • bg-linear-to-tr
  • bg-linear-to-r
  • bg-linear-to-br
  • bg-linear-to-b
  • bg-linear-to-bl
  • bg-linear-to-l
  • bg-linear-to-tl
  • bg-none

Docs: background-image

Direction utilities have no negative form (-bg-linear-to-r generates nothing). They all set the same property, so a responsive swap like the one above simply replaces the direction.

Colour stops: from, via, to

core

from-*, via-* and to-* set the start, middle and end colours of any gradient type. They take palette colours, theme colours, arbitrary values and CSS variables. A missing end stop fades to transparent.

  • from-indigo-500
  • via-purple-500
  • to-pink-500
  • from-[#ff0080]
  • from-(--brand)
  • from-transparent

Docs: gradient color stops

The missing stops default to transparent, so a lone via-* makes a soft band. That is handy for shimmer highlights and surprising everywhere else.

Gradient stop positions

core

Add a percentage to from-, via- or to- to say where a colour sits along the gradient. Two stops at the same position make a hard edge. Pixel lengths need brackets, and v4 lets a CSS variable carry a position when you hint its type.

  • from-10%
  • via-30%
  • to-90%
  • from-[25px]
  • to-[calc(100%-25px)]
  • via-(length:--p)

Docs: stop positions

from-60% and via-60% sit on the same position, so green stops dead at 60% and amber begins. Amber then ramps to rose, which holds from to-85% onward. There are only three stops, so a bar with two hard edges needs an arbitrary bg-[linear-gradient(…)].

Write from-[25px], not from-25px: bare lengths are not generated. A variable on its own, as in via-(--p), is read as a colour, so add the length: hint (the reference calls this resolving ambiguities).

Linear gradient angles

v4.0

bg-linear-45 sets the angle in degrees, and any positive whole number works. A leading minus negates it. 0 points up, 90 points right, 180 points down. Decimals and variables go through the arbitrary forms.

  • bg-linear-0
  • bg-linear-45
  • bg-linear-65
  • -bg-linear-45
  • bg-linear-[22.5deg]
  • bg-linear-(angle:--a)

Blog: linear gradient angles · Docs

bg-linear-22.5 is not generated, so use bg-linear-[22.5deg]. Arbitrary angles also skip the oklab hint and refuse an interpolation modifier.

Arbitrary and variable gradients

v4.0

bg-linear-[...] takes a raw gradient: either a whole list of angle and stops, or just an angle that you combine with from-* and to-*. bg-linear-(--my-gradient) reads it from a CSS variable.

  • bg-linear-[25deg,red_5%,yellow_60%]
  • bg-linear-(--my-gradient)
  • bg-linear-[25deg]
  • bg-linear-[to_right_in_oklch]

Docs: custom value

Do not mix a full arbitrary list with from-*/to-*: the whole list lands in the gradient's position slot and the stop utilities get appended after it. Use an angle-only (or position-only) value when you also use stops. Arbitrary values skip the in oklab hint that named utilities add, so spell it out for hex or rgb colours.

Interpolation modifiers

v4.0

Add /<mode> to bg-linear-*, bg-radial or bg-conic to pick the colour space the browser blends in. v4 defaults to oklab. Polar modes (oklch, hsl) travel around the hue wheel, and the hue modifiers choose which way.

  • /srgb
  • /hsl
  • /oklab
  • /oklch
  • /longer
  • /shorter
  • /increasing
  • /decreasing
  • /[in_hsl_longer_hue]

Docs: interpolation mode

The default row is identical to /oklab. For any two colours there are only two hue paths, so /shorter matches one of /increasing or /decreasing, and /longer matches the other. Greys, white and black have no hue, so hue modifiers do little with them. Gradient colour spaces need Chrome 111+, Safari 16.2+ or Firefox 127+; older browsers fall back to their default blend.

Radial gradients

v4.0

bg-radial draws a gradient outward from a centre point. Put a shape, size or position in brackets (bg-radial-[at_25%_25%]) and the same from-*, via-*, to-* stops and /mode modifiers apply.

  • bg-radial
  • bg-radial-[at_25%_25%]
  • bg-radial-[circle_at_center]
  • bg-radial-[circle_at_center,…]
  • bg-radial/srgb

Docs: radial gradient

The default shape is an ellipse sized to the farthest corner, so it stretches on wide boxes. Add circle when you want round. There are no bare-number forms (bg-radial-45 generates nothing).

Conic gradients

v4.0

bg-conic sweeps colours around a centre point, like a colour wheel or pie chart. bg-conic-180 sets the start angle, a leading minus reverses it, and brackets take a start angle plus position.

  • bg-conic
  • bg-conic-180
  • -bg-conic-90
  • bg-conic/decreasing
  • bg-conic-[from_45deg_at_30%_70%]
  • bg-conic-(--my-conic)

Docs: conic gradient

Write bg-conic-[from_0deg,red,blue], not bg-conic-[conic-gradient(…)]: the engine wraps the value in conic-gradient() itself. A stop at to-50% ends the sweep at the half-way angle, which makes the hard half-disc.

Stops with opacity

v4.0

The usual /50 opacity modifier works on from-*, via-* and to-*. A translucent stop shows whatever is behind it, so put a solid colour or image underneath. It is how scrims, tints and edge lights are built.

  • from-sky-500/50
  • via-white/60
  • from-black/70
  • to-[#0ea5e9]/40
  • to-transparent

Docs: color stops

Variants change only that stop

v4.0

In v4, dark:from-blue-500 or hover:to-teal-400 overrides just that one stop and keeps the others. In v3 it reset the whole gradient and left the end transparent. To collapse a three-stop gradient to two in some state, add via-none.

  • dark:from-blue-500
  • hover:to-teal-400
  • md:via-purple-500
  • dark:via-none
  • data-[state=error]:from-rose-500

Docs: upgrade guide, variants with gradients

Top row: only from changes, so the yellow end stays (blue to yellow). Bottom row: via-none drops the orange middle and dark:to-teal-400 swaps the end (blue to teal). The right column pins the page's dark variant on with a data-theme="dark" wrapper so you can compare without touching the theme menu.

Gradient text

core

Paint a gradient on the element, clip it to the letters with bg-clip-text, and hide the real text colour with text-transparent. For inline text that wraps, box-decoration-clone gives every line its own copy of the gradient.

  • bg-clip-text
  • text-transparent
  • bg-linear-to-r
  • box-decoration-clone
  • bg-size-[200%_100%]

Docs: background-clip · box-decoration-break

Without text-transparent the solid text colour paints over the gradient. Tight line heights can clip descenders (g, y), so add a little bottom padding. Check contrast against the lightest stop.

Gradient borders

core

CSS cannot put a gradient on border directly, so you fake it. Either pad a gradient wrapper around an opaque inner box, or paint two backgrounds, one clipped to the padding box and one to the border box, behind a transparent border.

  • p-px
  • rounded-[calc(var(--radius-2xl)-1px)]
  • border-transparent
  • bg-origin-border
  • [background-clip:padding-box,border-box]

Docs: background-origin

The wrapper is the most robust: it works with from-*, hover:from-* and dark:. Make the inner radius the outer radius minus the padding, and keep the inner fill opaque. The two single-element forms need a border width above zero (border-transparent, not border-0). bg-clip-* utilities set one value for every layer, so per-layer clipping needs the arbitrary property. For a spinning border see the conic spinner card.

Animating gradients

v4.0

v4 registers the stop colours and positions as typed properties, and transition-colors includes the colour stops. So hover:from-* fades smoothly. Positions need an explicit transition list. The angle and shape cannot tween through utilities.

  • transition-colors
  • transition-[--tw-gradient-from-position,--tw-gradient-to-position]
  • transition-[background-position]
  • transition-[background-size]
  • hover:bg-right

Docs: transition-property

Switching bg-linear-to-r for bg-linear-to-l, or changing an angle, snaps instead of animating, because the angle lives in an untyped variable. Animate the colours, the positions, background-position or background-size. To animate an angle, register your own typed @property (see the conic spinner card).

Mesh backgrounds

v4.0

A mesh or aurora look is three to five offset radial gradients stacked on a flat base. Use one layer per blob (each bg-radial-[at_x%_y%]), or write the whole stack as one arbitrary background-image.

  • bg-radial-[at_15%_20%]
  • from-indigo-500/80 to-transparent
  • isolate
  • -z-10
  • blur-3xl
  • bg-[radial-gradient(…),radial-gradient(…)]

Docs: radial gradient

Keep it to three to five layers. Large blurred layers are heavy on the GPU, so avoid animating them on phones, and check text contrast against the brightest blob.

Animated gradient pan

v4.1

Make the gradient twice as wide as its box with bg-size-[200%_100%], then move background-position back and forth with a keyframe animation. Use a symmetric colour list (A, B, A) so the loop is seamless. Arbitrary bg-size-[…] arrived in 4.1; in 4.0 write bg-[size:200%_100%].

  • bg-size-[200%_100%]
  • animate-gradient-pan
  • motion-reduce:animate-none

Docs: animation, customizing your theme

Striped and animated progress bars

v4.1

Two ways to stripe. A tiled hard-stop gradient with bg-size-[1rem_1rem] can slide sideways with a keyframe (the barber-pole bar). A repeating-linear-gradient needs no tile size but cannot be slid.

  • bg-[linear-gradient(45deg,…)]
  • bg-size-[1rem_1rem]
  • animate-stripes
  • bg-[repeating-linear-gradient(…)]
  • motion-reduce:animate-none

Docs: background-size

The keyframe distance (1rem) must equal the tile width, or the loop jumps. The colour comes from bg-indigo-500 beneath the translucent white image layer. Do not add a bg-linear-* class to the same element, because it would replace the stripe image.

Conic gradient spinners

v4.0

A conic gradient from transparent to a colour, cut into a ring with a mask, makes a spinner. animate-spin rotates the element. To rotate only the gradient, register a typed @property --angle and animate that.

  • bg-conic from-transparent to-indigo-500
  • animate-spin
  • bg-conic-[from_var(--angle)_in_oklab]
  • animate-angle
  • [mask:radial-gradient(…)]

Docs: conic gradient

The browser can only tween --angle because @property says it is an <angle> (Chrome 85+, Safari 16.4+, Firefox 128+). Do not try to animate --tw-gradient-position: it is untyped and would just snap. Rotating the whole element with animate-spin works everywhere, but it also turns shadows and children.

Arbitrary background images and tokens

v4.0

When you need a gradient the stop utilities cannot express, write it straight into bg-[…], or hold it in a variable with bg-(image:--g). A --background-image-* theme variable becomes a named utility. These set background-image directly, with no from-*/to-* wiring.

  • bg-[linear-gradient(…)]
  • bg-[repeating-linear-gradient(…)]
  • bg-(image:--g)
  • bg-none
  • --background-image-brand
  • bg-blend-multiply

Docs: custom value · blend mode

This works in 4.3.3, but the --background-image-* namespace is not listed in the theme docs' namespace table, so treat it as an engine feature rather than a documented one.

Swap the first layer for url(…) to tint a real photo. This demo uses a gradient so the page needs no image file. bg-none removes any background image, for example md:bg-none.

Arbitrary bg-size and bg-position

v4.1

4.1 added bg-size-[…], bg-size-(--var), bg-position-[…] and bg-position-(--var). They control tile size and placement for patterns, pans and underlines. Before 4.1 you wrote bg-[size:…], which still works.

  • bg-size-[200%_100%]
  • bg-size-(--s)
  • bg-position-[80%_20%]
  • bg-top-left
  • bg-left
  • bg-right

Docs: background-size · position

One value sets the width and leaves the height at auto, which for a gradient means "fill the box". That is why this draws vertical lines. For a square tile (a dot grid) give two values: bg-size-[16px_16px], or bg-size-[var(--s)_var(--s)].

4.1 also deprecated the reversed names (bg-left-top) in favour of bg-top-left, bg-top-right, bg-bottom-left and bg-bottom-right. There are no bare numbers: bg-size-200 is not a utility.

Gradients as masks

v4.1

The mask-* utilities use gradient stops to fade an element's own pixels: images, gradients, even text. That is different from an overlay gradient, which paints on top. Reach for a mask when you want to fade out, not tint.

  • mask-b-from-50%
  • mask-l-from-90%
  • mask-r-from-90%
  • mask-radial-from-70%
  • mask-linear-45
  • mask-none

Docs: mask-image

Masks fade alpha, so they cannot be recoloured by from-*/to-* (those belong to the background). The mask utilities keep their own --tw-mask-* variables. Masking works in all current browsers (Chrome 120+, Safari 15.4+, Firefox 53+). For a ring cut-out, the arbitrary [mask:radial-gradient(…)] used in the donut is simpler.

Custom gradient tokens and utilities

v4.0

Register brand colours in @theme and they feed from-*/to-*. Build parametric gradients with a functional @utility and --value(). Since 4.3, --default() gives that utility a value when none is written.

  • @theme { --color-brand-500 }
  • from-brand-300
  • @utility stripes-*
  • --value(--color-*, [color])
  • --default(45)

Docs: functional utilities

A custom @utility that sets background-image competes with bg-linear-* on the same element, and only one wins. @theme, @utility, @property and @custom-variant run in the browser build; @plugin and @config do not.

bg-gradient-to-* is now bg-linear-to-*

v4.0

v4 renamed the direction utilities to bg-linear-to-* to sit beside bg-radial and bg-conic. The upgrade tool rewrites your templates. In 4.3.3 the old names still compile through a compatibility shim, but teach and write the new ones.

  • bg-gradient-to-r → bg-linear-to-r
  • bg-gradient-to-br → bg-linear-to-br
  • npx @tailwindcss/upgrade

Blog: expanded gradient APIs · Upgrade guide

The generated CSS differs: the legacy shim adds in oklab without the @supports guard and has no modifier support, so bg-gradient-to-r/srgb does nothing. The upgrade guide does not list the rename in its table; the v4 blog post and the changelog are the sources. Do not say the old names were removed.
