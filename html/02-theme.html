Theme variables

In Tailwind v4 every design token is a CSS variable declared in @theme. Name one inside a namespace and the matching utility or variant exists. This page covers the namespaces, extending, overriding and resetting them, the dynamic spacing scale, the OKLCH palette, and reading tokens from CSS and JavaScript.

@theme vs plain :root variables

v4.0

A variable declared inside @theme does two jobs: it creates utilities (or variants), and it is emitted as a normal CSS variable on :root. A variable declared with plain :root is only a variable, so Tailwind generates nothing for it.

Use @theme for design tokens that should become classes, and :root for values that should not.

  • @theme { … }
  • --color-mint-500
  • bg-mint-500
  • var(--color-mint-500)
  • bg-(--color-peach-500)

Docs: theme variables

The textarea is the only place these three tokens are defined: this page's own stylesheet does not contain them. Change a value and the card updates; delete a line and that utility stops working. Resets such as --color-*: initial would wipe every colour on this page, so reload if you try one. Write @theme at the top level of a stylesheet: the docs say not to nest it under selectors or media queries.

Theme variable namespaces

v4.0

Each namespace is a prefix that maps to one family of utilities or variants. Add --shadow-card and shadow-card exists; add --breakpoint-3xl and the 3xl: variant exists.

  • --color-*

  • --spacing
  • --breakpoint-*
  • --container-*
  • --shadow-*
  • --ease-*
  • --animate-*

Extend, override and reset the default theme

v4.0

A new name extends a namespace. Redefining an existing name overrides one value. Setting --color-lime-*: initial removes one palette, --color-*: initial a whole namespace, and --*: initial the entire default theme.

  • --color-midnight: #121063
  • --radius-4xl: 3rem
  • --color-lime-*: initial
  • --color-*: initial
  • --*: initial

Docs: customizing your theme

This is the same mechanism as --color-lime-*: initial or --color-*: initial, applied to a palette this page defines so the rest of the page keeps its colours. The button probes each class in the live page and reports whether any CSS was generated.

Code-only: every demo on this page shares one in-browser compile, so a real --color-*: initial or --*: initial would strip the colours and sizes from all of them. The output shown was compiled with tailwindcss@4.3.3. After --*: initial, redefine --spacing or p-4 and friends stop working.

One --spacing variable drives the scale

v4.0

Spacing and sizing utilities are no longer a fixed list. Any number works (p-13, w-17, mt-29, gap-2.5) and compiles to calc(var(--spacing) * n).

Change --spacing on any element and everything inside it rescales, which makes a density control a one-liner.

  • --spacing
  • p-13
  • w-17
  • mt-29
  • size-13
  • gap-2.5
  • --spacing-gutter

Using theme variables in CSS, inline styles and JavaScript

v4.0

Every used theme variable is a real CSS variable on :root. Reference it in custom CSS, inline styles, arbitrary values (rounded-[calc(var(--radius-xl)-1px)]), or from JavaScript with getComputedStyle. The v3 resolveConfig() helper is gone.

  • var(--color-sky-500)
  • bg-(--color-mint-500)
  • rounded-[calc(var(--radius-xl)-1px)]
  • --alpha()
  • --spacing()
  • getComputedStyle

Docs: using your theme variables

Tailwind only emits a variable that something uses, so unused ones read back as empty. Use @theme static (below) for variables you only read at runtime. Shadow variables are inlined into box-shadow, so --shadow-xl is not emitted even when shadow-xl is in use.

The OKLCH default palette

v4.0

Since v4.0 the whole default palette is defined with oklch() instead of rgb, so it can reach more vivid colours on P3 displays than sRGB allowed. There are 26 palettes with 11 steps each (50 to 950). mauve, olive, mist and taupe arrived in v4.2.

  • --color-sky-500
  • bg-sky-50 … bg-sky-950
  • bg-mauve-500
  • bg-olive-500
  • bg-mist-500
  • bg-taupe-500

Docs: default colour palette

The palette is written in oklch(), and v4 relies on modern CSS such as @property and color-mix(), so it targets Safari 16.4+, Chrome 111+ and Firefox 128+ (see the upgrade guide). In a real build with generated class names (for example bg-${color}-500), safelist them with @source inline("bg-{red,orange,amber}-{50,{100..900..100},950}") (v4.1).

Opacity modifiers with color-mix()

v4.0

Any colour utility takes a slash modifier. v4 compiles it to color-mix(in oklab, …) instead of baking in an rgb value, so it works with theme variables, CSS variables and named opacity values.

  • bg-sky-500/50
  • bg-sky-500/[37%]
  • bg-sky-500/(--alpha)
  • bg-sky-500/glass
  • --opacity-glass

Docs: adjusting opacity

Code-only because it is compiler output, not something to run. The page demos above are the live effect.

Custom and removed breakpoints

v4.0

A --breakpoint-* variable defines a min-width variant and its max-* twin. Add a name, override a default, remove one with initial, or reset the namespace and start over.

Keep every breakpoint in one unit (rem), or the variants can sort in the wrong order.

  • --breakpoint-xs
  • --breakpoint-3xl
  • xs:
  • 3xl:
  • max-3xl:
  • --breakpoint-2xl: initial

Docs: custom breakpoints

Breakpoint variants react to the window, not to the demo box, so resize the window to see them change.

This is the same mechanism as --breakpoint-2xl: initial, applied to two throwaway breakpoints this page defines so the real ones keep working. 5rem is narrower than any real window, so a variant that exists always matches. The button creates each class and reports whether any CSS was generated.

Code-only: --breakpoint-*: initial would delete sm: to 2xl: for every demo on this page, which share one compile. The output was compiled with tailwindcss@4.3.3.

max-*, breakpoint ranges and min-[…]

core

Every breakpoint also gives a max-* variant. Stack a min and a max variant to target a range (md:max-xl:flex) or exactly one breakpoint (md:max-lg:flex). For one-offs, use min-[320px]: and max-[600px]:.

  • max-md:
  • md:max-xl:
  • md:max-lg:
  • min-md:
  • min-[320px]:
  • max-[600px]:

Docs: targeting a breakpoint range

Every demo in this feature reacts to the browser window, not to the demo box: resize the window to see them change. For the same idea measured on a parent element, see the Container queries page.

Code-only: it is compiler output. Because Tailwind is mobile-first, md:max-xl:flex needs no reset above xl; the max variant already limits it.

@theme inline: tokens that point at other variables

v4.0

When a theme variable references another variable, plain @theme resolves var(--other) where the theme variable is declared (on :root), so a later override on a child element never reaches the utility.

@theme inline puts the value straight into the utility instead, so the lookup happens on the element that uses it. Use it for tokens that follow runtime variables such as light and dark schemes.

  • @theme inline { … }
  • --color-canvas: var(--acme-canvas)
  • bg-canvas-inline
  • theme(inline)

Docs: referencing other variables

@theme static: always emit the variables

v4.0

By default Tailwind only writes the theme variables that generated CSS uses. @theme static forces its variables, and any variable they reference, into the output so inline styles, JavaScript and third-party CSS can read them. It first shipped in v4.0.5.

  • @theme static { … }
  • --color-chart-1
  • theme(static)

Docs: generating all CSS variables

The in-browser build used on this page only reads class names, which makes the tree-shaking visible: the second card has no styles. In a real build the source scanner also picks up var(--…) references in your files, so inline styles often work without static. Use it for variables that only JavaScript or other CSS reads.

Code-only: the browser build cannot change import options. For scale, compiling @import "tailwindcss" theme(static) with tailwindcss@4.3.3 and a single flex class emits 409 variables; the same build without static emits 4.

Custom font families with --font-*

v4.0

Define --font-<name> and font-<name> exists. Add --font-<name>--font-feature-settings or --font-<name>--font-variation-settings to give a family default OpenType features or variable-font axes.

  • --font-poster
  • font-poster
  • --font-*--font-feature-settings
  • --font-*--font-variation-settings

Docs: font-family

In your own project --font-display: "Oswald", sans-serif gives you font-display. These demos use font-poster and friends instead, because the guide's own stylesheet already defines --font-display on :root. Fonts load from the <link> in this page's head (Bricolage Grotesque and IBM Plex Sans from Google Fonts), so the visible difference needs a network connection. Do not use @import for fonts inside a text/tailwindcss style: it switches off the browser build's implicit Tailwind import.

Type scale tokens with line-height, tracking and weight

v4.0

--text-<name> creates text-<name>. Optional sub-values bundle the rest of the style: --text-<name>--line-height, --letter-spacing and --font-weight. The leading-*, tracking-* and font-* utilities still override them.

  • --text-tiny
  • --text-tiny--line-height
  • --text-tiny--letter-spacing
  • --text-tiny--font-weight
  • --tracking-ultra
  • --leading-comfy
  • --font-weight-heavy

Docs: font-size

Radius and shadow scales

v4.0

Name a token and the utility exists: --radius-squircle gives rounded-squircle, --shadow-card gives shadow-card, and --inset-shadow-pressed, --drop-shadow-glow and --text-shadow-neon work the same way. text-shadow-* is new in v4.1.

  • --radius-squircle
  • --shadow-card
  • --inset-shadow-pressed
  • --drop-shadow-glow
  • --text-shadow-neon

Docs: box-shadow · border-radius · text-shadow

The stage stays light in dark mode because shadows need a light surface to show. In v4, shadow-sm is the old shadow and shadow-xs is the old shadow-sm. --shadow-* values are inlined into the utility, so setting --shadow-lg on a wrapper does not change it. Radius and drop-shadow tokens are read with var(), so they can be overridden per element.

rounded-4xl is left out of the ramp: the Extend, override and reset feature above overrides --radius-4xl to 3rem for this whole page, so it no longer shows the default.

Custom easing and animations

v4.0

--ease-<name> creates ease-<name>, and --animate-<name> creates animate-<name>. Put the @keyframes inside the same @theme and they are only emitted when the animation is used.

  • --ease-snappy
  • ease-spring
  • --animate-wiggle
  • @keyframes
  • motion-reduce:animate-none

Docs: animation · transition-timing-function

linear() easing needs Chrome 113+, Safari 17.2+ or Firefox 112+; older browsers ignore the declaration and fall back to the default timing.

Keyframes declared inside @theme are tree-shaken with the animation. To always include a @keyframes rule, write it outside @theme.

Re-theme a subtree at runtime

v4.0

Utilities read var(--color-brand-500), not a baked-in value. Redefine that variable on any element, in CSS, an inline style or JavaScript, and everything inside follows. No recompile and no dark: variants.

  • [data-brand="forest"] { … }
  • style="--color-brand-500: …"
  • el.style.setProperty()

Docs: using your theme variables

Only variables that utilities read with var() can be overridden this way. --shadow-*, --inset-shadow-* and --text-shadow-* are inlined into their utilities, so a wrapper cannot change them.

Share a theme across projects

v4.0

A theme is just CSS. Put the @theme block in its own file or npm package, then @import it after tailwindcss in each app. It behaves exactly like a local @theme.

  • @import "../brand/theme.css"
  • @import "@acme/brand/theme.css"
  • @theme { … }

Docs: sharing across projects

Code-only for the import lines: the browser build cannot @import a local file or npm package (it throws "The browser build does not support @import"). The live cards use the same tokens, declared in this page's single style block. Do not put --*: initial in a shared theme you try out here, because it would wipe the page.

@theme default, reference and import options

v4.0

@theme takes options: inline and static (documented), plus default and reference, which Tailwind's own theme.css uses but theme.mdx does not describe. Import-level forms such as theme(static) and prefix(tw) go on the @import line.

  • @theme default { … }
  • @theme reference { … }
  • theme(static)
  • prefix(tw)

Docs: the static option · Docs: @reference

reference is the mechanism behind @reference, which lets a component stylesheet use your theme without duplicating its CSS. @reference itself needs file imports, so it is code-only here.

Code-only: a prefix changes every class name, so it would break every demo on this page. Unprefixed classes such as flex generate nothing once a prefix is set. The output was compiled with tailwindcss@4.3.3.

--container-*: container variants and sizes

v4.0

--container-* does double duty. It names the container-query variants (@sm:, @max-md:, @tablet:) used inside an @container, and it gives the sizes for max-w-md, w-md, min-w-md, basis-md and columns-md.

  • --container-tablet
  • @tablet:
  • max-w-tablet
  • @container
  • @container-size

Docs: custom container sizes

The card switches to a row at @sm (24rem) and shows the badge at @tablet (30rem), measured on the box, not the window. Container queries need Chrome 105+, Safari 16+ or Firefox 110+. See the Container queries page for the full variant list.

@container-size (container-type: size) shipped in v4.3.0. It lets a child use cqb (block-axis container units) as well as cqw, but the container then cannot size itself from its content.

Blur, perspective and aspect-ratio scales

v4.0

Smaller namespaces follow the same rule. --blur-<name> feeds blur-* and backdrop-blur-*, --perspective-<name> feeds perspective-*, and --aspect-<name> feeds aspect-<name> (the v3 key was aspectRatio).

  • --blur-2xs
  • backdrop-blur-2xs
  • --perspective-remote
  • --aspect-retro
  • aspect-cinema

Docs: perspective · blur · aspect-ratio

--default-* variables

v4.0

A few single-value variables set what bare utilities use. --default-transition-duration and --default-transition-timing-function feed transition; --default-font-family and --default-mono-font-family feed Preflight; --default-border-width changes the bare border.

  • --default-transition-duration
  • --default-transition-timing-function
  • --default-font-family
  • --default-border-width

Docs: default theme variables

Preflight sets the font of code, kbd, samp and pre on those elements, so the variable can be overridden on any wrapper. --default-font-family is different: Preflight sets it once on html, so change it there or in @theme, not per subtree.

Code-only for the variable: border width is inlined into .border, so it cannot be changed per element or after the compile, and setting it here would change every bordered demo. The left and right tiles show the 1px and 2px results; the compiled output was produced with tailwindcss@4.3.3. --default-ring-width and --default-outline-width work the same way. The upgrade guide shows --default-ring-width: 3px to restore v3's ring, but calls these variables compatibility-only and not idiomatic v4; --default-border-width is not mentioned in the docs at all.
