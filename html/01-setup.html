Setup & engine

Every way to install Tailwind v4.3, how it finds your classes and how to debug that, the one-off value syntax you will use every day, and how cascade layers, prefix and important fit into existing CSS. It ends with the engine and the editor tooling.

Choosing an installation path

v4.0

Tailwind v4 ships one package per build setup, and every one of them reads the same one-line stylesheet. Pick the plugin that matches your bundler, or the CLI if you have no bundler.

  • @tailwindcss/vite
  • @tailwindcss/postcss
  • @tailwindcss/cli
  • @tailwindcss/webpack
  • @tailwindcss/browser

Docs: installation guides

Vite plugin

v4.0

The first-party Vite plugin is the most direct setup for Vite-based frameworks. Install two packages, register the plugin, and import Tailwind in your CSS. It needs no tailwind.config.js and no PostCSS config.

  • @tailwindcss/vite
  • tailwindcss()
  • optimize

Docs: Installing with Vite

PostCSS plugin

v4.0

For frameworks that own the build, such as Next.js and Angular. In v4 the PostCSS plugin lives in its own package, and postcss-import and autoprefixer are no longer needed.

  • @tailwindcss/postcss
  • postcss.config.mjs
  • .postcssrc.json

Docs: Installing with PostCSS

Tailwind CLI

v4.0

The simplest path when you have no bundler: point the CLI at an input stylesheet and it scans your files and writes the CSS. It is also published as a standalone executable that needs no Node. The v3 command npx tailwindcss became npx @tailwindcss/cli.

  • -i -o
  • --watch
  • --minify
  • --silent
  • --poll

Docs: Tailwind CLI

Browser build (Play CDN)

v4.0

One <script> compiles Tailwind inside the page, with no build step. Add <style type="text/tailwindcss"> for @theme, @utility and the rest. The docs say it is for development only and not intended for production. This whole page runs on it.

  • @tailwindcss/browser
  • type="text/tailwindcss"

A dedicated loader for webpack and Rspack that skips the detour through PostCSS. The v4.3 post measured it 2.17x faster than the PostCSS plugin on the tailwindcss.com docs. @tailwindcss/turbopack is not released yet.

One line: @import "tailwindcss"

v4.0

v4 replaces the three @tailwind directives with one plain CSS import. That line brings in the layer order, the default theme, Preflight and every utility.

  • @import "tailwindcss"
  • @tailwind base (removed)
  • prefix() important source() theme()

Built-in imports, nesting and vendor prefixes

v4.0

Tailwind inlines @import files itself. In optimized builds, Lightning CSS also flattens nesting and adds vendor prefixes, so you do not need postcss-import, autoprefixer or Sass.

  • @import "./typography.css"
  • nested rules
  • -webkit- prefixes

Docs: build-time imports

Automatic content detection

v4.0

There is no content array. Tailwind reads your project files as plain text and generates CSS for every token that matches a utility. It skips .gitignore paths, node_modules (ignored by default since v4.1), binary files, CSS files and lockfiles.

  • plain-text scan
  • .gitignore
  • node_modules
  • full class names only

Docs: detecting classes in source files

@source, source() and source(none)

v4.0

Register extra paths to scan, move the base path, or switch automatic detection off and list your sources yourself. Paths are quoted and relative to the stylesheet.

  • @source "../path"
  • source("../src")
  • source(none)

Docs: explicitly registering sources

@source inline() safelist

v4.1

Force classes into the CSS even when they appear nowhere in your files. The string is brace-expanded, so one line can produce a whole ramp of shades and variants. This is the CSS-first replacement for the v3 safelist option.

  • @source inline("underline")
  • {hover:,focus:,}
  • {100..900..100}
  • {a,b,c}

Docs: safelisting specific utilities

@source not ignore paths

v4.1

Exclude folders or globs from scanning, such as legacy components, generated code or vendored libraries. It keeps stray class names out of the CSS and the scan faster.

  • @source not "../legacy"

Docs: ignoring specific paths

@source not inline() block classes

v4.1

The opposite of a safelist: keep named classes out of the CSS even if they show up in your files. Use it as a guardrail, or to stop Tailwind from generating a name that another stylesheet owns.

  • @source not inline("overline")
  • @source not inline("container")

Docs: explicitly excluding classes

Debug content detection with DEBUG=*

v4.1

When a class is missing from your CSS, run the build with the DEBUG environment variable set to *. Since v4.1.6 Tailwind then prints a timing report and writes a log with every @source entry, the sources it settled on and each file it read. If your file is not in that log, Tailwind never looked at it.

  • DEBUG=*
  • DEBUG=tailwindcss
  • DEBUG=tailwindcss:oxide
  • DEBUG=-tailwindcss
  • tailwindcss-<pid>.log

Arbitrary values in square brackets

core

Break out of the theme with a one-off value: top-[117px], bg-[#316ff6], text-[22px]. Brackets work with every variant, and underscores stand in for spaces. In v4, commas no longer turn into spaces inside grid-cols-* and object-*, so use underscores.

  • top-[117px]
  • bg-[#bada55]
  • grid-cols-[1fr_500px_2fr]
  • rounded-[calc(…)]
  • before:content-['Hi']

Docs: using arbitrary values

CSS variable shorthand bg-(--brand)

v4.0

Parentheses add var() for you and work on nearly every utility, including opacity modifiers. They replace the v3 form bg-[--brand], which now compiles to invalid CSS.

  • bg-(--brand)
  • w-(--sidebar)
  • ring-(--brand)/30
  • border-(--accent)

Docs: arbitrary values and variables

Type hints: text-(length:--size)

v4.0

Some namespaces are ambiguous. text-* can mean font size or colour, so a bare variable defaults to colour. Put a CSS data type before the variable to pick one.

  • text-(length:--size)
  • text-(color:--tone)
  • bg-(image:--hero)
  • font-(family-name:--f)

Docs: resolving ambiguities

Bare values: grid-cols-15, w-17, data-current:

v4.0

Utilities and variants accept any matching value without brackets or config. Spacing is a multiple of one --spacing variable, grid columns take any integer, and boolean data attributes need no setup.

  • grid-cols-15
  • w-17
  • opacity-37
  • aspect-8.5/11
  • data-current:

Blog: dynamic utility values and variants

Arbitrary properties: [mask-type:luminance]

core

Write any CSS property as a class when no utility exists. It works with every variant, which makes it a good way to set CSS variables per breakpoint or state.

  • [mask-type:luminance]
  • [--gutter-width:1rem]
  • lg:[--gutter-width:2rem]
  • [clip-path:polygon(…)]

Docs: arbitrary properties

Arbitrary variants: [&>*]:p-2

core

Write a selector or at-rule in brackets and Tailwind turns it into a variant, with & standing for the element. Use it when no built-in variant fits. A few common selectors already have one (*:, has-*, nth-*). In v4, stacked variants apply left to right, so first:*:pt-0 became *:first:pt-0.

  • [&>*]:p-2
  • [&_p]:text-sm
  • [&.is-dragging]:
  • [&:has(:checked)]:
  • [@supports(display:grid)]:

Docs: using arbitrary variants

Native cascade layers

v4.0

v4 emits real @layer rules in the order theme, base, components, utilities. CSS outside any layer beats all of them, which is why your own unlayered rules can override a utility whatever its specificity.

  • @layer theme, base, components, utilities
  • unlayered CSS wins
  • utility! beats unlayered

Blog: designed for the modern web

Base styles and component classes with @layer

v4.0

Use @layer base for element defaults and @layer components for reusable classes that utilities can still override. In v4 @layer is plain CSS. A custom class that needs variants such as hover: must use @utility instead.

  • @layer base
  • @layer components
  • @utility

Docs: adding base styles

Preflight and the v4 base-style changes

v4.0

Preflight, the reset in the base layer, clears margins, borders, headings and lists. v4 changed a few defaults: the hidden attribute beats display utilities, borders and rings default to currentcolor, and placeholders use the text colour at 50%.

  • hidden wins
  • border = currentcolor
  • ring = 1px
  • cursor: default buttons

Docs: Preflight

Import the pieces separately (drop Preflight)

v4.0

@import "tailwindcss" is just three imports. Import only theme.css and utilities.css to skip Preflight, for example when you add Tailwind to a site that already has a reset.

  • tailwindcss/theme.css
  • tailwindcss/preflight.css
  • tailwindcss/utilities.css
  • layer(…)

Docs: disabling Preflight

Important modifier: trailing !

v4.0

Add ! at the very end of a class, after any variants, and its declarations become !important. Use it to beat legacy or third-party CSS you cannot change. The v3 form with a leading ! still works but is deprecated.

  • bg-red-500!
  • flex!
  • hover:bg-red-600/50!

Docs: the important modifier

Prefix: prefix(tw)

v4.0

Namespace every Tailwind class and theme variable so they cannot collide with legacy CSS. v4 prefixes look like variants and always come first: tw:flex, tw:hover:bg-red-500. The prefix may only use lowercase letters a to z.

  • @import "tailwindcss" prefix(tw)
  • tw:flex
  • tw:bg-red-500!
  • --tw-color-red-500

Docs: using the prefix option

Important flag: @import "tailwindcss" important

v4.0

Marks every generated utility !important. It is meant for adding Tailwind to a project with existing high-specificity CSS. Prefer the per-class ! when only a few classes need it.

  • @import "tailwindcss" important
  • prefix(tw) important

Docs: the important flag

Modern CSS under the hood

v4.0

v4 is built on native cascade layers, @property-registered variables, color-mix() for opacity modifiers and logical properties like margin-inline. v4.1 added fallbacks so older Safari and Firefox still render most of it.

  • @layer
  • @property
  • color-mix()
  • margin-inline

Blog: designed for the modern web

Browser requirements

v4.0

v4 relies on @property, color-mix() and cascade layers for core features, so it targets Safari 16.4, Chrome 111 and Firefox 128 or newer. Since v4.1, older browsers get best-effort fallbacks (next card), but if they must look exactly right, stay on v3.4. A few utilities need even newer browsers and are opt-in.

  • Chrome 111
  • Safari 16.4
  • Firefox 128
  • field-sizing, starting:, text-balance

Docs: browser support

Fallbacks for older browsers

v4.1

In v4.0, colours, shadows and gradients could vanish in browsers stuck on Safari 15. Since v4.1 Tailwind writes its own fallbacks, so those browsers still render a usable page. Modern browsers skip every one of them, and v4 is still designed for Safari 16.4, Chrome 111 and Firefox 128 or newer.

  • @layer properties
  • @supports (color: color-mix(in lab, red, red))
  • @supports (background-image: linear-gradient(in lab, red, red))

The new engine, in numbers

v4.0

v4 is a ground-up rewrite: a TypeScript core, a Rust scanner and Lightning CSS. On the Catalyst template, full builds went from 378ms to 100ms, and rebuilds that need no new CSS from 35ms to 192 microseconds.

  • 3.78x full build
  • 8.8x incremental
  • 182x no new CSS
  • 2.17x webpack loader

Editor setup: Tailwind CSS IntelliSense

core

The official VS Code extension gives autocomplete, linting, hover previews and syntax highlighting. Its Tailwind CSS language mode understands v4's at-rules such as @theme, @variant and @source, so they are not flagged as unknown.

  • bradlc.vscode-tailwindcss
  • Tailwind CSS language mode

Class sorting with prettier-plugin-tailwindcss

core

The official Prettier plugin sorts classes into Tailwind's recommended order, so class lists stay consistent across a team. It runs wherever Prettier runs: editors, the command line and CI. For v4, point it at your CSS entry file.

  • prettier-plugin-tailwindcss
  • tailwindStylesheet
