Page 14 · New in v4.3

Scrollbars, zoom & tabs

Tailwind v4.3 added utilities for scrollbar-width, scrollbar-color, scrollbar-gutter, zoom and tab-size, plus size containers, stacked and compound @variant and --default(); the 4.3.x patches added CLI flags and bare grid track sizes. Scroll, resize and hover the demos: every utility on this page runs live.

Scrollbar width: scrollbar-thin, scrollbar-none

v4.3

Three utilities for the CSS scrollbar-width keywords. scrollbar-thin asks for a slimmer bar, scrollbar-none hides it while the box still scrolls, and scrollbar-auto is the default. They do not set overflow, so add overflow-auto yourself.

  • scrollbar-auto
  • scrollbar-thin
  • scrollbar-none
  • md:scrollbar-auto
  • hover:scrollbar-thin
  • pointer-fine:scrollbar-thin
  • pointer-coarse:scrollbar-none

Only the keywords auto, thin and none exist, no lengths. Support: Chrome and Edge 121+, Firefox 64+ and Safari 18.2+ (caniuse.com/css-scrollbar). macOS, iOS and Android draw overlay bars that take no layout space, so the readouts under the demos print the measured bar width (0px there).

Docs: scrollbar-width

Scrollbar colour: scrollbar-thumb-*, scrollbar-track-*

v4.3

Colour utilities for the draggable thumb and the track behind it. They accept the whole colour system: palette names, /opacity modifiers, [#hex], (--var), current and your own @theme colours. Set only one and the other is transparent.

  • scrollbar-thumb-sky-700
  • scrollbar-track-sky-100
  • scrollbar-thumb-slate-900/60
  • scrollbar-thumb-[#0f766e]
  • scrollbar-thumb-(--my-thumb)
  • scrollbar-thumb-current
  • hover:scrollbar-thumb-*
  • dark:scrollbar-track-*

Each utility sets a registered custom property plus the scrollbar-color shorthand. hover: fires while the pointer is anywhere over the box, not only over the thumb, and only on devices that can hover. Colours are applied by the browser: no rounded or padded thumbs. Support: Chrome and Edge 121+, Firefox 64+, and Safari 26.2+ (per Chrome's scrollbar-styling guide). Older Safari ignores the colours and shows its default bar.

Docs: scrollbar-color

Scrollbar gutter: scrollbar-gutter-stable

v4.3

Reserve the space a scrollbar would use before it appears, so content does not jump sideways when a list grows or a dialog locks scrolling. scrollbar-gutter-stable reserves it on the scrollbar side, scrollbar-gutter-both on both sides, scrollbar-gutter-auto only when a bar is shown.

  • scrollbar-gutter-auto
  • scrollbar-gutter-stable
  • scrollbar-gutter-both
  • md:scrollbar-gutter-stable

both is stable both-edges. It needs an overflow other than visible, and scrollbar-gutter-stable on <html> is the usual fix for a page that jumps when a modal sets overflow-hidden. Chrome 94+, Firefox 97+ and Safari 18.2+ support it. It only matters with classic scrollbars; overlay bars take no space.

Docs: scrollbar-gutter

Zoom: zoom-75, zoom-[1.1]

v4.3

Utilities for the CSS zoom property. Unlike scale-*, zoom changes the element's layout size: neighbours move, text wraps again, and padding and borders scale with it. A bare number is a percentage, so zoom-75 is zoom: 75%.

  • zoom-<number>
  • zoom-75
  • zoom-150
  • zoom-[1.1]
  • zoom-(--ui-zoom)
  • hover:zoom-110
  • md:zoom-125

Chrome and Safari have supported zoom for years and Firefox since version 126 (2024). It takes whole numbers only, so use zoom-[1.5] rather than zoom-1.5. Animating zoom is not interoperable: Firefox and Chrome 150+ interpolate it, Safari and older Chrome jump straight to the end value. For motion, use scale-* with a transition. Use zoom to resize a component's footprint, scale to transform it without moving anything else.

Docs: zoom

Tab size: tab-2, tab-4, tab-8

v4.3

Utilities for tab-size, the width of a tab character in preformatted text. Bare numbers are counts of space widths (tab-4 is tab-size: 4); tab-[12px] and tab-(--var) take lengths and variables. It is inherited, so one class on a wrapper covers every <pre> inside.

  • tab-<number>
  • tab-2
  • tab-8
  • tab-[12px]
  • tab-(--tab-size)
  • md:tab-4

It only affects preserved tab characters: <pre>, or whitespace-pre and whitespace-pre-wrap on other elements. Editors and formatters often swap tabs for spaces, so write them as &#9; in HTML (and &#10; for a newline). There is no bare tab class by default; see the --default() card for one you can define.

Docs: tab-size

@container-size: size containers

v4.3

@container makes an inline-size container, so children can react to its width but not its height. @container-size sets container-type: size, which makes the height-based units cqb and cqh work. Name one with @container-size/{name}.

  • @container-size
  • @container-size/hero
  • h-[50cqb]
  • text-[45cqb]

A size container cannot size itself from its content, so give it a height (h-40, an aspect ratio, or a stretching parent). In a plain @container, cqb silently falls back to the viewport. The full container-query tour is on page 04.

Docs: responsive design, size containers

Stacked and compound @variant

v4.3

In your own CSS, @variant now takes stacked variants (hover:focus, both must match) and compound variants (hover, focus, either matches, with one shared block of styles). Before 4.3 it took a single variant.

  • @variant hover:focus { … }
  • @variant hover, focus { … }
  • @variant dark:hover { … }

The output is plain nested CSS. The v4.3 post advises a real component styled with classes unless CSS is the right tool. Details on page 03.

Docs: adding custom styles, using variants

--default() for functional utilities

v4.3

Inside --value() and --modifier() of a functional @utility, --default() supplies the value used when the class is written without one. tab-stop can mean 4 while tab-stop-2 still means 2.

  • --value(integer, --default(4))
  • --modifier(number, --default(1.4))
  • tab-stop
  • tilt / tilt-12
  • type-18/2

A default is emitted exactly as written, so it can carry its own unit (--default(3deg) gives rotate: 3deg). The tilt demo uses a bare 3 and wraps it in calc(… * 1deg) because tilt-12 is a bare integer too. Bare number modifiers must be multiples of 0.25 (/1.5, /2), but a default is not checked: type-18 falls back to 1.4 while type-18/1.4 generates nothing. The demos define tab-stop-* rather than tab-* so the built-in tab-<n> above stays untouched. Not in 4.3.3: a default with spaces loses them (--default(1fr 2fr) becomes 1fr2fr); the fix is on the main branch. See page 03.

Docs: adding custom styles, default values

Bare auto-rows-12 and auto-cols-16

v4.3

Added in v4.3.2: auto-rows-* and auto-cols-* take bare numbers from the spacing scale. auto-rows-12 is grid-auto-rows: calc(var(--spacing) * 12), 3rem by default, so you no longer write auto-rows-[3rem].

  • auto-rows-12
  • auto-cols-16
  • auto-rows-6
  • auto-rows-[3rem] (old)
  • grid-flow-col
  • row-span-*

They size only the implicit rows or columns, the ones created beyond grid-template-*. A bare number must be a multiple of 0.25, so auto-rows-3.3 and auto-rows-px generate nothing; use auto-rows-[1px]. The keywords (min, max, fr) and arbitrary values still work.

Docs: grid-auto-rows · grid-auto-columns

CLI --silent

v4.3

Added in v4.3.1: @tailwindcss/cli accepts --silent, which suppresses non-error output, meaning the version banner and the "Done in" lines. Use it for CI logs and for dev scripts where Tailwind's chatter would interleave with other processes.

  • --silent
  • --watch --silent
  • tailwindcss build --silent

Code-only: the CLI runs in Node, not in the browser build, so there is nothing to run on this page. Real errors are still printed in silent mode, and CSS written to stdout is unaffected. It is not in the docs site; the sources are tailwindcss --help and the changelog.

Docs: Tailwind CLI · Changelog

CLI --watch --poll

v4.3

Added in v4.3.3: --poll[=ms] makes --watch check files on a timer instead of waiting for filesystem events. Use it where events are unreliable or missing. --poll alone checks every 250 ms; --poll=500 sets the interval.

  • --watch --poll
  • --watch --poll=500
  • --poll --silent

Code-only: this is a Node CLI flag. Polling only applies together with --watch, and --poll=0 is rejected with "Specified polling interval must be a positive number." The same release stopped loading @parcel/watcher unless it is needed, so polling works even where that module cannot load.

Docs: Tailwind CLI · Changelog
