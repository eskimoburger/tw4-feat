Page 08 · Motion

Motion: keyframes & scroll

Everything that moves with @keyframes: the four built-in animations, your own --animate-* tokens, animation controls, entrances and loops, @property tricks, SVG drawing, scroll-driven animations and view transitions. Nearly every example is live, and the moving ones fall back to a still version for reduced-motion users.

animate-spin

core

Turns an element one full rotation per second, linearly and forever. Put it on the icon of a loading button or any "working" indicator. In v4 it is only the --animate-spin theme variable, so you can restyle it or clone it with a new duration.

  • animate-spin
  • motion-reduce:animate-none
  • motion-safe:animate-spin
  • animate-spin-slow
  • --animate-spin

Put it on the SVG, not on the button, or the label spins too. Pair it with a text status so reduced-motion users still see that something is happening.

Docs: animation

animate-pulse

core

Fades an element between full and half opacity every two seconds. It is the standard skeleton loader: draw grey placeholder shapes and let the whole group breathe together.

  • animate-pulse
  • motion-reduce:animate-none
  • motion-safe:aria-busy:animate-pulse
  • group-aria-busy:*

Put animate-pulse on the container, not on each bar, so they pulse in unison. For a highlight that travels across the shape, see the shimmer card.

Docs: animation

animate-ping

core

Scales an element up to twice its size while fading it out, like a radar ping or a ripple on water. Use it for notification dots, "live" markers and map pins. It usually sits on top of a static twin that stays put.

  • animate-ping
  • motion-reduce:animate-none
  • animate-ping-slow
  • [animation-delay:500ms]

Layer an absolutely positioned animate-ping copy (usually opacity-75) over a relative static dot. Keep the ping aria-hidden and put the real status in text.

Docs: animation

animate-bounce

core

Moves an element up and down with a springy ease, once per second. It is the classic "scroll down" hint, and it also works for "new messages" pills or a button arrow that should invite a click.

  • animate-bounce
  • motion-reduce:animate-none
  • motion-safe:group-hover:animate-bounce
  • animate-bounce-slow

In v4, translate-*, scale-* and rotate-* are separate CSS properties, so they now stack with the transform-based bounce instead of being overridden. The hit area moves while it bounces: keep click targets on a wrapper that stays still.

Docs: animation

animate-none, motion-safe: and motion-reduce:

core

animate-none switches any animation off. motion-reduce: applies a utility only when the user asked their OS for less motion, and motion-safe: only when they did not. Use one of them on every animation that is more than a tiny fade.

  • animate-none
  • motion-reduce:animate-none
  • motion-safe:animate-*
  • not-motion-reduce:*
  • motion-reduce:hidden
  • motion-reduce:transition-none
  • @custom-variant motion-off

Easy trap: motion-reduce:animate-none loses to hover:, group-hover:, data-[…]: and peer-*: utilities, because those selectors are more specific. Write motion-safe:hover:animate-bounce instead.

Docs: prefers-reduced-motion

Custom animations in @theme

v4.0

Define --animate-name: … in @theme with its @keyframes right next to it, and Tailwind generates an animate-name utility that works with every variant. This replaces theme.extend.animation and keyframes in tailwind.config.js.

  • --animate-*
  • @keyframes in @theme
  • animate-fade-in-up
  • animate-wiggle
  • --animate-*: initial

Keyframes inside @theme are only emitted when a utility uses them. Put @keyframes outside @theme to always include them. End entrance tokens with both so the first frame applies during a delay.

Docs: theme

animate-[…] and animate-(--var)

v4.0

Set a one-off animation value without a theme token. Square brackets take any value, with underscores for spaces. The v4 parenthesis form reads a CSS variable, which suits values set per element in a style attribute.

  • animate-[wiggle_1s_ease-in-out_infinite]
  • animate-(--my-animation)
  • motion-safe:hover:animate-[…]
  • sm:motion-safe:animate-[…]
  • animate-[a_1s,b_2s]

Square brackets are v3 syntax and still work. A keyframe named inside animate-[…] is emitted from @theme, but a name hidden in a variable is not: define keyframes for animate-(--var) outside @theme.

Docs: animation

Entrances: fade-in-up and pop

v4.0

Two small tokens cover most entrances. animate-fade-in-up slides content up one rem while it fades in. animate-pop scales it up from 80% with a slight overshoot. Both fill backwards, so a delayed item stays hidden until its turn.

  • animate-fade-in-up
  • animate-pop
  • [animation-delay:150ms]
  • motion-reduce:animate-none
  • --ease-spring

CSS animations run once when the element first renders. To see them again, press Replay: it removes the demo and puts it back. With motion-reduce:animate-none the element is simply visible, which is what an entrance should fall back to.

Docs: theme

Staggered entrance with --i

core

Give each child an index in a CSS variable and turn it into a delay: style="--i:2" plus [animation-delay:calc(var(--i)*80ms)]. It scales to any number of items and works the same in React with style={{ "--i": i }}.

  • style="--i:n"
  • [animation-delay:calc(var(--i)*80ms)]
  • [animation-delay:calc(min(var(--i),6)*60ms)]
  • stagger-60

The animation needs both fill mode (the tokens here have it), or delayed items flash visible first. Cap the index on long lists so row 40 does not wait three seconds.

Docs: arbitrary properties

Animation controls with arbitrary properties

core

Tailwind has no utilities for animation-delay, -iteration-count, -direction, -fill-mode or -play-state. Arbitrary properties cover them, and they take any variant, so hover:[animation-play-state:paused] just works.

  • [animation-delay:-0.3s]
  • [animation-iteration-count:3]
  • [animation-direction:alternate]
  • [animation-fill-mode:both]
  • [animation-timing-function:steps(6)]
  • hover:[animation-play-state:paused]
  • group-hover:[animation-play-state:paused]
  • data-[paused=true]:[animation-play-state:paused]

A plain animate-* is emitted before plain [animation-…] longhands, so the longhand wins. A variant-wrapped shorthand such as hover:animate-x comes after them and resets the delay and fill mode, so repeat the longhand under the same variant.

Docs: arbitrary properties

Your own scale: animate-delay-*

v4.0

A functional @utility with --value() turns a bare number or an arbitrary value into a declaration. Define it once and write animate-delay-200, animate-delay-[350ms] or animate-delay-(--d) anywhere, with any variant.

  • @utility animate-delay-*
  • --value(integer)
  • --value([*])
  • animate-count-*
  • animate-paused
  • hover:animate-delay-500

Tailwind already uses delay-* and duration-* for transitions, so give animation helpers their own prefix. [time] is not a valid --value() type; use [*]. v4.3 adds --default() so the bare class (animate-delay) can have a value too.

Shimmer skeleton loader

v4.1

A highlight that travels across placeholder shapes. The gradient is twice as wide as the block, with matching first and last colours, and the keyframes slide its background-position. It reads as "loading" more clearly than a plain pulse.

  • animate-shimmer
  • bg-linear-to-r
  • from-* via-* to-*
  • bg-size-[200%_100%]
  • motion-reduce:animate-none

bg-size-[…] arrived in v4.1; on v4.0 write bg-[length:200%_100%]. Give every block the same animation, not just the container, and use light-on-dark colours under dark:.

Docs: background-size

Infinite marquee and logo strip

v4.0

A seamless ticker: render the items twice inside a w-max track and slide it left by exactly half its width, forever. Pause it on hover and keyboard focus so people can read and click.

  • animate-marquee
  • w-max
  • group-hover:[animation-play-state:paused]
  • group-focus-within:[animation-play-state:paused]
  • [animation-direction:reverse]
  • mask-x-from-90%
  • motion-reduce:overflow-x-auto

Put spacing on each item (mx-8), not gap-* on the track, or the loop jumps. Each copy must be wider than the container. Mark the duplicate aria-hidden. The soft edges use mask-x-from-90% (v4.1); before that, write a [mask-image:linear-gradient(…)].

Docs: theme

Attention loops: heartbeat, float, wiggle, ring-pulse

v4.0

A small kit of one-line tokens for drawing the eye without a library. Each is a few keyframes and one --animate-* variable, and each can be switched on by state, such as a checked box or an invalid field.

  • animate-heartbeat
  • animate-float
  • animate-wiggle
  • animate-ring-pulse
  • animate-spin-slow
  • motion-safe:peer-checked:animate-heartbeat
  • --alpha()

--alpha(var(--color-sky-400) / 60%) works inside @keyframes and counts as a use of that theme colour. Transform loops are cheap; box-shadow loops repaint every frame, so use them sparingly.

Docs: theme

Typewriter and blinking caret

v4.0

Reveal text one character at a time by animating width with steps(N) on a monospace font, while a second animation blinks a caret drawn as a right border. A separate animate-caret token blinks any caret element.

  • animate-typewriter
  • animate-caret
  • w-[24ch]
  • steps(24, end)
  • box-content
  • overflow-hidden whitespace-nowrap

The text length, the steps(N) count and the w-[Nch] width must all match (24 characters here). The keyframe only has a from, so the end width comes from the element itself. Use box-content so the caret border does not eat into the last letter.

Docs: theme

Gradient pan: animated backgrounds

v4.1

Make a gradient larger than its element with bg-size-[200%_200%], then slide background-position back and forth. Good for call-to-action buttons, announcement banners and indeterminate progress bars.

  • animate-gradient-pan
  • bg-linear-to-r
  • bg-linear-to-r/oklch
  • bg-size-[200%_200%]
  • animate-indeterminate

The background must be bigger than the element on the panned axis or nothing moves. The /oklch modifier picks the colour space the gradient blends in, which keeps mid-tones vivid. Large animated gradients repaint every frame, so keep them small.

Docs: background-image

Shimmering and panning gradient text

v4.1

Crop a gradient to the letters with bg-clip-text text-transparent, then move it. animate-shimmer sweeps a bright band across the text, and animate-gradient-pan drifts the colours. Use it for hero titles, "thinking" labels and badges.

  • bg-clip-text
  • text-transparent
  • animate-shimmer
  • animate-gradient-pan
  • bg-size-[200%_100%]
  • bg-linear-to-r/oklch

You need both bg-clip-text and text-transparent. Use the same first and last colour so the loop is invisible, and pick a sweep colour that contrasts with the page. Add pb-1 to big headlines so descenders are not clipped.

Docs: background-clip

SVG line drawing, checkmarks and marching dashes

v4.0

Animate stroke-dashoffset to "draw" a path. Set pathLength="1" so one class fits any path, hide it with [stroke-dasharray:1] [stroke-dashoffset:1], and run animate-draw. A second token, animate-dash-chase, makes a dashed stroke crawl forever.

  • animate-draw
  • animate-dash-chase
  • pathLength="1"
  • [stroke-dasharray:1]
  • [stroke-dashoffset:1]
  • stroke-emerald-500
  • stroke-3

Reduced-motion trap: if animate-none removes the animation, the path keeps its hidden start state and stays invisible. Put the hidden state under motion-safe: too, as below, so those users see the finished drawing.

Docs: stroke-width

State-driven animation

v4.0

Every animate-* class takes variants, so an animation can follow state instead of JavaScript: a data-* or aria-* attribute, an open <details>, a checked input, a hovered group. In v4 data and aria variants accept bare values.

  • motion-safe:group-data-[loading=true]:animate-spin
  • motion-safe:group-open:animate-fade-in-up
  • motion-safe:data-[state=active]:animate-pop
  • motion-safe:peer-checked:animate-heartbeat
  • motion-safe:pointer-fine:hover:animate-wiggle

Put motion-safe: in front of the state variant; motion-reduce:animate-none would lose to it. An animation restarts only when its name changes or the element is shown again. For exit effects, use starting: and transition-discrete.

Docs: data attributes

Individual transform properties stack with keyframes

v4.0

In v4, rotate-*, scale-* and translate-* set the separate CSS properties rotate, scale and translate, not transform. They now combine with animations that use transform, such as bounce, float or spin, instead of replacing them.

  • rotate-12
  • scale-95
  • translate-y-4
  • rotate-none
  • transition-transform
  • transition-[opacity,scale]

Two migration traps. transform-none no longer clears these utilities (use scale-none), and transition-[opacity,transform] will not animate scale-*: list scale, rotate or translate yourself.

Docs: upgrade guide

starting: enter transitions

v4.0

starting:opacity-0 wraps a utility in @starting-style, so an element transitions from that state the first time it renders or when it goes from display: none to visible. It animates popovers, dialogs and inserted nodes without keyframes.

  • starting:opacity-0
  • starting:open:scale-95
  • transition-discrete
  • transition-[opacity,scale,display,overlay]
  • open:opacity-100
  • backdrop:bg-slate-900/50

Browser support: @starting-style works in Chrome and Edge 117+, Safari 17.5+ and Firefox 129+. transition-discrete is what lets the exit animate before display: none applies. A custom transition list must name scale, display and overlay.

Docs: @starting-style

Scroll-driven reveal: view()

core

Tailwind has no scroll-driven utilities, but arbitrary properties cover them. [animation-timeline:view()] ties an animation to how far an element has travelled through its scroll container, and [animation-range:…] picks the phase. The animation scrubs forward and backward with the scrollbar.

  • animate-reveal
  • [animation-timeline:view()]
  • [animation-range:entry_0%_cover_35%]
  • [animation-range:exit_0%_exit_100%]
  • supports-[animation-timeline:view()]:*
  • motion-reduce:animate-none

Browser support: Chrome and Edge 115+, Safari 26+. Firefox still has it behind a flag (as of mid-2026), so check caniuse. Repeat the supports-[…]: prefix on the shorthand, the timeline and the range, so other browsers keep the plain static layout. Scroll the boxes to see each effect.

Docs: arbitrary properties

Reading progress: scroll()

core

[animation-timeline:scroll()] binds an animation to the scroll position of the nearest scroll container, so a bar can grow from 0 to 100% as someone reads, with no JavaScript. scroll(root) follows the whole page, and [animation-range:…] limits when it runs.

  • animate-progress
  • [animation-timeline:scroll()]
  • [animation-timeline:scroll(root)]
  • [animation-range:0_24px]
  • origin-left
  • not-supports-[animation-timeline:scroll()]:hidden
  • motion-reduce:hidden

Browser support: Chrome and Edge 115+, Safari 26+; Firefox behind a flag (as of mid-2026). Hide the bar where unsupported, because a static full bar would mislead. For reduced motion use motion-reduce:hidden: animate-none would leave the bar full width. The bar needs origin-left or it scales from the centre.

Named timelines, timeline-scope and parallax

core

Name a scroller with scroll-timeline or an element with view-timeline, and another element can follow it with animation-timeline: --name. timeline-scope on a shared ancestor lets an element outside the scroller, like a header bar, react to it.

  • [scroll-timeline:--doc_block]
  • [view-timeline-name:--chapter]
  • [timeline-scope:--doc]
  • [animation-timeline:--doc]
  • animate-parallax
  • [animation-range:cover]

Browser support matches the other scroll-driven cards (Chrome and Edge 115+, Safari 26+); timeline-scope needs Chrome and Edge 116+. Underscores in arbitrary values become spaces, so --doc_block is --doc block. A parallax layer needs overflow-hidden on its frame and to be taller than the frame.

Docs: arbitrary properties

Progressive enhancement with supports-[…]

core

supports-[prop:value]: wraps a utility in @supports, so new CSS applies only where the browser understands it. not-supports-[…]: (v4.0) styles the fallback instead. A @custom-variant can bundle "motion is welcome" and "browser supports it" into one short name.

  • supports-[animation-timeline:view()]:*
  • not-supports-[animation-timeline:view()]:*
  • @custom-variant sda
  • sda:animate-reveal
  • CSS.supports()

Prefix both the shorthand and its longhands with the same variant. A plain longhand loses to a variant-wrapped shorthand that comes later. Without support, the page simply keeps its static layout.

Docs: supports

View Transitions API and view-transition-name

core

Wrap a DOM change in document.startViewTransition() and the browser animates every element that has a view-transition-name from its old position and size to its new one. A class toggle that changes layout is enough: no keyframes, no FLIP maths.

  • document.startViewTransition()
  • [view-transition-name:card-1]
  • vt-[card-1]
  • ::view-transition-group(*)
  • ::view-transition-old(root)
  • ::view-transition-new(root)

Browser support for same-document transitions: Chrome and Edge 111+, Safari 18+, Firefox 144+. Elsewhere startViewTransition is undefined, so call the update directly and the layout simply changes. Names must be unique on the page. Tailwind has no variants for the ::view-transition-* pseudo-elements, so style them in plain CSS and switch them off for reduced motion.

@property and bg-conic: rotating borders and glows

v4.0

Register --angle with @property so the browser can animate it, animate it from 0 to 360deg, and feed it to bg-conic-[from_var(--angle)]. The usual from-*, via-* and to-* utilities set the colours. A 1px wrapper around a solid panel becomes a spinning gradient border.

  • @property --angle
  • animate-orbit
  • bg-conic-[from_var(--angle)]
  • from-* via-* to-*
  • p-px
  • rounded-[calc(1rem-1px)]
  • focus-within:[animation-play-state:running]

Browser support for @property: Chrome and Edge 85+, Safari 16.4+, Firefox 128+. Without it the angle jumps instead of turning, but the card still renders. Repeat the first colour as the last stop for a seamless loop, and give the inner panel a solid background.

Docs: background-image

@property counters: numbers that count up

v4.0

Register --num as an <integer>, animate it from 0, and show it with counter-reset and content: counter(num). Each element sets its own target in a style attribute, so one keyframe serves every tile, and the same variable can drive a bar width.

  • @property --num
  • animate-count-up
  • style="--num:4096"
  • [counter-reset:num_var(--num)]
  • after:content-[counter(num)]
  • w-[calc(var(--num)*1%)]
  • tabular-nums

Browser support matches @property (Chrome and Edge 85+, Safari 16.4+, Firefox 128+). counter() cannot add thousands separators. Generated content is unreliable for screen readers, so keep the real value in an aria-label. With inherits: true, children can read the animated value.

Docs: content

Animating gradient colour stops

v4.0

v4 registers --tw-gradient-from, -via and -to as real colour properties, so they can animate. Keyframes can move them on an element that already uses from-* and to-*, and transition-colors cross-fades a gradient on hover.

  • animate-aurora
  • --tw-gradient-from
  • --tw-gradient-to
  • transition-colors
  • hover:from-pink-500
  • bg-linear-to-br

Define keyframes that assign var(--color-*) to a custom property outside @theme, or Tailwind does not see the colour as used and the stop fades to transparent. The --tw-gradient-* names are internal: stable in v4 but not documented API.

Docs: background-image

Edge fades with mask-*

v4.1

mask-b-from-70%, mask-x-from-90% and friends fade one or two edges of an element to transparent. They replace a hand-written [mask-image:linear-gradient(…)] for scrollers, chip rows and marquees: the content just dissolves at the edge.

  • mask-x-from-90%
  • mask-b-from-70%
  • mask-r-from-80%
  • mask-x-from-70% mask-x-to-90%
  • mask-y-from-80%

A larger from value means a thinner fade. The mask clips everything inside, including focus rings, so keep interactive items away from the faded zone. On a scroll container the fade stays fixed at the edge, even once you reach the end.

Docs: mask-image

text-shadow-*: glow and flicker

v4.1

text-shadow-2xs to text-shadow-lg add depth to text, a colour utility such as text-shadow-sky-400/60 tints it, and an arbitrary value builds a neon glow. Combine with animate-pulse or a flicker keyframe for signs and "live" labels.

  • text-shadow-lg
  • text-shadow-sky-400/60
  • text-shadow-[0_0_14px_var(--color-sky-400)]
  • text-shadow-[0_0_12px_var(--tw-text-shadow-color)]
  • animate-pulse
  • animate-[flicker_3s_linear_infinite]

A colour utility such as text-shadow-pink-500 replaces the colour in a named size and in an arbitrary shadow that spells out its own colour. Write var(--tw-text-shadow-color) in the arbitrary value to build a glow that takes whatever colour utility you add. A heavy blur on big text repaints every frame under a pulse; for a large headline, animate the opacity of a duplicate glow layer instead.

Docs: text-shadow

Theme tokens inside animations

v4.0

An animation token can reuse other theme variables. A custom easing like --ease-spring works inside --animate-pop and as the ease-spring utility. --alpha() reads a theme colour inside @keyframes, and @theme static always emits a variable even when only an inline style mentions it.

  • --ease-spring
  • ease-spring
  • var(--ease-spring)
  • --alpha(var(--color-brand) / 50%)
  • @theme static
  • animate-(--my-anim)

By default only theme variables that are used end up in the CSS. If you reference an --animate-* token only from an inline style attribute, which Tailwind does not scan, declare it in @theme static.

Docs: theme
