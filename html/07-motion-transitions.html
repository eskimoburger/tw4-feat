Page 07 · Motion

Motion: transitions

Everything that moves between two states without a keyframe: which properties transition, how long and how fast, entry and exit animations for popovers, dialogs and toasts, accordions, micro-interactions and staggers. Hover, click and press Replay: every example runs live, except the React snippets at the end.

Which properties transition

core

Pick WHAT animates when a state changes. Bare transition covers the common visual properties, the named variants narrow it, and transition-[…] lets you list exactly what you need (height, width, anything).

  • transition
  • transition-colors
  • transition-opacity
  • transition-shadow
  • transition-transform
  • transition-all
  • transition-none
  • transition-[height,width]
  • transition-(--props)

Every one except transition-none also sets the default 150ms duration and easing. In v4, transition-transform covers transform, translate, scale and rotate.

Docs: transition-property

What bare transition covers, and the default theme variables

v4.0

Bare transition animates colours (including outline-color and gradient stops), opacity, shadow, filters, and the individual translate, scale and rotate properties. Since 4.1.5 it also covers display, overlay, content-visibility and pointer-events.

  • transition
  • --default-transition-duration
  • --default-transition-timing-function
  • transition-[width,background-color]

Not covered: width, height, margin, padding, inset, grid-template-rows, outline-offset. List them yourself. Defaults are 150ms and cubic-bezier(0.4, 0, 0.2, 1).

Docs: transition-property · Upgrade guide: outline-color

How long: duration-*

v4.0

Sets transition-duration. In v4 any whole number works with no config (duration-123 is 123ms), and you can use a time (duration-[1.5s]), a list (duration-[150ms,400ms,700ms]) or a variable (duration-(--d)).

  • duration-75
  • duration-300
  • duration-1000
  • duration-123
  • duration-[1.5s]
  • duration-[150ms,400ms,700ms]
  • duration-(--d)
  • hover:duration-150
  • motion-reduce:duration-0

A duration on its own is enough to animate: the CSS default for transition-property is all, so duration-300 alone transitions every property that changes, with the browser’s plain ease curve. Add a transition-* class to narrow the list and to get Tailwind’s default easing. The duration that applies is the one on the state you are moving TO, so duration-700 hover:duration-150 is fast in, slow out.

Docs: transition-duration

Wait first: delay-*

v4.0

Sets transition-delay. Like duration, any whole number works in v4. Use it for hover intent, sequencing and grace periods. A delay on the state you are moving TO only slows entering that state.

  • delay-150
  • delay-700
  • delay-1400
  • delay-0
  • delay-[calc(var(--i)*60ms)]
  • delay-(--stagger)
  • group-hover:delay-500

Docs: transition-delay

How it moves: ease-*

core

Sets the timing function. Built-ins are ease-linear, ease-in, ease-out and ease-in-out. For anything else use a variable (ease-(--my-ease)) or a curve in brackets (ease-[cubic-bezier(0.34,1.56,0.64,1)]).

  • ease-linear
  • ease-in
  • ease-out
  • ease-in-out
  • ease-initial
  • ease-(--my-ease)
  • ease-[cubic-bezier(…)]

ease-in is cubic-bezier(0.4, 0, 1, 1), ease-out is (0, 0, 0.2, 1), ease-in-out is (0.4, 0, 0.2, 1). Enter with ease-out (fast start, soft landing), leave with ease-in. No spaces in arbitrary values: use commas or underscores.

Docs: transition-timing-function

Custom easing in @theme

v4.0

Any --ease-* variable you add to @theme becomes an ease-* utility. Plain cubic-bezier() values work, and so do CSS linear() curves, which means real spring and bounce physics ship as one class.

  • --ease-snappy
  • --ease-spring
  • --ease-bounce
  • ease-snappy
  • ease-spring
  • ease-bounce
  • --default-transition-timing-function

Browser support for linear(): Chrome 113, Safari 17.2, Firefox 112. In an older browser the curve is invalid, so the transition falls back to the plain ease curve: it still runs for the same duration, just without the spring. Overshoot curves go past the target on translate and scale; opacity is clamped. Generate your own curves with a linear() easing generator.

Docs: customizing your theme

Easing race track

v4.0

The same distance, the same duration, six different curves. Press Play and watch how each one spends its time. Duration and easing are independent knobs: the second race fixes the curve and changes only the duration.

  • @container
  • group-data-run:translate-x-[calc(85cqw-1.5rem)]
  • duration-(--race-d)
  • ease-linear
  • ease-spring
  • transition-transform

Each lane is an @container, so 100cqw is the lane width and the distance needs no JS measuring. To replay a transition the racers must first jump back to the start with no transition, which is what the Play script does.

Hover and focus micro-interactions

core

Small transitions that make an interface feel alive: a button that lifts, an arrow that nudges, an underline that grows, an image that zooms inside its frame, a focus ring that steps outward.

  • hover:-translate-y-0.5
  • hover:shadow-lg
  • active:scale-95
  • group-hover:translate-x-1
  • group-hover/row:opacity-100
  • after:scale-x-0
  • hover:after:scale-x-100
  • after:origin-right
  • hover:after:origin-left
  • transition-[outline-offset,outline-color]

In v4 hover: only applies on devices that can hover (@media (hover: hover)), so never hide essential UI behind it. transform-origin is not in the list that transition-transform covers (transform, translate, scale, rotate), so it flips at once, which is exactly why swapping after:origin-right for hover:after:origin-left makes the underline enter from the left and leave to the right.

Docs: hover, focus and other states

translate, scale and rotate compose

v4.0

In v4 the translate-*, scale-* and rotate-* utilities write the individual CSS properties of the same names. They stack without fighting each other, and each can be reset or transitioned on its own.

  • hover:scale-105
  • hover:-rotate-3
  • hover:-translate-y-2
  • scale-none
  • rotate-none
  • translate-none
  • transition-transform
  • transition-[opacity,scale]

Two upgrade traps. transform-none no longer resets these, use scale-none and friends. And a custom list like transition-[opacity,transform] stops animating them, name scale, translate and rotate instead. Rotating in 3D (rotate-x-*) still uses transform.

Upgrade guide: individual transform properties

motion-safe: and motion-reduce:

core

These variants follow the OS “reduce motion” setting. Write the movement behind motion-safe: so people who asked for less motion get the still version by default, and keep non-motion feedback (colour, underline, opacity) for everyone.

  • motion-safe:transition
  • motion-safe:hover:-translate-y-1
  • motion-safe:animate-spin
  • motion-reduce:hidden
  • motion-reduce:transition-none
  • motion-reduce:duration-0
  • motion-reduce:delay-0
  • not-motion-reduce:transition

Do not use motion-reduce:hover:transform-none to undo a hover move in v4: it cannot reset the individual translate, scale and rotate properties. Gate the move itself with motion-safe:, or reset it with motion-reduce:hover:translate-y-0. To test, switch on “reduce motion” in your OS or in DevTools rendering tools.

Docs: prefers-reduced-motion

Animate display: none with transition-discrete

v4.0

transition-discrete sets transition-behavior: allow-discrete. Properties that normally flip instantly, such as display, can then take part in a transition. An element that goes to display: none stays rendered until its other transitions finish, so it can fade out and only then leave the layout. No timeouts, no JS.

  • transition-discrete
  • transition-normal
  • hidden
  • peer-has-checked:block
  • not-peer-has-checked:opacity-0
  • data-dismissed:hidden
  • group-hover:block
  • starting:group-hover:opacity-0

Leaving needs only transition-discrete. Entering from display: none also needs starting: (next card), because the browser has no “before” style yet. Since 4.1.5 plain transition already includes display; on 4.0.x use transition-all or list display yourself. Support: Chrome/Edge 117, Safari 17.4, Firefox 129; elsewhere the element just flips instantly.

Docs: transition-behavior

starting: for entry animations

v4.0

starting: wraps a utility in @starting-style. It gives an element its “before” look the first time it renders: on page load, when JS appends it, or when it goes from display: none to visible. Put a transition on the element and it animates in.

  • starting:opacity-0
  • starting:translate-y-4
  • starting:scale-95
  • starting:blur-sm
  • starting:data-on:opacity-0
  • starting:open:opacity-0
  • starting:group-hover:opacity-0

Support: Chrome/Edge 117, Safari 17.5, Firefox 129. Treat it as progressive enhancement: the element must look right without it. Entry demos here replay when they scroll into view; use Replay to run them again.

Docs: @starting-style

Popover enter and exit with open:

v4.0

The native popover attribute needs no JS: popovertarget on a button opens it. Style the closed state, style open:, add starting:open: for the entry and transition-discrete for the exit, and it animates both ways.

  • popover
  • popovertarget
  • open:opacity-100
  • starting:open:opacity-0
  • transition-discrete
  • backdrop:bg-black/40
  • m-auto
  • origin-top-right

Preflight resets margin, so add m-auto to get the browser’s default centring back. open: matches [open], :popover-open and :open. The exit relies on the overlay property (Chromium); in other engines the popover still enters smoothly and just disappears at the end. Popover API: Chrome 114, Safari 17, Firefox 125.

Docs: @starting-style

<dialog> enter and exit with backdrop:

v4.0

A native <dialog> opened with showModal() fades and scales in and out with classes only. The dialog and its ::backdrop are styled and transitioned separately, with the same closed/open/starting recipe as a popover.

  • open:opacity-100
  • starting:open:opacity-0
  • transition-discrete
  • backdrop:bg-black/0
  • backdrop:transition
  • backdrop:transition-discrete
  • open:backdrop:bg-black/50
  • starting:open:backdrop:bg-black/0
  • inert:opacity-40

Add m-auto (preflight removes the browser’s centring) and close with <form method="dialog">. Prefer plain transition over transition-all here: it already contains display and overlay (4.1.5+) without dragging in unrelated properties. The exit of a top-layer element needs overlay (Chromium 117+); Firefox and Safari animate the entry and may skip the exit.

Docs: ::backdrop · Docs: inert

Toasts: starting: in, data-closing: out

v4.0

Append the toast with a transition and starting: classes and it animates in with no extra code. To leave, set a data-closing attribute that carries the exit classes, then remove the node when the transition ends.

  • starting:opacity-0
  • starting:translate-y-4
  • data-closing:opacity-0
  • data-closing:-translate-y-2
  • starting:grid-rows-[0fr]
  • popover="manual"
  • open:

Filter transitionend by target and propertyName, or the toast is removed when the first of several properties, or a transition on a child such as the close button, finishes. For toasts that must sit above open modals, use popover="manual" so they live in the top layer. In the live Tailwind build, the CSS for a class that has never been in the DOM is generated a moment after the element is inserted. Reading layout (offsetWidth, getBoundingClientRect) in that gap can make the browser style the element without its classes first and cause stray transitions. These toasts are clones of a prototype that already carries every class, so they are safe, and a normal build ships its CSS up front.

Docs: @starting-style

Native accordion with details-content:

v4.1

The details-content: variant targets the ::details-content box of a <details>. Combined with interpolate-size it lets the native element animate its height from 0 to auto, with no JS and no wrapper elements.

  • details-content:h-0
  • details-content:overflow-clip
  • details-content:transition-[height,content-visibility]
  • details-content:transition-discrete
  • open:details-content:h-auto
  • [interpolate-size:allow-keywords]
  • group-open:rotate-180

You need both interpolate-size (so 0 can animate to auto) and transition-discrete with content-visibility in the list (so the closing animation is not cut off). Clip the overflow so the content does not spill while the box is short: overflow-clip does that without turning the box into a scroll container. Support: ::details-content is in Chrome and Edge 131, Safari 18.4 and Firefox 143; interpolate-size is Chromium 129+ only so far. Without interpolate-size the height snaps instead of animating, and without ::details-content the rules are ignored and <details> works as normal. Treat it as a progressive enhancement and see the grid-rows card for a cross-browser version.

Docs: details-content

Cross-browser accordion: grid-rows-[0fr] to [1fr]

core

Put the content in a one-row grid and transition grid-template-rows from 0fr to 1fr. Fractional units interpolate numerically, so the height animates to the content’s real size in every browser. The inner child needs overflow-hidden.

  • grid
  • grid-rows-[0fr]
  • grid-rows-[1fr]
  • transition-[grid-template-rows]
  • peer-aria-expanded:grid-rows-[1fr]
  • group-data-[state=open]:grid-rows-[1fr]
  • overflow-hidden
  • min-h-0
  • inert

grid-template-rows is not in the default transition list, so name it. Put padding on an element INSIDE the clipped child (padding on the clipped child itself stops it collapsing to 0). Closed content is still focusable, so set inert while it is closed.

Docs: grid-template-rows

Animate to height: auto

core

Tailwind has no interpolate-size utility, but the arbitrary property [interpolate-size:allow-keywords] opts an element in. Then h-0 to h-auto (or h-fit, h-max) transitions with transition-[height]. A per-element alternative is h-[calc-size(auto,size)].

  • [interpolate-size:allow-keywords]
  • h-0
  • h-auto
  • transition-[height]
  • data-[state=open]:h-auto
  • h-[calc-size(auto,size)]

The property is inherited, so you can set it once on :root in @layer base for the whole site. One end of the animation must be a length or percentage, so h-0 to h-auto works but h-auto to h-max does not. Support: interpolate-size and calc-size() in Chromium 129+. Other engines snap to the final height, so this is progressive enhancement.

Docs: arbitrary properties

Switches and checkboxes with peer-checked: and has-checked:

core

A visually hidden checkbox (sr-only) holds the state; CSS reacts to it with no JS. peer-checked: styles later siblings, has-checked: styles a parent that contains a checked input, and group-has-checked: reaches nested children from it.

  • sr-only
  • peer
  • peer-checked:bg-indigo-600
  • peer-checked:after:translate-x-5
  • has-checked:bg-emerald-500
  • group-has-checked:translate-x-5
  • has-focus-visible:ring-2
  • peer-focus-visible:ring-2

peer-* only reaches siblings that come AFTER the input. A knob nested inside the track span is not a sibling, so use group-has-checked: on it, or draw the knob with after: on the track.

Rotate icons from state: data-*, aria-*, open:

v4.0

A tiny script flips one attribute, and the variants do the rest. Style a chevron from data-[state=open], aria-expanded, aria-sort or the native open state of a <details>. v4 also lets you test a data attribute that has no value (data-on:rotate-180 matches [data-on]) and adds the in-* variant, which needs no group class.

  • group-data-[state=open]:rotate-180
  • group-aria-expanded:rotate-180
  • group-aria-[sort=descending]:rotate-180
  • group-open:rotate-180
  • in-data-[state=open]:rotate-90
  • data-on:rotate-180
  • group-data-[state=open]/dir:rotate-90

in-* and a repeated group name match ANY ancestor in that state, not just the nearest one. For nested trees give each level its own group name (group/dir, group/sub).

Like, rating and success morphs

v4.0

Combine a transition (fill, scale, swap) with a one-shot keyframe registered in @theme. --animate-pop plus @keyframes pop gives you animate-pop, and peer-checked:animate-pop plays it every time a hidden checkbox is checked.

  • --animate-pop
  • peer-checked:animate-pop
  • peer-checked:fill-rose-500
  • active:scale-90
  • group-data-done:scale-100
  • delay-[calc(var(--i)*40ms)]
  • group-hover:fill-amber-400

Use the individual scale property inside the keyframe (not transform: scale()) so it composes with Tailwind’s own scale-* utilities. A pure transition cannot overshoot unless its easing does, which is why ease-spring shows up here too.

Docs: defining animation keyframes

Staggered transitions with a CSS variable

v4.0

Give each item style="--i:3" and write the delay once: delay-[calc(var(--i)*60ms)]. Flip one attribute on the parent and the items cascade in. The variable is the only thing that differs, so the class names stay complete strings.

  • style="--i:3"
  • delay-[calc(var(--i)*60ms)]
  • delay-[calc((var(--n)-var(--i))*50ms)]
  • in-data-on:opacity-100
  • @utility stagger-*
  • stagger-80
  • motion-reduce:delay-0

A delay only affects the transition INTO the state that carries it. Put it on the resting state to stagger the way in, and a different delay on the open state to stagger the way out. In React or Vue write style={{'--i': i}} plus the static class, never delay-${i*60}: a scanner cannot see that class.

Docs: transition-delay, custom value

Staggers from position: nth-* and sibling-index()

v4.0

For short fixed lists, nth-2:delay-100, nth-3:delay-200 and friends set a delay per position with no variable. For lists of any length, the CSS function sibling-index() gives each child its position: delay-[calc(sibling-index()*40ms)].

  • nth-2:delay-100
  • nth-3:delay-200
  • nth-[2n]:delay-100
  • delay-[calc(sibling-index()*40ms)]
  • odd:-translate-x-6
  • even:translate-x-6

sibling-index() counts from 1 and is new CSS: Chrome and Edge 138, Safari 26.2; other engines are catching up. Where it is unsupported the declaration is dropped and the items simply move together, so the effect degrades cleanly. The --i variable technique is the fallback that works everywhere.

Docs: first, last, odd and even

Gradient colour stops transition

v4.0

In v4 the gradient stops (from-*, via-*, to-*) are registered custom properties and are part of transition and transition-colors. A gradient background therefore animates between two colour schemes with nothing extra.

  • bg-linear-to-r
  • from-indigo-500
  • via-rose-400
  • to-pink-500
  • hover:from-pink-500
  • data-on:to-fuchsia-900
  • bg-linear-to-r/oklch
  • transition-colors

Only the colour stops animate, not the angle or a switch between gradient types. A stop that exists in only one state, such as a via-* added on hover, fades in from transparent; give both states the same stops to blend one colour into another.

Docs: background-image

Sliding gradients with bg-size and bg-position

v4.1

Make a gradient twice as wide as its box with bg-size-[200%_auto], then transition background-position to slide it across. bg-size-[…] and bg-position-[…] arbitrary utilities arrived in 4.1.

  • bg-size-[200%_auto]
  • bg-position-[0%_0%]
  • hover:bg-position-[100%_0%]
  • transition-[background-position]
  • bg-clip-text
  • text-transparent

On 4.0 write bg-[length:200%_auto] and bg-[position:100%_0%] instead. background-position is not in the default transition list, so name it. End the gradient on its first colour (from-x via-y to-x) so the slide loops seamlessly.

Docs: background-position

Sliding indicator driven by a CSS variable

v4.0

One absolutely positioned pill moves between options. A script writes the active index (or pixel offset) into a custom property, and translate-x-[calc(var(--i)*100%)] or translate-x-(--x) does the rest, with whatever easing you like.

  • translate-x-[calc(var(--i)*100%)]
  • translate-x-(--x)
  • translate-y-(--y)
  • w-(--w)
  • w-[calc((100%-0.5rem)/3)]
  • transition-[translate,width]
  • ease-spring

The class names are static, only the variable changes, so a build-time scanner (and the live build) sees everything it needs. Never build class names such as translate-x-${i} in JS.

Docs: translate, custom value

will-change-*

core

Hints to the browser which property is about to change, so it can prepare a compositor layer. It is a last resort for a known jank problem, not a default: apply it just before the animation and release it afterwards.

  • will-change-auto
  • will-change-transform
  • will-change-scroll
  • will-change-contents
  • will-change-(--hint)
  • will-change-[top,left]
  • data-hot:will-change-transform

A permanent will-change-transform on many elements wastes GPU memory and can make things slower. A hover:will-change-transform arrives only when the hover starts, which gives the browser no head start. The docs say to apply it just before the change and remove it shortly after with will-change-auto; the first demo below does that from JS with pointerover and transitionend.

Docs: will-change

Hover is capability-gated: pointer-coarse: and friends

v4.1

Since v4.0 hover: only applies on devices whose primary input can hover, so touch screens never get stuck hover states. Version 4.1 added pointer-fine:, pointer-coarse:, pointer-none: and the any-pointer-* set, to size targets and gate effects per input type.

  • hover:-translate-y-0.5
  • active:scale-95
  • pointer-coarse:py-3
  • pointer-fine:hover:bg-slate-900
  • any-pointer-coarse:p-4
  • @custom-variant hover (&:hover);

Use active: for touch feedback, and treat hover as an enhancement: never hide essential information behind it. To restore the old tap-to-hover behaviour site-wide, override the variant with @custom-variant hover (&:hover);.

Docs: pointer and any-pointer · Upgrade guide: hover on mobile

Motion tokens: @custom-variant, @utility, @keyframes

v4.0

Turn repeated motion into your own vocabulary. A custom variant like hocus: covers hover plus keyboard focus, and an @utility wraps a keyframe so authors write pop-in instead of a long animation value. All of it works inside the page’s <style type="text/tailwindcss">.

  • @custom-variant hocus
  • hocus:-translate-y-0.5
  • @utility pop-in
  • @keyframes pop-in
  • @utility stagger-*
  • motion-safe:hocus:

@keyframes written outside @theme are always emitted; inside @theme only when an --animate-* variable is used. The live browser build does not support @plugin, @config or local @import.

The same patterns in React

v4.0

None of the effects above need an animation library. In a React app the rules are the same: keep class names as complete strings, pass numbers through CSS variables, drive state with data-* attributes, and let starting: handle mounting while a flag plus onTransitionEnd handles unmounting.

  • style={{'--i': i}}
  • data-state={open ? 'open' : 'closed'}
  • onTransitionEnd
  • inert={!open}
  • dialogRef.current?.showModal()
  • @import "tailwindcss";

Code only: these need React and a build step, so they cannot run in this standalone page. Each one is the real component for a live demo above. Theme tokens are real CSS variables, so a JS animation library can read them too, for example animate={{ backgroundColor: 'var(--color-blue-500)' }}.

Docs: theme variables
