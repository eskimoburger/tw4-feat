Page 06 · Variants

Environment & form variants

Variants that react to the state of a form control, to open and inert elements, and to the device and user settings around the page: pointer, motion, contrast, forced colors, orientation and print. Every media variant has a LIVE chip that uses the variant itself, so you can flip a setting in your OS or DevTools and watch it light up (the full board is at the end).

user-valid: / user-invalid:

v4.1

Match a field only after the person has interacted with it: changed the value and left the field, or tried to submit the form. Plain invalid: matches from the first paint, so an empty required field is already red before anyone types. Use the user- versions for inline validation that does not shout at people.

  • user-valid:*
  • user-invalid:*
  • peer-user-invalid:*
  • has-user-invalid:*
  • group-has-user-invalid:*

Docs: :user-invalid · v4.1 post

invalid: valid: required: optional:

core

required: and optional: describe the markup. invalid: and valid: describe the current value. A <form> is itself :invalid while any control inside is, so group-invalid: on the form can gate a button without JS.

  • required:*
  • optional:*
  • invalid:*
  • valid:*
  • peer-required:*
  • peer-optional:*
  • group-invalid:*

placeholder-shown:

core

Matches while the placeholder is visible, which means the field is empty. With peer-* it drives floating labels, clear buttons and keyboard-hint badges with no JS.

  • placeholder-shown:*
  • peer-placeholder-shown:*
  • peer-not-placeholder-shown:*
  • peer-focus:*

The field needs a placeholder attribute, even a blank one: use placeholder=" " for floating labels.

Docs: :placeholder-shown

checked: for checkboxes and radios

core

Styles checked checkboxes and radios directly (checked:) or through siblings and parents (peer-checked:, has-checked:). Hide the real input with sr-only to build switches, cards and chips that stay keyboard accessible.

  • checked:*
  • peer-checked:*
  • has-checked:*
  • peer-focus-visible:*
  • has-focus-visible:*

If you use appearance-none, add forced-colors:appearance-auto so the native control returns in forced-colors mode.

Docs: :checked

indeterminate:

core

Matches checkboxes whose indeterminate DOM property is true, such as a "select all" box when only some rows are selected. There is no HTML attribute for it, so you set the property from JS. A <progress> without a value matches too.

  • indeterminate:*
  • group-has-indeterminate:*
  • has-indeterminate:*
  • indeterminate:motion-safe:*

Docs: :indeterminate

enabled: / disabled:

core

Style controls by their disabled state. enabled:hover: keeps a disabled button from getting a hover color. A <fieldset disabled> disables every control inside, and in-disabled: (new in v4.0) or has-disabled: let labels and cards dim without a group class.

  • enabled:*
  • disabled:*
  • in-disabled:*
  • has-disabled:*
  • group-has-disabled:*

Preflight gives buttons cursor: default in v4, so add enabled:cursor-pointer yourself. hover: only fires on hover-capable devices (see below).

Docs: :required and :disabled

focus-visible:

core

Shows a focus style only when the browser decides it helps: keyboard navigation, and any focus on a text field. Mouse clicks on buttons and links do not trigger it, which is why it is the usual choice for focus rings.

  • focus-visible:outline-2
  • focus-visible:ring-2
  • has-focus-visible:*
  • peer-focus-visible:*
  • outline-hidden

v4 renamed outline-none to outline-hidden (it keeps an outline in forced-colors mode), and ring is now 1px, so use ring-2 or ring-3.

Docs: :focus-visible · Upgrade guide

read-only:

core

Styles inputs and textareas that have the readonly attribute. They stay focusable, selectable and submitted with the form, unlike disabled ones. Put it on form controls only: :read-only matches every element that is not editable.

  • read-only:*
  • read-only:focus:*
  • peer-read-only:*

There is no read-write: variant in Tailwind.

Docs: :read-only

in-range: / out-of-range:

core

Match inputs that have min or max limits, depending on whether the current value satisfies them. Works on number, range, date and time inputs. Typing outside the range is not blocked, it only changes the styling.

  • in-range:*
  • out-of-range:*
  • peer-out-of-range:*

An input with no limits matches neither variant.

Docs: :out-of-range

autofill:

core

Styles an input that the browser has autofilled. Use it for branded login forms and to stop floating labels from overlapping autofilled text. Chrome paints its own fill over background-color, so the usual trick is a large inset box-shadow plus -webkit-text-fill-color.

  • autofill:*
  • peer-autofill:*
  • autofill:shadow-[inset_…]

The variant compiles live, but a page cannot force autofill: you only see it when the browser fills a field from your saved details. Each example has a static preview of the same classes.

Docs: :autofill

field-sizing-content

v4.0

Makes textareas, inputs and selects size to their content with no JS. Pair it with min-h-* and max-h-* so an empty field does not collapse and a long paste does not grow forever.

  • field-sizing-content
  • field-sizing-fixed
  • min-h-12
  • max-h-60

Browser support: Chrome and Edge 123, Safari 26.2 and Firefox 152 (check caniuse for the current picture). Where it is missing the field keeps its normal fixed size.

Docs: field-sizing

accent-* and caret-*

core

Color native controls (checkbox, radio, range) with accent-* and the text cursor with caret-*. It is the lowest-effort alternative to appearance-none custom controls and keeps native accessibility and forced-colors behavior.

  • accent-indigo-600
  • accent-auto
  • caret-pink-500
  • caret-transparent

Docs: accent-color · caret-color

scheme-* (color-scheme)

v4.0

Sets color-scheme so native UI (scrollbars, date pickers, select popups, autofill) matches your theme. Put scheme-light dark:scheme-dark on the root once and native widgets follow.

  • scheme-normal
  • scheme-light
  • scheme-dark
  • scheme-light-dark
  • scheme-only-dark
  • scheme-only-light

Docs: color-scheme · Dark mode page

open: on <details>

core

Styles a disclosure widget while it is open. group-open:, in-open: (new in v4.0) and has-open: build on it, so you can rotate a chevron or restyle a whole card without any JS.

  • open:*
  • group-open:*
  • group-open/name:*
  • in-open:*
  • has-open:*

In v4 open: compiles to &:is([open], :popover-open, :open), so one variant covers details, dialogs and popovers. To hide the default arrow use list-none plus [&::-webkit-details-marker]:hidden for Safari.

Docs: Open/closed state

open: on popovers

v4.0

The same open: variant matches :popover-open, so an element with the popover attribute, opened by a popovertarget button, can be styled and animated with zero JS. You get light dismiss and Esc for free.

  • popover
  • popovertarget
  • open:*
  • starting:open:*
  • backdrop:*
  • has-open:*
  • transition-discrete

There is no popover-open: variant: use open:. Browser support: the popover attribute is in all current browsers; CSS anchor positioning (the menu below) is in Chrome and Edge 125, Safari 26 and Firefox 147, so older browsers need a fallback position. For the deep dive on starting: and transition-discrete, see Motion: transitions.

Docs: Open/closed state

open: on <dialog>

core

A dialog opened with showModal() or an invoker command matches open:. Combine it with starting: and transition-discrete for enter and exit animations, and with backdrop: to style the dimmed layer behind it.

  • open:*
  • open:backdrop:*
  • starting:open:*
  • backdrop:*
  • commandfor command

Write open:backdrop:, not backdrop:open: (variants apply left to right in v4). Invoker commands (commandfor / command) are newer than <dialog> (Chrome and Edge 135, Firefox 144, Safari 26.2); the JS below falls back to showModal() where they are missing.

Docs: Open/closed state · ::backdrop

details-content:

v4.1

Targets the ::details-content part of <details>: the box that holds everything after <summary>. You can now pad, border, scroll or animate the content container itself, not just its children.

  • details-content:*
  • open:details-content:*
  • [interpolate-size:allow-keywords]

Write open:details-content:h-auto. The other order, details-content:open:, generates an invalid selector. Browser support: ::details-content works in Chrome and Edge 131, Safari 18.4 and Firefox 143. interpolate-size (the smooth height) is in Chrome and Edge 129 and newer but not yet in Firefox or Safari, so check caniuse. Without them the disclosure simply opens instantly.

Docs: ::details-content · v4.1 post

inert:

v4.0

Styles anything with the inert attribute, or inside an element that has it. The attribute blocks clicks, focus and assistive tech; the variant gives the visual cue. Use it for locked steps, sub-options that do not apply yet, and "saving" states.

  • inert:opacity-25
  • inert:grayscale
  • inert:cursor-wait
  • inert:blur-sm

The variant also matches descendants, so an inert:opacity-* on a child inside an inert parent compounds. Toggle the attribute from JS with el.inert = true.

Docs: Styling inert elements

starting: (@starting-style)

v4.0

Sets the first-frame look of an element that has just been added to the page, or that goes from display: none to visible. The browser transitions from that look to the normal one. It is what powers the popover and dialog animations above.

  • starting:opacity-0
  • starting:-translate-y-3
  • starting:open:*
  • transition-discrete

Browser support: @starting-style is in current Chrome, Safari and Firefox. Deep dive: Motion: transitions.

Docs: @starting-style · transition-behavior

hover: only on hover-capable devices

v4.0

In v4, hover: is wrapped in @media (hover: hover), so it only applies when the primary input can hover. A tap on a phone no longer leaves a sticky hover color behind. group-hover:, peer-hover:, in-hover: and enabled:hover: work the same way. One line brings v3 behavior back.

  • hover:*
  • group-hover:*
  • @custom-variant hover (&:hover)
  • @custom-variant any-hover

Treat hover as an enhancement: never hide required functionality behind it, because touch devices cannot hover.

Docs: Hover styles on mobile

pointer-fine: pointer-coarse: pointer-none:

v4.1

Target the primary pointing device: an accurate one (mouse, trackpad), a coarse one (finger on a touchscreen), or none. Use them to make tap targets bigger on touch, swap keyboard hints for tap hints, and keep hover-only controls visible on phones.

  • pointer-fine:*
  • pointer-coarse:*
  • pointer-none:*
  • not-pointer-coarse:*

Only the primary pointer counts: a laptop with a touchscreen still reports fine. See any-pointer-* below for hybrids.

Docs: pointer and any-pointer · v4.1 post

any-pointer-fine: any-pointer-coarse: any-pointer-none:

v4.1

Like pointer-*, but true when any connected pointing device matches. any-pointer-coarse: is how you detect a touchscreen on a laptop that also has a trackpad.

  • any-pointer-fine:*
  • any-pointer-coarse:*
  • any-pointer-none:*

A phone with a Bluetooth mouse reports any-pointer: fine as well.

Docs: pointer and any-pointer

motion-safe: / motion-reduce:

core

motion-reduce: applies when the user asked their system to minimize motion (prefers-reduced-motion: reduce). motion-safe: applies when they did not. Use motion-safe: when motion-reduce: would mean undoing a long list of styles.

  • motion-reduce:*
  • motion-safe:*
  • motion-safe:hover:*
  • not-motion-reduce:*

Starting animations and transitions are covered on Motion: transitions and Motion: keyframes & scroll.

Docs: prefers-reduced-motion · animation

contrast-more: / contrast-less:

core

Respond to prefers-contrast. Strengthen borders, text and opacity for people who asked for more contrast, and soften things for those who asked for less.

  • contrast-more:*
  • contrast-less:*
  • contrast-more:border-2
  • contrast-more:backdrop-blur-none

On macOS the "Increase contrast" setting turns contrast-more: on. DevTools can emulate more, less and custom.

Docs: prefers-contrast

forced-colors:

core

Matches when the browser replaces your palette with the user's own (Windows contrast themes). Backgrounds, shadows and color-only cues disappear, so use this variant to swap in text, borders and native controls.

  • forced-colors:*
  • forced-colors:appearance-auto
  • forced-colors:border-[ButtonText]
  • forced-colors:bg-[Highlight]
  • not-forced-colors:*

Leave focus visible too: outline-hidden keeps a transparent outline that turns visible in forced-colors mode.

Docs: forced-colors

forced-color-adjust-none / -auto

core

Opts an element out of forced colors, or back in. Use it where the color itself is the content: swatches, chart keys, brand marks. Opting out makes you responsible for contrast, so keep it to small elements, never whole pages.

  • forced-color-adjust-none
  • forced-color-adjust-auto
  • lg:forced-color-adjust-auto

Docs: forced-color-adjust

portrait: / landscape:

core

Match the orientation of the viewport: taller than wide is portrait, otherwise landscape. They flip when you resize a desktop window, not only when a phone rotates. For component-level sizing use container queries instead.

  • portrait:*
  • landscape:*
  • portrait:grid-cols-1
  • landscape:aspect-video

Docs: orientation · Container queries page

print:

core

Applies in print and print preview. Hide navigation and buttons, reveal print-only text, drop shadows, and keep cards from splitting across pages.

  • print:hidden
  • hidden print:block
  • print:break-inside-avoid
  • print:after:content-[attr(href)]
  • not-print:*

It only shows in print preview (Ctrl/Cmd + P, a Print button, or DevTools "Emulate CSS media type: print"), so a chip cannot light up on screen. Browsers often skip background colors when printing, so do not rely on them.

Docs: print

inverted-colors:

v4.1

Matches when the operating system has inverted the display. Use it to avoid effects that look wrong inverted, such as black shadows turning into glowing white halos, or photos turning into negatives.

  • inverted-colors:shadow-none
  • inverted-colors:invert
  • inverted-colors:border

Browser support: only Safari implements inverted-colors today, so you cannot test it in Chrome or Firefox. The previews below simulate inversion with the invert filter.

Docs: inverted-colors · v4.1 post

noscript:

v4.1

Applies only when scripting is turned off (@media (scripting: none)). Use it to show an "enable JavaScript" banner, keep content readable, or hide controls that need a script.

  • noscript:block
  • hidden noscript:block
  • noscript:hidden

Code-only in this showcase: the in-browser Tailwind build itself needs JavaScript to produce any CSS, so with scripting off the whole page is unstyled. With CSS compiled ahead of time (CLI, Vite, PostCSS) it works as shown. Browser support: the scripting media feature is in current Chrome, Firefox and Safari.

Docs: scripting · v4.1 post

not-* with media variants

v4.0

The v4 not- variant negates other variants, including media queries. It turns "do this unless the user asked otherwise" into the default instead of an undo list. Stacked variants read left to right.

  • not-forced-colors:*
  • not-motion-reduce:*
  • not-pointer-coarse:hover:*
  • not-print:*
  • hover:not-focus:*

Not always identical to the positive variant: not-motion-reduce: is @media not (prefers-reduced-motion: reduce), while motion-safe: requires no-preference.

Docs: :not()

@custom-variant for environment checks

v4.0

@custom-variant turns any media query or selector into a variant, so you can name the checks Tailwind does not ship: real touch devices, hover capability, "JavaScript did not run". Since v4.3, @variant also accepts stacked (hover:focus) and compound (hover, focus) variants inside your own CSS.

  • @custom-variant touch
  • @custom-variant can-hover
  • @custom-variant any-hover
  • @custom-variant no-js
  • @variant hover:focus v4.3
  • @variant hover, focus v4.3

These live in your stylesheet (here, the page's <style type="text/tailwindcss">). Stacked and compound @variant need v4.3 or newer.

Docs: custom variants · v4.3 post · Directives page
