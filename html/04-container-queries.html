Container queries

Style a component from the width of the box it sits in instead of the width of the screen. This page covers @container, the @sm: … @7xl: and @max-* variants, ranges, named and nested containers, container units, custom sizes and the v4.3 @container-size. Drag the handles and sliders: every example is live.

@container and the size variants

v4.0

Add @container to a parent and its descendants can use @sm:, @md:, @lg: and friends, which react to that parent's width instead of the screen. Like viewport breakpoints they are mobile-first: a variant applies at that width and up.

  • @container
  • @3xs: … @7xl:
  • @min-md:
  • @[475px]:

A container cannot style itself, only its descendants. Queries measure the container's content box, so padding and border on the container are not counted. Browser support: Baseline 2023 (Chrome and Edge 105, Safari 16, Firefox 110).

Drag to resize: the live playground

v4.0

Make the wrapper both the container and the resize target with @container resize-x overflow-auto. Drag its corner (or use the slider on a touch screen) and the component reflows with no JavaScript inside it.

  • @container/demo
  • resize-x
  • overflow-auto
  • min-w-56
  • @md/demo:

resize only works when overflow is not visible. The readout script is optional: it prints the content-box width, which is the number the queries test.

One component, two slots

v4.0

Drop the same markup into a narrow sidebar and a wide main column, each wrapped in its own @container, and each copy picks the layout that fits its slot. Viewport breakpoints cannot do this because the screen is the same size for both.

  • <aside class="@container">
  • <main class="@container">
  • @sm:flex-row
  • @max-xs:hidden

Give a flex or grid child min-w-0 so it can shrink below its content, otherwise the container never gets narrow enough to switch.

Docs: responsive design, what are container queries

Container queries or viewport breakpoints?

v4.0

Use viewport breakpoints (md:) for page-level decisions that depend on the screen, and container queries (@md:) for components that depend on the space they are given. The two scales are different: @md is 28rem, md: is 48rem.

  • md:flex-row
  • @md:flex-row
  • lg:grid-cols-[…]
  • dark:
  • print:

Container queries only see size. Media features such as dark:, print:, motion-reduce:, pointer-coarse: and landscape: stay viewport-level, and mixing both in one component is normal.

A grid whose columns follow its container

v4.0

Put @container on the parent of the grid and step the column count with @xs:, @lg:, @3xl:. The grid gets more columns when its slot is wide, such as no sidebar, and fewer when the same slot is narrow.

  • @container
  • grid-cols-2
  • @lg:grid-cols-3
  • @3xl:grid-cols-4
  • repeat(auto-fill,minmax())

The grid cannot be its own container for its own variants: put @container on its parent. If you only need "as many columns as fit", grid-cols-[repeat(auto-fill,minmax(min(100%,7rem),1fr))] needs no query at all.

@max-*: below a container size

v4.0

@max-sm:, @max-md: and the rest apply below a container size, the mirror of @sm:. Reach for them for desktop-first tweaks inside a component, like collapsing a column or hiding a label when space runs out.

  • @max-3xs: … @max-7xl:
  • @max-md:hidden
  • @max-sm:sr-only
  • @max-[960px]:

@max-md: means width < 28rem and @md: means width >= 28rem, so the two never overlap. Avoid mixing both directions on the same property in one element.

Docs: responsive design, max-width container queries

Container query ranges

v4.0

Stack a min variant and a max variant to target a band between two container sizes. @sm:@max-lg:grid-cols-2 applies from 24rem up to, but not including, 32rem. The order you write them in does not matter.

  • @sm:@max-md:flex-col
  • @min-md:@max-xl:hidden
  • @md/name:@max-xl/name:

Both variants must resolve to the same container: with names, put the name on each, like @sm/main:@max-md/main:.

Docs: responsive design, container query ranges

Named containers

v4.0

Name a container with @container/sidebar and target it from any descendant with @lg/sidebar:. The element then responds to that specific ancestor instead of the nearest one, which is what you need as soon as containers nest.

  • @container/name
  • @lg/name:
  • @max-md/name:
  • @min-[600px]/name:

A name only works if an ancestor carries the same name. A typo never matches and gives no warning.

Docs: responsive design, named containers

Nested containers

v4.0

Containers can sit inside containers. An unnamed variant like @md: always asks the nearest one; a named variant like @md/page: skips ahead to the ancestor with that name, so one element can react to several containers at once.

  • @container/page
  • @container/card
  • @lg/page:underline
  • @sm/card:font-bold
  • @md: (nearest)

The nearest container answers unnamed variants whether or not it has a name. Name the containers as soon as there are two.

Docs: responsive design, named containers

Arbitrary container sizes

v4.0

For a one-off size that is not in the theme, use @min-[475px]: and @max-[960px]: with any length unit. @[475px]: is shorthand for @min-[475px]:, and every form accepts a /name suffix.

  • @min-[475px]:
  • @max-[960px]:
  • @[600px]:
  • @min-[30rem]/feed:
  • @min-[theme(--breakpoint-md)]:

The value cannot be a CSS variable: @min-(--bp): and @min-[var(--bp)]: generate nothing. Use a literal or theme().

Docs: responsive design, using arbitrary values

The container size scale

v4.0

Thirteen sizes, from @3xs (16rem) to @7xl (80rem), come from the --container-* theme variables. The same variables also drive max-w-*, w-* and columns-*, so one scale sets both layout widths and container variants.

  • --container-3xs … --container-7xl
  • max-w-md
  • columns-xs
  • @min-md:

These are not the viewport breakpoints: @md is 28rem (448px), while md: is 48rem (768px). There is no @8xl unless you add it.

Docs: responsive design, container size reference

Custom container sizes

v4.0

Add a --container-* variable in @theme and you get matching @name:, @min-name: and @max-name: variants, plus max-w-name and friends. Use it for sizes beyond 80rem or for names that describe intent.

  • --container-8xl: 96rem
  • @8xl:
  • @card-wide:
  • @max-compact:
  • --container-*: initial

Hyphenated names such as @card-wide: need v4.1.4 or later. If a --spacing-* name collides with a --container-* name, spacing wins for w-* and max-w-*.

Container query units

core

The CSS units cqw, cqi, cqh, cqb, cqmin and cqmax are 1% of the container's width, inline size, height, block size, smaller side and larger side. Use them as arbitrary values in any utility to scale padding, gaps, sizes and radii with the box.

  • w-[50cqw]
  • p-[4cqi]
  • gap-[3cqi]
  • size-[12cqi]
  • rounded-[2cqi]
  • w-[calc(100cqw-2rem)]

Units follow the nearest container. cqw and cqi work in any @container; cqh, cqb, cqmin and cqmax also need the block size, so use @container-size (below). Without a container they silently fall back to viewport units.

Docs: responsive design, container query units

Fluid type with cqi

core

Wrap a cqi term in clamp() so text scales smoothly with its container, between a minimum and a maximum. Tailwind passes the whole clamp() through as an arbitrary font size.

  • text-[clamp(1rem,7cqi,3rem)]
  • text-[5cqi]
  • leading-[1.1]

Prefer cqi over cqw, since it follows the writing direction. Always clamp: unclamped container units are unreadable in a small box.

@container-size: size containers

v4.3

@container-size sets container-type: size instead of inline-size, so the block size is available too. That unlocks the cqb, cqh, cqmin and cqmax units. @container-size/name names it, like @container/name.

  • @container-size
  • @container-size/poster
  • h-[50cqb]
  • text-[12cqmin]
  • text-[10cqh]

A size container ignores its content when sizing, so give it a height (h-*, an aspect ratio, or a stretching flex or grid parent) or it collapses to zero. Width variants such as @md/poster: still work. Keep plain @container for things that grow with their content.

Height and aspect-ratio container queries

v4.3

Tailwind has no @h-* variants, but a size container can be queried by height or aspect ratio with an arbitrary variant that wraps the at-rule, with underscores for spaces. Use it for panels that show more detail the taller they get.

  • [@container_(height>=16rem)]:
  • [@container_panel_(height>=20rem)]:
  • [@container_(aspect-ratio>1)]:
  • @container-size/panel

The query only works against a size container, never a plain @container. Sizes are measured on the content box. Container size queries are Baseline 2023.

Negated container queries (not-@md:)

v4.0

The not-* variant works with container variants: not-@md:hidden applies when the container is not at least 28rem wide, and not-@sm/side: does the same for a named container. @max-md: is usually the clearer way to write it.

  • not-@md:
  • not-@lg:block
  • not-@sm/side:hidden

not-* shipped in v4.0, but negating a container query was buggy until v4.3.1 fixed it. The pinned v4.3.3 is fine; use 4.3.1 or later.

container is not @container

v4.0

The plain container class is the old fixed-width helper: width: 100% plus a max-width at each viewport breakpoint. It does not query anything. In v4 you customize it with @utility container instead of the v3 center and padding options.

  • container
  • @utility container
  • @container

This page extends container with the override below, so every container here is centered and padded by 1rem. Without it, container does not center itself or add padding.

@container-normal and @container-[…]

v4.0

@container-normal sets container-type: normal, which switches containment off, for example above a viewport breakpoint. @container-[size] sets any container type directly.

  • @container-normal
  • lg:@container-normal
  • @container-[size]
  • @container-[inline-size]/card

Inline-size containment means a container's width can never come from its content, so @container on a shrink-to-fit element (a flex item with no width, w-fit, inline-block) collapses to zero. A container is also an independent formatting context. The last container utility on an element wins.

Container style queries (bonus)

core

Tailwind does not document it, but an arbitrary variant can write a CSS container style query. Set a custom property on a wrapper and any descendant can restyle itself from its value, without a class on each child.

  • [@container_style(--tone:dark)]:
  • [@container_tone_style(--tone:dark)]:
  • [--tone:dark]
  • has-checked:[--tone:dark]

Browser support is narrower than for size queries: style queries on custom properties work in Chromium (111+) and Safari (18+). Firefox support is newer or limited, so check caniuse before relying on it.
