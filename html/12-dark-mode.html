Dark mode & theming

How dark: works in v4 and what to build on top of it: class and attribute strategies, a three-way toggle, dark-mode details like hairlines and gradients, semantic color tokens, multi-palette themes, scheme-*, light-dark() and forced colors. Every demo follows the Theme menu in the top bar; demos with their own switch say so.

dark: follows the OS setting

core

With no setup, dark: compiles to @media (prefers-color-scheme: dark). Write the light design with plain utilities and override only what changes. Variants stack left to right, so dark:md:hover: reads like the CSS.

  • dark:bg-gray-800
  • dark:text-white
  • dark:odd:bg-gray-900/50
  • dark:md:hover:bg-fuchsia-800

On this page dark is redefined to also follow the Theme menu (see the data-attribute card), so the demos react to the menu and to your OS.

Class strategy: @custom-variant dark

v4.0

Override dark in CSS so it follows a .dark class anywhere up the tree instead of the OS setting. This replaces v3's darkMode: 'class' config option. Because it is a class, you can also scope dark to one region, like a dark sidebar in a light app.

  • @custom-variant dark (&:where(.dark, .dark *))
  • <html class="dark">
  • demo-dark:bg-slate-900

This page already defines dark, so the demos use demo-dark with the identical selector. On your own site you would name it dark.

Data-attribute strategy, and this page's variant

v4.0

The same idea with an attribute: @custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *)). A variant can hold several rules. This page's variant combines the attribute with a prefers-color-scheme media rule, so dark: follows the OS until the Theme menu pins light or dark.

  • [data-theme=dark]
  • <html data-theme="dark">
  • demo-attr-dark:bg-slate-900
  • @slot

Light, dark and system toggle

v4.0

The docs recipe is a class-based dark variant (one @custom-variant line in v4, replacing v3's darkMode: 'class') plus a few lines of JS. The script applies dark from localStorage, falls back to matchMedia when nothing is saved, and runs inline in <head> so the first paint is already correct. Choosing System removes the saved key.

  • localStorage.theme
  • matchMedia('(prefers-color-scheme: dark)')
  • classList.toggle('dark', …)
  • <meta name="color-scheme">

The demos below run this logic on cards, not on the page, and save the choice under demo-theme so the Theme menu is left alone. Reload to see it remembered.

Hairlines: borders, dividers, outlines

v4.0

On a dark surface a light gray border looks heavy. Swap it for translucent white, such as dark:border-white/10, which adapts to any dark background. Two v4 defaults matter here: the default border color is currentColor, and a bare outline now sets a 1px width, so always name a color and its dark counterpart.

  • border-gray-200 dark:border-white/10
  • divide-y divide-gray-200 dark:divide-white/10
  • ring-1 ring-gray-900/5 dark:ring-white/10
  • outline outline-black/5 dark:-outline-offset-1 dark:outline-white/10

Inset rings and shadows in dark

v4.0

Black drop shadows disappear on dark surfaces. Replace them with a hairline drawn inside the box: dark:inset-ring dark:inset-ring-white/5. inset-ring and inset-shadow-* are new in v4 and stack with shadow-* and ring.

  • shadow-xl dark:shadow-none
  • ring ring-black/5
  • dark:inset-ring dark:inset-ring-white/5
  • inset-shadow-2xs inset-shadow-white/20
  • forced-colors:border

All of these are box-shadow layers, and browsers turn box-shadow off in forced-colors mode. Add a border fallback for cards whose only edge is a shadow.

Gradients with dark variants

v4.0

In v4 a variant only replaces the stops it names. dark:from-blue-500 keeps your to-* stop, where v3 reset the whole gradient. Use dark:via-none to drop a middle stop in dark. bg-linear-* replaces bg-gradient-to-*.

  • bg-linear-to-b
  • from-sky-100 to-white
  • dark:from-sky-950 dark:to-slate-900
  • dark:via-none
  • bg-clip-text text-transparent

core

Semantic color tokens with @theme inline

v4.0

Name colors by role instead of hue. Keep each theme's raw values in plain CSS variables, then expose them with @theme inline { --color-app-bg: var(--pal-bg); }. bg-app-bg and text-app-ink now compile to var(--pal-bg) and re-skin whenever an ancestor redefines the variable. Opacity modifiers like bg-app-brand/15 work too.

  • @theme inline
  • --color-app-*
  • bg-app-card
  • text-app-muted
  • bg-app-brand/15
  • @theme static

inline is the important word. Without it, Tailwind emits the variable on :root, where your per-theme variable does not exist. @theme static is a different option: it emits every variable even when no utility uses it, and does not change how var() resolves. The names here use a --pal-* prefix because the page chrome already owns --surface, --ink and friends.

Live multi-theme switcher

v4.0

One attribute re-skins a mini app: data-palette="ocean|forest|sunset" on its wrapper. Each palette is a plain CSS rule that sets --pal-* variables (colors, radius, font, shadow) and nests @variant dark for its own dark values. Palette times mode works with no dark: in the markup.

  • data-palette
  • rounded-card
  • font-ui
  • shadow-card
  • bg-app-card
  • @variant dark

Switching is wrapper.dataset.palette = name. Nothing recompiles, because every palette already exists in the CSS. The mode (light or dark) comes from the Theme menu.

Custom theme variants

v4.0

@custom-variant theme-midnight (&:where([data-palette=midnight], [data-palette=midnight] *)) adds theme-midnight:* utilities for tweaks that tokens cannot express: an extra ring, a different icon, neon accents. Define one variant per theme if you like, and stack it like any other (theme-midnight:hover:…).

  • @custom-variant theme-midnight
  • theme-midnight:bg-black
  • theme-midnight:hover:bg-lime-400/10
  • palette-forest:inline-block

Include the bare [data-palette=midnight] in the selector, not only [data-palette=midnight] *. Otherwise the element carrying the attribute never matches (third example).

@variant in your own CSS

v4.0

@variant applies any variant, built-in or custom, inside plain CSS. Nest it in a rule to write the dark value next to the light one. Since v4.3 you can stack variants (@variant dark:hover) and group them (@variant dark, demo-dark) in one block.

  • @variant dark { … }
  • @variant dark:hover { … }
  • @variant dark, demo-dark { … }

The stacked and grouped forms need v4.3 or later. In a Vue, Svelte or CSS-module block, add @reference first so @variant can see your variants.

scheme-*: native controls that match

v4.0

color-scheme tells the browser which scheme to use for the UI it draws itself: form controls, date pickers, select popups, scrollbars and the system colors (Canvas, CanvasText, Field). It never changes your Tailwind colors, so pair it with your dark variant.

light-dark() in arbitrary values

core

The CSS light-dark(light, dark) function works inside any color arbitrary value: bg-[light-dark(white,black)]. It reads the element's computed color-scheme, not the dark variant, so it flips with scheme-* and with this page's Theme menu.

  • bg-[light-dark(white,black)]
  • text-[light-dark(#111,#eee)]
  • border-[light-dark(#e2e8f0,#334155)]
  • stroke-[light-dark(#111,#eee)]
  • supports-[color:light-dark(white,black)]:

Browser support: light-dark() is Baseline 2024 (Chrome and Edge 123, Firefox 120, Safari 17.5). That is newer than Tailwind v4's Chrome and Safari floors (111 and 16.4) but not its Firefox floor (128), so Chrome 111 to 122 and Safari 16.4 to 17.4 are the gap. They drop the whole declaration, so give a plain fallback or guard it with supports-[…]. With the default color-scheme: normal you always get the light value.

light-dark() tokens in @theme inline

v4.0

Put the pair inside the token: --color-ld-surface: light-dark(var(--color-white), var(--color-slate-900)). Then bg-ld-surface, text-ld-ink and border-ld-line adapt on their own, and /50 opacity still works. Flip a subtree with scheme-light or scheme-dark.

  • @theme inline
  • light-dark()
  • --alpha()
  • bg-ld-surface
  • border-ld-line
  • bg-ld-surface/50

It follows color-scheme, not dark. A toggle must change color-scheme (a scheme-dark class), and a lone .dark class will not flip it. Same browser gap as light-dark() above (Chrome 111 to 122, Safari 16.4 to 17.4).

Text shadows that adapt

v4.1

text-shadow-* arrived in v4.1. The launch post uses it for dark legibility: text-gray-950 dark:text-white dark:text-shadow-2xs. Pick the color with text-shadow-sky-300, or change only the opacity with text-shadow-lg/50.

  • text-shadow-2xs
  • dark:text-shadow-2xs
  • text-shadow-xs text-shadow-white
  • dark:text-shadow-black
  • dark:text-shadow-sky-400
  • dark:text-shadow-[0_0_14px_var(--tw-text-shadow-color)]
  • text-shadow-lg/50

Keep it faint: the default sizes run from a 1px edge (2xs) to a soft 8px blur (lg). Forced-colors mode removes text shadows too.

Themed scrollbars

v4.3

v4.3 added scrollbar color utilities. Combine scrollbar-thumb-* and scrollbar-track-* with dark: variants, and add scheme-dark so the rest of the native UI matches.

  • scrollbar-thin
  • scrollbar-thumb-sky-700
  • scrollbar-track-sky-100
  • dark:scrollbar-thumb-sky-400
  • dark:scrollbar-track-gray-700

Browser support: scrollbar-color works in Chrome and Edge 121+ and Firefox 64+, and Safari added it in 26.2, so it sits above Tailwind v4's Chrome and Safari floors (111 and 16.4). Where it is unsupported the scrollbar keeps its default look. Overlay scrollbars (the macOS default, and headless browsers) hide the colors until you scroll.

Respect forced colors

core

Windows High Contrast and other forced-color modes replace your palette with the user's, whatever your theme. Backgrounds, shadows, rings and gradients drop out. Add forced-colors: borders and system colors, use forced-color-adjust-none where color is the content (swatches), and prefer outline-hidden over outline-none so focus stays visible.

  • forced-colors:border
  • forced-colors:border-[CanvasText]
  • forced-colors:outline-[Highlight]
  • forced-color-adjust-none
  • outline-hidden

Emulate it in DevTools: Rendering, "Emulate CSS media feature forced-colors". prefers-color-scheme still reports the user's scheme, so dark: keeps matching, but its colors get overridden. outline-hidden is v4's name for what outline-none did in v3; v4's outline-none removes the outline entirely.
