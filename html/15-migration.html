Upgrading from v3

Everything that changes when you move a v3 project to v4.3.3: the upgrade tool, renamed and removed classes, new defaults, and the shift from a JavaScript config to CSS. Each card shows what changed, why, and the exact before and after, with a live demo wherever a browser can run it.

The upgrade tool

v4.0

A codemod that updates your Tailwind packages, moves tailwind.config.js into CSS, rewrites your stylesheets and renames classes in your templates. Run it on a new git branch with Node.js 20 or higher, then review the diff and click through the app.

  • npx @tailwindcss/upgrade
  • --force -f
  • --config -c
  • Node.js 20+

Docs: upgrade guide

Browser support baseline

v4.0

v4 targets Chrome 111, Safari 16.4 and Firefox 128 because its core features rest on @property, color-mix() and cascade layers. If you must support older browsers, stay on v3.4. The baseline is unchanged through 4.3.3.

  • Chrome 111+
  • Safari 16.4+
  • Firefox 128+
  • @property
  • color-mix()
  • @layer

Docs: compatibility

Build tool packages

v4.0

The PostCSS plugin, the CLI and the Vite plugin each moved into their own package. v4 bundles @import files and adds vendor prefixes itself, so postcss-import and autoprefixer can go. v4.2 added a webpack loader.

  • @tailwindcss/postcss
  • @tailwindcss/vite
  • @tailwindcss/cli
  • @tailwindcss/webpack

Docs: upgrading manually

@tailwind becomes @import

v4.0

One CSS @import "tailwindcss" replaces the three @tailwind directives. Tailwind now uses native cascade layers (theme, base, components, utilities) instead of hijacking @layer.

  • @import "tailwindcss"
  • prefix(tw)
  • important
  • source(none)
  • layer(theme)

Renamed, removed and deprecated utilities

v4.0

v4 renamed a dozen utilities, dropped a few that had been deprecated for years and, in 4.1 and 4.2, deprecated a few more. The tables list every row from the upgrade guide plus the later deprecations. Paste your own v3 classes into the converter to see the v4 names.

  • shadow-xs
  • rounded-xs
  • outline-hidden
  • ring-3
  • bg-linear-to-r
  • /50
  • shrink-*
  • text-ellipsis
  • bg-top-left
  • inset-s-*

Shadow, radius and blur scales

v4.0

Every default scale now has a named smallest step, so the v3 -sm names became -xs and the bare names became -sm. The bare names still compile, so a missed rename changes pixels instead of raising an error.

  • shadow-2xs
  • shadow-xs
  • rounded-xs
  • blur-xs
  • backdrop-blur-xs
  • drop-shadow-xs

Docs: updated scales

Default ring width and color

v4.0

ring used to be a 3px blue ring. In v4 it is a 1px ring in the current text color, matching border and outline. Use ring-3 plus an explicit color to keep the v3 look.

  • ring
  • ring-3
  • ring-blue-500/50
  • --default-ring-width
  • --default-ring-color

Docs: default ring width and color

outline-none becomes outline-hidden

v4.0

v3's outline-none kept an invisible outline so forced-colors mode still showed focus. That behavior is now outline-hidden, and v4's outline-none really sets outline-style: none. Also, outline is 1px wide and outline-2 implies a solid style.

  • focus:outline-hidden
  • outline-none
  • outline
  • outline-2
  • focus-visible:ring-3

Docs: renamed outline utility

bg-gradient-to-* becomes bg-linear-to-*

v4.0

Linear gradients are now bg-linear-*, which also takes angles and an interpolation modifier. bg-radial and bg-conic join them. The old bg-gradient-to-* names still compile, and the upgrade tool rewrites them.

  • bg-linear-to-r
  • bg-linear-45
  • bg-linear-to-r/srgb
  • bg-radial
  • bg-conic

Docs: background image

Opacity utilities removed

v4.0

bg-opacity-*, text-opacity-*, border-opacity-*, divide-opacity-*, ring-opacity-* and placeholder-opacity-* are gone. Put the opacity on the color with a /50 modifier. These are the only renames that fail silently by generating nothing.

  • bg-black/50
  • text-black/50
  • bg-black/[0.35]
  • bg-indigo-600/(--a)

Docs: removed deprecated utilities

Default border color is currentColor

v4.0

border and divide no longer default to gray-200. They follow the text color, like the browser does. Name a color wherever you rely on the old default, or add a base layer that restores it.

  • border
  • border-gray-200
  • divide-y
  • divide-gray-200
  • @layer base

Docs: default border color

New default placeholder color

v4.0

Placeholders now use the current text color at 50% opacity instead of gray-400. It is often an improvement, but you can restore the old look with placeholder:text-gray-400 or a base rule.

  • placeholder:text-gray-400
  • placeholder:italic
  • ::placeholder

Docs: new default placeholder color

Buttons use the default cursor

v4.0

Preflight no longer sets cursor: pointer on buttons, matching the browser. Add cursor-pointer to the buttons that should have it, or restore the old rule once in a base layer.

  • cursor-pointer
  • disabled:cursor-not-allowed
  • @layer base

Docs: buttons use the default cursor

hover: only on hover-capable devices

v4.0

The hover variant now compiles inside @media (hover: hover), so a tap on a phone no longer triggers it. Treat hover as an enhancement. If you depend on tap-to-hover, redefine the variant with @custom-variant hover (&:hover).

  • hover:
  • @custom-variant hover
  • pointer-coarse:
  • group-hover:

Docs: hover styles on mobile

space-* and divide-* selectors

v4.0

The selector changed from > :not([hidden]) ~ :not([hidden]) to > :not(:last-child) to fix a performance problem on large pages. Hidden last children and inline items now behave differently. When in doubt, use flex and gap.

  • space-y-4
  • space-x-2
  • divide-y
  • flex flex-col gap-4

Docs: space-between selector

Variants keep gradient stops

v4.0

In v3, overriding one stop in a variant reset the others to transparent. In v4 the other stops stay. Use via-none when you want to drop a middle stop in one state.

  • from-*
  • via-*
  • to-*
  • via-none
  • dark:from-blue-500

Docs: using variants with gradients

The important modifier goes last

v4.0

Write flex!, not !flex. The old leading form still works but is deprecated. To mark every utility important, import Tailwind with the important flag.

  • flex!
  • bg-red-500!
  • hover:bg-red-600/50!
  • @import "tailwindcss" important

Docs: the important modifier

CSS variables in arbitrary values

v4.0

Reference a variable with parentheses: bg-(--brand). Recent CSS additions made the v3 square-bracket form bg-[--brand] ambiguous, so it now emits an invalid declaration. In grid and object-position values, commas are no longer turned into spaces, so write underscores.

  • bg-(--brand)
  • w-(--sidebar-w)
  • text-(length:--fs)
  • grid-cols-[max-content_auto]

Docs: variables in arbitrary values

Variant stacking order

v4.0

Stacked variants now apply left to right, like CSS reads. Reverse any order-sensitive stack. In practice that means the child variants (* and **) and plugin variants such as prose-headings when you stack them with others.

  • *:first:pt-0
  • *:last:pb-0
  • *:hover:bg-*
  • dark:md:hover:

Docs: variant stacking order

@layer utilities becomes @utility

v4.0

v3 treated any class inside @layer utilities or @layer components as a real utility. v4 uses native cascade layers instead, so custom classes need @utility to work with variants. Custom utilities are also sorted by how many properties they set, so a one-property Tailwind utility can override a component class.

  • @utility
  • @utility btn
  • @utility glow-*
  • --value()
  • @variant md

Docs: adding custom utilities

theme() becomes var()

v4.0

Every theme value is a CSS variable now, so write var(--color-red-500). theme() still works but is deprecated and inlines the value. Where variables are not allowed, such as media queries, use theme(--breakpoint-xl). --alpha() and --spacing() cover the other common uses.

  • var(--color-red-500)
  • theme(--breakpoint-xl)
  • --alpha()
  • --spacing()
  • --theme()

Docs: using the theme() function

darkMode becomes @custom-variant dark

v4.0

The JavaScript darkMode option is now a CSS custom variant. The default follows prefers-color-scheme. To toggle with a class or a data attribute, redefine dark with the selector you want.

  • @custom-variant dark
  • .dark
  • [data-theme=dark]
  • dark:

Docs: toggling dark mode manually

Container customization

v4.0

The v3 container config options center and padding no longer exist. Extend the container utility with @utility instead. Your declarations merge with the built-in per-breakpoint max-width rules.

  • container
  • @utility container
  • margin-inline: auto
  • theme(--breakpoint-sm)

Docs: container configuration

transition now animates outline color

v4.0

transition and transition-colors include outline-color. If the outline color is set only in the hover or focus state, it fades in from currentColor. Set the color unconditionally, or in both states.

  • transition
  • transition-colors
  • outline-cyan-500
  • hover:outline-2

Docs: transitioning outline-color

Individual transform properties

v4.0

rotate-*, scale-* and translate-* now set the individual CSS properties rotate, scale and translate. That means transform-none no longer resets them, and a custom transition list that names transform no longer animates them.

  • scale-none
  • rotate-none
  • translate-none
  • transition-[opacity,scale]
  • transition-transform

Docs: individual transform properties

The hidden attribute wins

v4.0

Elements with the HTML hidden attribute stay display: none even if a utility like flex is also present, so remove the attribute to show the element. The exception is hidden="until-found". The hidden utility class is unaffected.

  • hidden attribute
  • hidden="until-found"
  • el.hidden = false

Docs: hidden attribute takes priority

Dialog margins removed

v4.0

Preflight now resets margins on <dialog> like every other element, so a modal dialog sits in the top-left corner until you give it m-auto. For a side drawer, push it with ml-auto.

  • m-auto
  • ml-auto
  • backdrop:bg-slate-900/50
  • max-h-none

Docs: dialog margins removed

Legacy aliases: grow, shrink, ellipsis

v4.0

The upgrade guide lists these v3 names as removed: flex-shrink-*, flex-grow-*, overflow-ellipsis, decoration-slice and decoration-clone. They are undocumented but still compile in 4.3.3, so nothing breaks yet. Rename them to shrink-*, grow-*, text-ellipsis and box-decoration-*.

  • shrink-0
  • grow
  • text-ellipsis
  • box-decoration-clone
  • box-decoration-slice
  • wrap-break-word

Deprecated corner positions

v4.1

In v4.1, the corner names for bg-* and object-* became vertical-first, matching how CSS reads: bg-top-left instead of bg-left-top. The old names still compile.

  • bg-top-left
  • bg-bottom-right
  • object-top-left
  • object-bottom-right

Docs: background position

start-* and end-* deprecated

v4.2

v4.2 added inset-s-*, inset-e-*, inset-bs-* and inset-be-*, a consistent logical-inset family, and deprecated start-* and end-*. The old names still work in 4.3.3.

  • inset-s-4
  • inset-e-4
  • -inset-s-2
  • inset-bs-0
  • inset-be-0

Docs: logical properties

JS config, @theme and resolveConfig

v4.0

A tailwind.config.js is no longer picked up automatically. Load it with @config while you migrate, then move values into @theme. resolveConfig is gone: read the generated CSS variables, for example with getComputedStyle.

  • @config
  • @plugin
  • @theme
  • @theme static
  • getComputedStyle

Docs: using a JavaScript config file

Removed config options

v4.0

corePlugins, separator and safelist from the JS config are not supported in v4, and content is replaced by automatic source detection plus @source. Most other options moved into CSS.

  • corePlugins
  • separator
  • safelist
  • content
  • @source

Docs: disabling core plugins

safelist becomes @source inline()

v4.1

Force classes into the output even when no file mentions them, using @source inline(). It supports brace expansion for variants and ranges. @source not inline() does the reverse.

  • @source inline("underline")
  • {hover:,focus:,}
  • bg-red-{50,{100..900..100},950}
  • @source not inline()

Docs: safelisting specific utilities

Prefix syntax tw:

v4.0

A prefix now looks like a variant and sits at the start of every class: tw:flex, not tw-flex. Declare theme variables without the prefix. The generated CSS variables get it, so they never collide with yours.

  • prefix(tw)
  • tw:flex
  • tw:hover:bg-red-600
  • tw:bg-red-500!
  • --tw-color-brand

Docs: using a prefix

Sass, Less, Stylus and @reference

v4.0

Tailwind is not designed to run with CSS preprocessors. It already does nesting, imports and vendor prefixing. Stylesheets bundled separately, such as CSS modules or Vue and Svelte <style> blocks, need @reference to use @apply or theme variables.

  • @reference
  • @apply
  • var(--color-red-500)
  • CSS nesting
