Page 03 · Foundations

Directives & functions

The at-rules and build-time functions that extend Tailwind from your own CSS: custom utilities and variants, @apply, @variant, and --alpha(), --spacing() and --theme(). Whatever the in-browser build can compile runs live on this page; directives that need a build step are shown as code, and @theme has its own page (Theme variables).

Simple @utility

v4.0

Register a one-class utility with @utility and it behaves like a built-in: it lands in the utilities layer, works with every variant (hover:, md:, dark:, group-hover:) and needs no extra config. Use it for a CSS feature Tailwind has no class for. Utilities with more declarations sort first, so a plain px-8 or rounded-none still overrides them.

  • @utility glass { … }
  • hover:glass
  • md:bg-checker
  • content-auto

Docs: simple utilities

This one has no visible effect: content-visibility: auto lets the browser skip layout and paint for rows that are scrolled out of view, and contain-intrinsic-size reserves their height so the scrollbar stays stable. It needs Chrome or Edge 85+, Firefox 125+ or Safari 18+. backdrop-filter (first example) is unprefixed in Chrome 76+, Firefox 103+ and Safari 18+.

@utility with nested selectors

v4.0

Inside @utility you can nest &::after, &:hover, & > * + * or an @media block. The whole block is one class, so tooltips, animated underlines and hidden WebKit scrollbars ship as a single utility that still accepts variants.

  • &::after
  • &:hover::after
  • & > * + *
  • scrollbar-hidden
  • motion-safe:link-underline

Docs: complex utilities

scrollbar-width: none covers Firefox and current Chromium; the nested ::-webkit-scrollbar rule covers older WebKit. Since v4.3 Tailwind also ships built-in scrollbar-none and scrollbar-thin (see page 14), but only this nested form also removes the WebKit pseudo-element. Classic scrollbars are only visible on systems that use them; overlay-scrollbar systems such as macOS hide both rows' bars until you scroll.

The browser build on this page emits your nested CSS as written (native CSS nesting: Chrome 120+, Safari 17.2+, Firefox 117+). A compiled build flattens it for the v4 baseline of Chrome 111, Safari 16.4 and Firefox 128.

@apply in custom CSS

core

@apply inlines utility classes, including variants, into your own selectors. Use it for CSS you cannot put classes on, such as a third-party widget or CMS markup. In v4 it can only apply classes Tailwind generates: built-in utilities, @utility rules and custom variants.

  • @apply px-3 py-2
  • @apply hover:bg-sky-50
  • @apply dark:bg-slate-800
  • @apply border-0!

Docs: @apply

The ! goes at the end of the class (border-0!) and compiles to !important, which is how you beat a vendor rule that has the same specificity as yours.

Code-only: an @apply error makes the whole stylesheet fail to compile, which would blank every demo on this page. In Vue, Svelte and CSS-module <style> blocks you also need @reference first (see below). Since v4.3.1 @apply also accepts CSS mixins.

@layer components vs @utility

v4.0

In v3 a class inside @layer utilities became a real utility. In v4 Tailwind uses native cascade layers, so only @utility gets variants (hover:, md:) and works with @apply. A class in @layer components is plain CSS that utilities can still override.

  • @layer components
  • @utility btn-util
  • hover:btn-util
  • md:btn-util

Docs: upgrade guide, adding custom utilities

The first chip is deliberately broken: hover:btn-layer is not a class Tailwind can generate, so it produces no CSS. Tailwind silently ignores a class it cannot generate, and that is the lesson.

Utilities win over @layer components because the layer order is theme, base, components, utilities. Among @utility rules, the one that declares more properties is emitted first, so single-property classes like px-8 still override it.

Code-only: a diff to copy, not something to run. Note that tab-* and zoom-* became built-in utilities in v4.3, so tab-4 now exists without any CSS.

@variant in custom CSS

v4.0

Use @variant inside your own rules to apply any Tailwind variant (dark, md, hover, group-hover, aria-invalid and so on) without writing the media query or selector yourself. It compiles to native nested CSS.

  • @variant dark { … }
  • @variant md { … }
  • @variant group-hover { … }
  • @variant aria-invalid { … }

Docs: using variants

The output is native nested CSS: @variant dark becomes a nested @media (prefers-color-scheme: dark) (on this page, the hybrid selector defined at the top). The in-browser build ships it as written (Chrome 120+, Safari 17.2+, Firefox 117+); a compiled build flattens it. Put @variant inside a rule, as above: a top-level @variant dark { :root { … } } breaks with a selector-based dark variant like this page's. In a Vue or Svelte <style> block you need @reference first.

Stacked and compound @variant

v4.3

Since v4.3, @variant takes stacked variants separated by colons (hover:focus, applied left to right like in HTML, so both must match) and compound lists separated by commas (hover, focus-visible, either may match) that share one block of CSS.

  • @variant hover:focus { … }
  • @variant hover, focus-visible { … }
  • @variant dark:hover { … }
  • @variant aria-[current=page]

Docs: using variants · v4.3 release post

Hover it with the mouse, then click it and keep the pointer over it: the outline ring needs both states. In dark mode the hover colour is lighter (dark:hover), and from the md breakpoint up it lifts by 1px (md:hover). Hover rules are wrapped in @media (hover: hover), so touch screens never get a stuck hover.

Hover a row, or press Tab to move focus into it: both reveal the buttons. The docs point out that a component styled with utilities is usually better than this; reach for it when plain CSS is the right tool. Requires v4.3: older versions reject the stacked and compound forms.

@custom-variant shorthand

v4.0

Define a variant in one line with @custom-variant name (selector-or-at-rule);, where & stands for the element carrying the utility. Selectors, @media, @container and @supports all work, and the variant stacks with the built-in ones in either order (md:hocus:underline).

  • hocus:
  • loading:
  • theme-midnight:
  • narrow-card:

Docs: adding custom variants

Container queries need Chrome 105+, Safari 16+ or Firefox 110+. Touch screens cannot drag the resize handle, but a narrow phone already puts the card below 24rem. Redefining a built-in name overrides it: @custom-variant hover (&:hover); restores the pre-v4 tap-to-hover behaviour, and this page's own dark variant is defined the same way (see the next card). Names may use letters, digits, dashes and underscores.

@custom-variant block form with @slot

v4.0

When a variant needs nesting, write a block and put @slot where the utility's declarations should land. That lets you wrap them in @media or @supports, use ancestor selectors, or emit several rules that each receive the utility.

  • @custom-variant name { … }
  • @slot
  • any-hover:
  • group-hocus:
  • sidebar-open:

Docs: adding custom variants

Plain hover: only applies when the primary pointer can hover (@media (hover: hover)). any-hover checks every pointer, so a touch laptop with a trackpad still gets the highlight.

The first rule pins dark when the Theme menu says so; the second follows the operating system unless the menu pins light. Multiple rules in one block each receive the utility. For an at-rule-only variant you can skip the &, as in @custom-variant supports-grid { @supports (display: grid) { @slot; } }.

@variant inside @custom-variant

v4.1

Build a custom variant from other variants by nesting @variant in its block. The result inherits their behaviour, for example hover staying wrapped in @media (hover: hover). Handling landed in v4.1.14; use v4.2 or later to avoid an infinite-loop bug.

  • @variant hover { @slot; }
  • @variant max-md { … }
  • hocus-nested:
  • nav-open:

Changelog: 4.1.14

On a mouse they look the same. On a touch screen hocus can leave a tapped button stuck in its hover colour, while hocus-nested only applies the hover half when the device can really hover. Tab to either button to see the focus-visible half.

Code-only because it is compiler output. The selector-only hocus from the shorthand card would compile to a single :is(:hover, :focus-visible) rule with no media query.

Functional utilities from theme keys

v4.0

End a utility name with -* and read its value with --value(). --value(--glow-*) turns every --glow-xxx variable in @theme into a class, so --glow-sm becomes glow-sm. Unknown keys generate nothing, and unused variables are not emitted.

  • @utility glow-* { … }
  • --value(--glow-*)
  • hover:glow-lg
  • shape-blob

Docs: matching theme values

Shadows are hard to see on a dark stage, so these cards also carry a border. Tailwind only writes the theme variables that something uses: --glow-lg is emitted because hover:glow-lg appears in the markup. Use @theme static to force them. Nested theme keys also resolve, for example --value(--text-*--line-height).

Bare values: --value(integer)

v4.0

Put a data type in --value() to accept a bare value right after the dash: stagger-3, hue-shift-90, progress-75%. The bare types are integer, number, percentage and ratio; anything else needs the arbitrary […] form.

  • --value(integer)
  • --value(number)
  • --value(percentage)
  • stagger-3
  • hue-shift-12.5

Docs: bare values

--value(integer) returns the raw digits, so wrap it: calc(--value(integer) * 80ms). Write rise-in with longhand animation properties: with the animation shorthand, motion-safe:rise-in is emitted after stagger-3 and would silently reset the delay to 0s. The motion-safe: prefix leaves the list static for people who prefer reduced motion.

number accepts decimals such as 12.5, integer rejects them. progress-75% works because % is a legal class character; progress-[75%] would need --value([percentage]) as well.

Arbitrary values: --value([length])

v4.0

Wrap a data type in square brackets, --value([angle]), to accept arbitrary values such as sweep-[270deg]. The types are absolute-size, angle, bg-size, color, family-name, generic-name, image, integer, length, line-width, number, percentage, position, ratio, relative-size, url, vector and * (anything).

  • --value([angle])
  • --value(--color-*, [color])
  • --value([*])
  • sweep-[270deg]

Docs: arbitrary values

Conic-gradient stops are not animatable, so the hover snaps instead of transitioning.

Underscores become spaces inside […]. The font needs real wght and opsz axes: Bricolage Grotesque, loaded by this page from Google Fonts, has both. If the font cannot load, the heading falls back to a system font and the hover does nothing visible.

A value that does not match the declared type is dropped silently: --value([length]) does not accept percentages, so list [percentage] too when you need both.

Several --value() fallbacks

v4.0

One --value() can list several resolvers (theme key, bare value, arbitrary value) that are tried left to right. Or write several declarations of the same property, each with its own --value(): declarations that cannot resolve are dropped, so each input form can map to a different CSS expression.

  • --value(--container-*, [length])
  • calc(--value(integer) * 1ch)
  • measure-65
  • measure-md
  • measure-[24rem]

Docs: supporting theme, bare and arbitrary values together

For measure-65 the first max-width resolves and the second is dropped; for measure-md it is the other way round. At least one --value() in the utility must resolve, or the whole class is invalid.

autofit-xs asks for columns of at least 20rem (--container-xs), autofit-[9rem] for 9rem. Resize the window to watch the column count change without a single breakpoint class.

--modifier() for the /modifier part

v4.0

The text after the slash (type-xl/tight, aura-sky-500/40) is read with --modifier(), which takes the same arguments as --value(). If the class has no modifier, every declaration that depends on --modifier() is left out.

  • --modifier(integer)
  • --modifier(--leading-*, [length])
  • type-3xl/tight
  • aura-sky-500/40
  • pad-6/2

Docs: modifiers

--alpha(color / --modifier(integer)) would emit an invalid color-mix() percentage, so convert the bare number first: calc(--modifier(integer) * 1%). A modifier that no --modifier() understands (type-xl/foo) makes the class invalid.

The last chip has no modifier, so only the inline padding is set. A utility that uses --value(ratio) cannot also read a modifier, because the slash is consumed as part of the ratio.

Negative utilities: @utility -name-*

v4.0

A leading dash in the @utility name registers the negative form. Tailwind does not derive it from the positive one, so declare both, using --spacing(--value(integer) * -1) or calc(--value([length]) * -1). Variants still go before the dash: hover:-shift-x-2.

  • @utility shift-x-* { … }
  • @utility -shift-x-* { … }
  • -shift-x-[85%]
  • group-hover:-shift-x-2

Docs: negative values

The percentage resolves against the drawer's own width, so 85% of 12rem hides all but a sliver. Tab into the button to open it from the keyboard (focus-within:shift-x-0). The spacing form (shift-x-3) and the arbitrary form (-shift-x-[85%]) come from the same two declarations.

Negative utilities stack with structural variants too. The shift utilities use the individual translate property, so they combine with rotate-* and scale-* without clashing.

Fractions and ratios: --value(ratio)

v4.0

Putting ratio in --value() tells Tailwind to treat the value and the modifier as one fraction, so frame-4/5 and frame-[7/9] work, and theme keys can add named ratios such as frame-video. Both sides must be integers.

  • --value(--frame-*, ratio, [ratio])
  • frame-4/5
  • frame-video
  • frame-[7/9]

Docs: fractions

Pick a different root than aspect-*: the built-in aspect-* is its own utility and already accepts fractions. Fractions like 1.5/1 are rejected in custom utilities, and --value(ratio) cannot be combined with --modifier() in the same class.

Literal values: --value('auto')

v4.0

Quote words inside --value() to accept exact keywords. Each quoted literal becomes a class suffix and is emitted as written, which suits keyword properties and mapping a suffix to a @keyframes name. Literals arrived in v4.0.16, after the first v4.0 release.

  • --value('fade-in', 'slide-up')
  • reveal-slide-up
  • writing-vertical-rl
  • last-line-center

Docs: literal values

A word that is not in the list (reveal-spin) generates nothing. Define the @keyframes at the top level of the stylesheet: keyframes inside @theme are only emitted when a theme animation variable uses them. motion-safe: keeps the toasts static for people who prefer reduced motion.

Both paragraphs are justified; only the second centres its final line. Single and double quotes both work around the literals.

--default() in --value() and --modifier()

v4.3

New in v4.3: pass --default(x) to --value() or --modifier() so the bare utility name works with no value (lift) and no modifier (enter-4 versus enter-4/3). The default can be any single CSS token such as 4, auto or 9999px.

  • --value(integer, --default(1))
  • --modifier(integer, --default(0))
  • hover:lift
  • enter/6
  • avatar-12/lg

Docs: default values · v4.3 release post

Gotcha in v4.3.3: a default with more than one token loses its spaces. --default(1px solid) compiles to 1pxsolid, so keep the spaces outside, as in rule-* above. The fix, "Preserve whitespace in --default(…)", is only in the changelog's Unreleased section, so treat it as upcoming. The built-in tab-* and zoom-* utilities already use these names since v4.3, so the docs' tab example name is taken. A functional @utility needs at least one --value() or it generates nothing.

Same utility defined more than once

v4.3

Since v4.3 you can write several @utility rules with the same functional name but different value types, for example one for theme keys and one for arbitrary values, and they merge instead of clashing. Duplicate static names merge their declarations into one rule.

  • @utility elev-* { … } twice
  • elev-2
  • elev-[0_4px_12px_red]
  • @utility chip-base twice

Changelog: 4.3.0

Each definition resolves the values it understands, so a design-system package and an app can each add a branch to the same utility name. A static name such as chip-base simply merges the declarations.

Code-only because it is compiler output. The theme-key definition matches elev-2 and the [*] definition matches the bracketed value.

--alpha(): adjust colour opacity

v4.0

--alpha(color / 50%) mixes any colour (a theme variable, a literal, currentColor) with transparent and compiles to color-mix(). It works in custom CSS, inside @utility and in arbitrary values. The syntax is a slash; the old comma form was replaced during the v4 betas.

  • --alpha(var(--color-lime-300) / 50%)
  • --alpha(currentColor / 25%)
  • bg-[--alpha(var(--color-sky-500)/15%)]

Docs: --alpha()

Code-only because it is compiler output. The docs show only the color-mix(in oklab, …) line; 4.3.3 also emits an sRGB fallback ahead of an @supports guard so engines without color-mix() degrade gracefully. color-mix() itself is baseline since 2023 (Chrome 111, Safari 16.2, Firefox 113).

--spacing(): theme-based spacing

v4.0

--spacing(4) compiles to calc(var(--spacing) * 4), so custom CSS and arbitrary values stay on the spacing scale and follow a redefined --spacing. It takes exactly one argument. --spacing(1) simplifies to var(--spacing) and --spacing(0) to 0px.

  • --spacing(4)
  • py-[calc(--spacing(4)-1px)]
  • top-[--spacing(14)]
  • --spacing(--value(integer))

Docs: --spacing()

The buttons redefine --spacing on the demo box only. Every gap and padding in .rhythm was written as --spacing(n), so the whole card rescales without touching its CSS. The default is 0.25rem.

The 1px border adds to the outline button's height, so shaving 1px from the vertical padding makes both buttons the same size. The arbitrary value compiles to calc(calc(var(--spacing) * 4) - 1px).

Code-only because it is compiler output. Zero stays a length (0px) so it still works inside calc().

--theme(): read theme variables

v4.0

--theme(--color-red-500) returns the theme value as var(--color-red-500). Inside at-rule parameters such as @media, @container and @supports, where CSS variables are invalid, it inlines the real value: @media (width >= --theme(--breakpoint-md)) becomes 48rem. Add inline to force the literal anywhere.

  • --theme(--color-red-500)
  • --theme(--breakpoint-md)
  • --theme(--font-brand, Georgia, serif)
  • --theme(--color-red-500 inline)
  • min-[--theme(--breakpoint-md)]:flex

Docs: upgrade guide, theme() function

A media query cannot contain var(--breakpoint-md), which is why --theme() inlines the value here. If you redefine --breakpoint-md in @theme, this rule moves with it. Media queries react to the window, not to the demo box.

Without a fallback, a missing variable throws a compile error. --theme() only accepts names that start with --; the dot-notation theme() is covered in the next card. The in-browser build resolves these at compile time, in the page, so no browser-support concerns apply.

Legacy theme() (deprecated)

core

The v3 dot-notation function, theme(spacing.12), still works for compatibility, but the docs call it deprecated and recommend CSS variables instead. In media queries use the variable name: theme(--breakpoint-xl), or better, --theme(--breakpoint-xl).

  • theme(spacing.12)
  • theme(colors.red.500)
  • theme(--breakpoint-xl)
  • theme(screens.lg)

Docs: theme() function

All three compile to @media (width >= 64rem). The first is the v3 spelling and still resolves; the second is what the upgrade guide recommends if you keep theme(); the third is the v4 function. Resize the window across 64rem to watch the chips change together. theme(--spacing inline) is not supported by the legacy function in 4.3.3; use --theme(--spacing inline).

The upgrade tool rewrites many of these for you. Prefer var(--color-*) in plain declarations: it is a runtime variable, so it also follows theme overrides on a wrapper element.

@reference for Vue, Svelte and CSS modules

v4.0

@reference imports your main stylesheet for lookups only (theme variables, @utility, @custom-variant) without re-emitting any of its CSS. That makes @apply and @variant work inside component <style> blocks and *.module.css files, where the main file is not visible.

  • @reference "../../app.css";
  • @reference "tailwindcss";
  • @reference "#app.css";

Docs: @reference

Code-only: this page has one stylesheet, so there is nothing to reference, and the build step that resolves @reference paths does not exist in the browser. The preview applies the same three utilities directly; the HTML listing above is that markup, not the Vue file. Without the directive, @apply fails with Cannot apply unknown utility class.

Code-only: needs a bundler that processes CSS modules. The React app in this repo follows the same convention; every file in react/src/demos/*.css starts with @reference "../index.css";.

Code-only. @import, @reference, @plugin and @config all accept subpath imports when you use the CLI, Vite or PostCSS. A compiled @reference file emits only its own rules, with theme values as fallbacks, and none of the main stylesheet's CSS. Since v4.1.6 @reference no longer scans files for classes.

@config: load a legacy JavaScript config

v4.0

tailwind.config.js is no longer picked up automatically in v4. Load it explicitly with @config "./tailwind.config.js". Its theme.extend values merge with your CSS, and CSS-first features such as @theme take precedence, so you can migrate step by step.

  • @config "./tailwind.config.js";
  • @config "#tw-config";

Docs: @config

Code-only: the browser build cannot read files. @config and @plugin throw "The browser build does not support plugins or config files" and discard the whole stylesheet, which would blank every demo here. The swatch uses the equivalent @theme variable, which is what the config entry turns into: colors.legacy becomes --color-legacy and a bg-legacy utility.

Things defined in CSS are merged where possible and otherwise take precedence over the config, presets and plugins. Move one block at a time, and delete the config when it is empty.

corePlugins, safelist and separator do not work with @config in v4. Leave out preflight.css to drop the reset, use @source inline() for the safelist, and note that variants now always use :.

@plugin: load JavaScript plugins from CSS

v4.0

@plugin "@tailwindcss/typography" registers a v3-style JavaScript plugin, from npm or a local path, straight from your CSS. It can be combined with @theme, @utility and the other CSS features. The React app in this repo runs typography and forms for real in react/src/index.css; the browser build cannot.

  • @plugin "@tailwindcss/typography";
  • @plugin "@tailwindcss/forms";
  • @plugin "./plugins/halo.js";

Docs: @plugin

Code-only: the browser build throws "The browser build does not support plugins or config files" and drops the whole stylesheet. The preview above approximates what prose automates using arbitrary variants ([&_a]:underline); the real plugin covers far more elements. Open the React app at react/ to see it for real.

Code-only. The plugin resets form controls so they take your border, ring and colour utilities. By default it restyles every form element; the next card shows the strategy: "class" option that limits it to form-* classes.

For a one-off utility like this, @utility is simpler and needs no JavaScript. Reach for @plugin when you adopt a third-party plugin or need its JavaScript API (matchUtilities, addBase, theme()). With @tailwindcss/vite, @plugin resolves the package's JavaScript entry (a v4.3.0 fix).

@plugin options block

v4.0

Give @plugin a block of key: value; lines and they become the plugin's options object. @tailwindcss/forms takes strategy ("base" or "class"); @tailwindcss/typography takes className and target. The option names come from each plugin's own README.

  • @plugin "…" { strategy: "class"; }
  • className: wysiwyg;
  • target: legacy;

Docs: @plugin

Code-only: compiled with the CLI against tailwindcss 4.3.3 and forms 0.5.11, this setup emits only the .form-* classes and no global element styles, so plain inputs stay native. The React app in this repo uses exactly this block in react/src/index.css. The browser build cannot load plugins.

Code-only: with typography 0.5.20 the option generates .wysiwyg and .wysiwyg-lg and no .prose. target: legacy switches to the older selector format ("modern" is the default).

Code-only: needs Node to load the plugin file. The values in the block reach plugin.withOptions as the options argument. For something this small, an @utility rule needs no plugin at all.

@source: register extra files to scan

v4.0

@source adds paths that Tailwind's automatic content detection misses, such as a UI kit in node_modules or a sibling package. Paths are relative to the stylesheet. source("../src") on the import sets the base path, and source(none) turns detection off.

  • @source "../node_modules/@acmecorp/ui-lib";
  • source("../src")
  • source(none)

Docs: @source · Detecting classes

Code-only: the browser build has no files to scan. It compiles the classes it finds in the live page, and silently ignores @source, so there is no visible effect to show. In a real build, dependencies are skipped by default (they are usually in .gitignore, and since v4.1 node_modules is ignored outright), so a library built with Tailwind needs this line.

Code-only. source(none) disables automatic detection so each stylesheet only includes the classes of the folders you list. Handy when several Tailwind stylesheets live in one repo.

Code-only. Tailwind scans from the current working directory by default, so source("../src") matters when builds run from the repo root. The React app in this repo uses @source not (next card) so the class names quoted in its README do not generate CSS.

@source not and @source inline()

v4.1

@source not "path" excludes a path from scanning. @source inline("…") force-generates classes that never appear in your files, a safelist with brace expansion such as {hover:,focus:,}underline and ranges like bg-red-{50,{100..900..100},950}. @source not inline() blocks classes.

  • @source not "../legacy";
  • @source inline("underline");
  • @source inline("{hover:,}bg-red-{50,{100..900..100},950}");
  • @source not inline("…");

Docs: safelisting specific utilities

This works here only because the in-browser build compiles whichever classes appear in the live page, so it needs no safelist. A real build scans your files for whole class names; 'bg-' + color + '-600' never appears as one, so those utilities would not be generated without the @source inline() line. Pick a colour to see Tailwind compile the new class on the fly.

Try {hover:,}underline, p-{1..4} or m-{2,4,6}. A list is {a,b,c}; a numeric range is {start..end..step}; empty items are allowed, which is how {hover:,focus:,} includes the plain class. The demo ports Tailwind's own expansion algorithm, but only the real engine decides which of the expanded names are valid classes.

Code-only: the browser build ignores @source directives. @source inline() replaces the v3 safelist option, which @config no longer supports. Since v4.2 whitespace around the inline() argument is allowed, and later @source rules can re-include files excluded by an earlier @source not (v4.3.1).

@import "tailwindcss" and its options

v4.0

One @import "tailwindcss" replaces the three v3 @tailwind directives. It accepts source(), prefix(), theme() and layer() options, so you can set the scanning base, add a tw: prefix, or import theme, preflight and utilities separately.

  • @import "tailwindcss";
  • prefix(tw)
  • source("../src")
  • theme(static)
  • layer(base)

Docs: @import

Code-only, and this one has a trap. @tailwindcss/browser injects @import "tailwindcss" for you, but only if none of the page's text/tailwindcss CSS contains the text @import. Even a comment containing it switches the injection off and no utilities are generated, so this page never writes it inside a live style block.

Code-only: prefix() is an import option, and the browser build cannot change how it imports Tailwind. The prefix stops Tailwind classes clashing with an older stylesheet; the generated theme variables get the prefix too (--tw-color-avocado-500).

Code-only. This is what @import "tailwindcss" expands to, and the way to put Preflight in a different layer or leave it out. source(), theme() and prefix() go on the import they apply to. theme(static) emits every theme variable whether or not a class uses it.
