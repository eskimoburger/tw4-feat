Page 05 · Variants

Selector variants

Variants that style an element from the state of the DOM around it: its parents, siblings, children and own attributes. This page covers group, peer, has-*, not-*, in-*, nth-*, *: and **:, plus the data-*, aria-* and supports-* variants, the pseudo-element variants and arbitrary variants. Form-state, open: and media variants are on page 06, and @custom-variant is on page 03.

group and group-*

core

Put group on a parent, then prefix any state variant with group- on its descendants. The children react when the parent is hovered, focused, open, odd, empty and so on. Use it when one hover or focus area should restyle several inner elements at once.

  • group
  • group-hover:*
  • group-focus-within:*
  • group-focus-visible:*
  • group-active:*
  • group-odd:*
  • group-first:*
  • group-only:*
  • group-empty:*

Docs: styling based on parent state

peer and peer-*

core

Put peer on an element and use peer-* variants on the siblings that come after it. They react to the peer's state: checked, invalid, focused, placeholder shown, disabled. It is the CSS-only way to build switches, floating labels and inline validation.

  • peer
  • peer-checked:*
  • peer-invalid:*
  • peer-focus:*
  • peer-focus-visible:*
  • peer-placeholder-shown:*
  • peer-disabled:*

Docs: styling based on sibling state

Named groups and peers

core

Add a name with a slash: group/item, peer/email. Then target it with group-hover/item: or peer-invalid/email:. Names are what let nested groups, or several peers in one form, react independently. They need no configuration.

  • group/item
  • group-hover/item:*
  • peer/email
  • peer-invalid/email:*
  • peer-checked/draft:*

Docs: nested groups · peers

has-*

core

Style an element based on what it contains, using the CSS :has() selector. Use a bare variant like has-checked: or any selector in brackets, like has-[img]:. It lets a card, row or field react to the state of an input or child inside it, with no script.

  • has-checked:*
  • has-focus-visible:*
  • has-disabled:*
  • has-[img]:*
  • has-[:invalid]:*
  • has-data-[state=open]:*

Docs: :has()

group-has-*

core

Mark an ancestor with group and style a descendant by what the group contains. Use it when the thing that changes is not the container itself but something inside it, like an icon that only appears if the card holds a link.

  • group-has-[a]:*
  • group-has-checked:*
  • group-has-indeterminate:*
  • group-has-disabled:*
  • group-has-[:invalid]:*
  • group-has-user-invalid:*

Docs: descendants of a group

peer-has-*

core

Mark an element with peer and style a later sibling by what the peer contains. Use it when an input is wrapped in a label or field and something next to the wrapper should react to the input's state.

  • peer-has-checked:*
  • peer-has-disabled:*
  • peer-has-[:focus]:*
  • peer-has-[img]:*

data-*

v4.0

Style an element from its data attributes. data-active: matches when the attribute is present, and data-[size=large]: matches a value. In v4 this needs no theme configuration. It is how you style components that expose their state as data-state="open", such as Radix and Headless UI.

  • data-active:*
  • data-[size=large]:*
  • data-[state=open]:*
  • data-[ui~=checked]:*
  • group-data-[state=open]:*
  • not-data-[state=open]:*

Docs: data attributes

aria-*

core

Style an element from its ARIA state, so the attribute that screen readers announce is also the one that drives the look. aria-checked: matches aria-checked="true", and aria-[sort=ascending]: matches any other value. Use it for switches, tabs, accordions and sortable headers.

  • aria-checked:*
  • aria-expanded:*
  • aria-selected:*
  • aria-pressed:*
  • aria-busy:*
  • aria-disabled:*
  • aria-[sort=ascending]:*
  • aria-[current=page]:*
  • group-aria-expanded:*
  • peer-aria-expanded:*

Docs: ARIA states

not-*

v4.0

Apply a utility only when a condition is not true. not-first: wraps the state in :not(), and it stacks with other variants, so hover:not-focus: means "hovered and not focused". Use it instead of writing a style and then undoing it for the exceptions.

  • not-first:*
  • not-last:*
  • not-empty:*
  • not-disabled:*
  • not-checked:*
  • hover:not-focus:*
  • not-data-[state=open]:*
  • not-aria-expanded:*
  • not-has-[img]:*
  • not-[.is-open]:*
  • not-group-hover:*
  • not-peer-checked:*

not- with @supports and media queries

v4.0

not- also negates variants that become @supports and @media rules: not-supports-[display:grid]:, not-sm:, not-dark:, not-motion-reduce:. Use it to write the fallback or the "otherwise" branch without a second breakpoint or a reversed query.

  • not-supports-[display:grid]:*
  • not-supports-backdrop-filter:*
  • not-sm:*
  • not-motion-reduce:*
  • not-print:*
  • not-hover:*

Docs: :not() · @supports

supports-*

v4.0

Apply a utility only if the browser supports a CSS feature. supports-[display:grid]: becomes an @supports rule, and in v4 you can check just a property name: supports-backdrop-filter:. Use it for progressive enhancement: write the simple version first, then upgrade where the feature exists. not-supports-* writes the fallback branch.

  • supports-[display:grid]:*
  • supports-backdrop-filter:*
  • supports-[(display:grid)_and_(gap:1px)]:*
  • supports-[selector(:has(*))]:*
  • supports-grid:*
  • not-supports-[display:grid]:*
  • [@supports(display:grid)]:*

Docs: @supports

in-*

v4.0

Like group-*, but with no group class: in-focus: matches when any ancestor is in that state. Use it to react to a parent you do not control, or when adding a class to the parent would be a chore. When you need to pick one specific ancestor, use group instead.

  • in-focus:*
  • in-hover:*
  • in-open:*
  • in-aria-expanded:*
  • in-data-[state=open]:*
  • in-[.demo-compact]:*

Docs: implicit groups

first, last, only, odd, even and empty

core

Style an element by where it sits among its siblings, or by being empty. These are the classic structural variants from v3. They still apply to the element that carries the class, and they compose with every v4 variant (not-first:, group-only:, first:before:).

  • first:*
  • last:*
  • only:*
  • odd:*
  • even:*
  • first-of-type:*
  • last-of-type:*
  • only-of-type:*
  • empty:*
  • group-only:*

Docs: first, last, odd and even

nth-*

v4.0

Style the Nth child, the Nth from the end, or the Nth of its tag. Pass a bare number (nth-3:) or any An+B expression in brackets (nth-[3n+1]:). The bracket form can even filter, as in nth-[odd_of_:not([hidden])]:. Use it for medals, bento layouts and repeating patterns.

  • nth-3:*
  • nth-last-2:*
  • nth-of-type-2:*
  • nth-last-of-type-1:*
  • nth-[3n+1]:*
  • nth-[-n+3]:*
  • nth-[n+4]:*
  • nth-[odd_of_:not([hidden])]:*

Docs: nth-*

*: direct children

v4.0

Style every direct child from the parent, without touching the children. It suits content you do not control, such as CMS output or a component slot. The * variant is older, but in v4 stacked variants read left to right, so *:first:pt-0 is "the first child". The v3 spelling first:*:pt-0 now means something else.

  • *:rounded-full
  • *:px-2
  • *:first:pt-0
  • *:not-first:mt-4
  • *:hover:bg-slate-100
  • dark:*:border-sky-500/15

Docs: direct children · upgrade guide

**: all descendants

v4.0

Like *:, but it reaches every descendant, not just the direct children. A bare **:p-2 would hit every element at every depth, so narrow it with another variant: **:data-avatar:size-12 or **:[a]:underline.

  • **:data-avatar:size-12
  • **:data-icon:size-4
  • **:[a]:underline
  • **:first:mt-0
  • hover:**:data-icon:*

Docs: all descendants

Arbitrary variants

core

Write your own selector or at-rule in square brackets, with & standing for the element: [&.is-dragging]:cursor-grabbing, [&_p]:mt-4, [@media(min-width:900px)]:p-8. Use underscores for spaces. They are the escape hatch for anything the built-in variants do not cover, and they stack with built-in variants.

  • [&.js-dragging]:*
  • [&_p]:mt-4
  • [&_svg:not([class*='size-'])]:size-4
  • [&:is(:hover,:focus-visible)]:*
  • [@supports(display:grid)]:grid
  • [@media(min-width:900px)]:*
  • [.js-warm_&]:*
  • [&::-webkit-scrollbar]:hidden

Docs: arbitrary variants

Arbitrary group-[…] and peer-[…]

core

Give group or peer your own selector: group-[.js-open]:block reacts to a class on the group, peer-[.js-dirty]:… to a class on the peer. Add & to say where the group sits in the selector. Use it for state that lives in a class, such as a value a script toggles.

  • group-[.js-open]:*
  • group-[.js-loading]:*
  • group-[li:nth-of-type(3)_&]:*
  • peer-[.js-dirty]:*
  • peer-[.js-dirty]:peer-invalid:*

Docs: arbitrary groups · peers

Variant stacking order

v4.0

In v4, stacked variants apply from left to right, like nested CSS: *:first:pt-0 means "the first child of this element". In v3 they applied right to left. The order only matters when a variant changes what is selected (children, ancestors, pseudo-elements). Pseudo-element variants such as before: must come last.

  • *:first:pt-0
  • first:*:pt-0
  • dark:md:hover:bg-fuchsia-600
  • group-hover:before:w-full
  • not-disabled:hover:bg-*
  • hover:not-focus:bg-*

Docs: upgrade guide

What each wrapper variant can wrap

v4.0

The compound variants (not-, has-, in-, group-, peer-) wrap another variant. They work with selector-based variants like hover or first. Only not- also wraps media and @supports variants. None of them wraps a pseudo-element. When a class generates nothing, this is the first thing to check.

  • not-hover:*
  • has-checked:*
  • in-focus:*
  • group-hover:*
  • peer-checked:*
  • not-group-hover:*

target:, focus-within:, focus-visible:, visited:

core

Four interaction and navigation states. target: is the element whose id matches the URL hash. focus-within: is an element that holds focus somewhere inside. focus-visible: is keyboard-style focus only. visited: is a link the browser has seen before.

  • target:*
  • focus-within:*
  • focus-visible:*
  • visited:*
  • group-focus-within:*
  • peer-focus-within:*

Docs: pseudo-class reference

before: and after:

core

Style the ::before and ::after pseudo-elements. Tailwind sets content to an empty string for you, so a decorative box needs no content-['']. Add text with content-['…'] or read an attribute with content-[attr(data-tip)]. Use them for markers, labels, tooltips and stretched links.

  • before:*
  • after:*
  • after:content-['*']
  • before:content-[attr(data-tip)]
  • hover:before:opacity-100
  • group-hover:after:w-full
  • after:absolute after:inset-0

Docs: ::before and ::after · content

placeholder:

core

Style the placeholder text of an input or textarea (::placeholder). Do not confuse it with placeholder-shown:, which styles the field while its placeholder is visible. Use placeholder: for colour, italics or a fade on focus.

  • placeholder:text-slate-500
  • placeholder:italic
  • focus:placeholder:text-transparent
  • placeholder-shown:border-dashed

Docs: ::placeholder

file:

core

Style the button inside <input type="file"> (::file-selector-button), which a normal class cannot reach. Put file: utilities on the input. Stack it as hover:file:bg-*, with the state of the input first.

  • file:rounded-full
  • file:bg-violet-50
  • file:px-4
  • hover:file:bg-violet-100
  • file:cursor-pointer

Docs: ::file-selector-button

marker:

core

Style list bullets and numbers (::marker). It is inherited, so one marker:text-sky-400 on a <ul> colours every bullet. It also reaches the arrow of <summary>. Browser support for properties on ::marker differs, mainly in Safari, so keep it decorative.

  • marker:text-sky-400
  • marker:font-bold
  • marker:content-['✓_']
  • group-open:marker:content-['▾_']
  • list-disc
  • list-decimal

Docs: ::marker

selection:

core

Style the text a person has selected (::selection). It is inherited, so one selection:bg-fuchsia-300 on a wrapper, or on <body>, covers everything inside. Only a few properties apply: colours, text decoration and text shadow.

  • selection:bg-fuchsia-300
  • selection:text-fuchsia-900
  • selection:bg-transparent

Docs: ::selection

first-line: and first-letter:

core

Style the first rendered line of a block (::first-line) or its first letter (::first-letter). Use them for drop caps, small-caps ledes and magazine-style openings. The first line re-wraps as the box resizes, and only typography properties apply to it.

  • first-letter:float-left
  • first-letter:text-7xl
  • first-line:uppercase
  • first-line:tracking-widest
  • nth-of-type-1:first-letter:*

Docs: first-line and first-letter

backdrop:

core

Style the ::backdrop behind a modal <dialog> or an open popover, such as a tint and a blur. The backdrop only exists while the element is in the top layer: a dialog opened with showModal(), not show(). It is not inherited, so set it on the dialog itself.

  • backdrop:bg-slate-900/50
  • backdrop:backdrop-blur-sm
  • open:backdrop:bg-black/50

Docs: ::backdrop

rtl: and ltr:

core

Apply styles by text direction, for layouts that must work left-to-right and right-to-left: ltr:ml-3 rtl:mr-3. They follow the nearest dir attribute, including dir="auto". For spacing and alignment, logical utilities such as ms-3 and text-start are often simpler. Reach for rtl: when something has to be flipped, such as an arrow.

  • ltr:ml-3
  • rtl:mr-3
  • rtl:rotate-180
  • rtl:-scale-x-100
  • ms-3
  • text-start

Docs: RTL support
