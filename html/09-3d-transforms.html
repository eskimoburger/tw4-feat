3D transforms

Tilt, flip, hinge and spin elements in 3D with perspective-*, rotate-x/y/z, translate-z-*, transform-3d and backface-hidden, plus the variables, keyframes and starting styles that make them move. In v4, hover: only applies on devices that can hover, so the hover demos here also respond to keyboard focus and to a tap.

3D rotation: rotate-x/y/z

v4.0

rotate-x-*, rotate-y-* and rotate-z-* turn an element around one axis each. They stack into one transform, always applied in the order X, Y, Z, so rotate-x-50 rotate-z-45 works in any class order. Put a perspective-* class on the parent, or the result looks squashed instead of deep.

  • rotate-x-50
  • -rotate-y-30
  • rotate-z-45
  • rotate-x-[0.6rad]
  • rotate-y-(--ry)
  • rotate-x-0

Docs: rotate, 3D space

rotate-x-12.5 generates nothing, because bare values must be whole degrees. Write rotate-x-[12.5deg] instead. There is no rotate-x-none; use rotate-x-0. Put hover: on a static wrapper such as group and rotate the child: hovering the element that is turning away makes its edge slide out from under the pointer and the card flickers.

Camera depth: perspective-*

v4.0

Sets the CSS perspective on the element, which gives its children a vanishing point. Smaller numbers feel more dramatic. It only reaches direct children, so deeper levels need transform-3d on the elements in between.

  • perspective-dramatic
  • perspective-near
  • perspective-normal
  • perspective-midrange
  • perspective-distant
  • perspective-none
  • perspective-[750px]
  • perspective-(--p)

Docs: perspective

perspective-500, perspective-1000 and perspective-sm do not exist and generate nothing. Use the five named sizes or an arbitrary value. Elements in the top layer (a popover or dialog.showModal()) do not get perspective from their ancestors, so put a perspective-* wrapper inside them. Resize the window across 768px to flip the last example.

Keep depth: transform-3d

v4.0

transform-3d sets transform-style: preserve-3d, so children live in the same 3D space as their parent instead of being flattened into its plane. Every cube, ring and layer stack needs it. transform-flat is the default and turns it back off.

  • transform-3d
  • transform-flat
  • max-md:transform-flat

Docs: transform-style

Clip and round the faces (the leaf elements), never the transform-3d parent. transform-3d does not create perspective by itself: it only keeps depth, so you still need a perspective-* ancestor. Checked in Chromium. Use max-md:transform-flat to drop a 3D scene to a plain layout on small screens.

Card faces: backface-hidden

v4.0

Decides whether the reverse side of a rotated element is drawn. Put backface-hidden on both faces of a card and only the one facing you shows, which is the whole flip-card trick. backface-visible is the default and lets translucent cube faces show their backs.

  • backface-hidden
  • backface-visible
  • *:backface-hidden
  • rotate-y-180
  • group-hover:rotate-y-180

Docs: backface-visibility

backface-hidden goes on every face, not on the container. A hidden face is not clickable (the pointer hits whatever is in front), but it is still keyboard-focusable and still read by screen readers, so pair a flip with group-focus-within: as above. Inside a <button> use <span class="block"> faces, because a button cannot contain a <div>. No -webkit- prefix is needed: Safari has read the unprefixed property since 15.4 and v4 targets Safari 16.4 and newer. Reduced motion: the coin and flap use motion-safe:, so they stay still.

State variants that drive a flip

v4.0

A flip is just rotate-y-180 behind a variant. In v4 hover: only fires on devices that can hover, so give touch and keyboard users another trigger: focus-within, aria-pressed, peer-checked or a data-* attribute. All of these work without a line of animation code.

  • group-hover:
  • group-focus-within:
  • group-aria-pressed:
  • peer-checked:
  • group-data-flipped:
  • data-[face=right]:
  • peer-hover:
  • has-[~:hover]:
  • *: *:last:
  • pointer-coarse: pointer-fine:

Docs: parent state

On a touch screen hover:, group-hover: and peer-hover: never fire (checked in mobile emulation), so always ship a second trigger. The first card above still flips on a tap because it has tabindex="0" and group-focus-within:, and the aria-pressed card flips on a tap too. peer-checked: only reaches later siblings, so the input must come first. pointer-fine: and pointer-coarse: need v4.1. The last example is for a mouse.

Depth offset: translate-z-*

v4.0

Moves an element toward or away from the viewer, using the spacing scale. It writes the standalone translate property, so it combines with translate-x-*, translate-y-* and every rotate or scale utility. The parent needs transform-3d so the layers share one 3D space.

  • translate-z-12
  • -translate-z-8
  • translate-z-px
  • translate-z-[40px]
  • translate-z-(--tz)
  • translate-3d

Docs: translate, z-axis

The browser composes translate, then rotate, then scale, then transform (the order you would write them in a transform list), so translate-z-* moves along the parent's z axis, not the element's own rotated normal. That is why a cube side is translate-x-10 rotate-y-90 and not rotate-y-90 translate-z-10; nest a rotated wrapper around a translate-z-* child for a ring (see the Keep depth card). Fractions and percentages such as translate-z-1/2 generate nothing. translate-3d and scale-3d are the three-axis forms of translate and scale; they change nothing visible on their own (the last example in the Stretch depth card reads the values live). One gotcha, checked in 4.3.3: a later class that writes only x and y, such as hover:translate-y-2, rewrites translate without z, so the element drops back to z = 0 on hover. Add hover:translate-3d or repeat hover:translate-z-8 to keep the depth. A custom transition-[transform] does not cover translate: write transition-[translate].

Hinges: origin-*

core

Picks the pivot point for every rotate, scale and skew on the element. In 3D it is the hinge: a book cover, door, envelope flap or calendar page turns around an edge instead of its centre. An arbitrary value with a third number sets a pivot in depth.

  • origin-center
  • origin-top
  • origin-left
  • origin-bottom-right
  • origin-[33%_75%]
  • origin-[50%_50%_-5.5rem]
  • origin-(--o)

Docs: transform-origin

The origin is measured from the element's own box, so origin-right on a half-width door is that door's right edge. Side and corner keywords compile to numbers (origin-left is 0, origin-top-right is 100% 0) although the docs table prints left and top right; center, top and bottom stay keywords. Translate ignores the origin; only rotate, scale and skew use it.

Vanishing point: perspective-origin-*

v4.0

Moves the vanishing point of the perspective-* set on the same element. Nine keyword positions, plus arbitrary and variable forms. Use it to make panels lean toward the content, or to tie a parallax scene to the cursor.

  • perspective-origin-center
  • perspective-origin-top-left
  • perspective-origin-right
  • perspective-origin-bottom
  • perspective-origin-[30%_70%]
  • perspective-origin-(--po)

Docs: perspective-origin

Percentages are relative to the perspective element's own box, so a bigger stage shows a bigger shift. Set it on the wrapper next to perspective-*, never on the rotating child. With perspective-none or a very large perspective the origin barely matters. The docs table prints keyword pairs, but the engine emits numbers for sides and corners (perspective-origin-top-left is 0 0).

Stretch depth: scale-z-*

v4.0

Scales an element along z, in percent like scale-x-*. On a transform-3d element it stretches or squeezes the gaps between everything inside, so one class explodes or collapses a whole layer stack. Keep the tilt (rotate-x-*, rotate-z-*) on an outer wrapper, or the z scale is hidden. On a flat element it does nothing visible.

  • scale-z-300
  • -scale-z-100
  • scale-z-[2]
  • scale-z-(--sz)
  • scale-3d

Docs: scale

The tilt goes on an outer wrapper because rotate-x-* writes transform, which the browser applies before scale. With the tilt on the same element, the layers are tilted first and the z scale only stretches that result along the viewer's axis, which barely shows. Do not use scale-z-0 as the collapsed state: it flattens every layer into one plane and the stack vanishes. scale-z-10 keeps the layers visible and nearly merged. scale-110 stores a z value too but its scale does not read it, so it stays a flat two-axis scale; scale-3d writes the three-axis form that does. translate-3d does the same for translate, but it only matters if you set --tw-translate-z by hand. You do not need either with scale-z-* or translate-z-*, which already write the z part. The same gotcha applies to scale: scale-z-150 hover:scale-110 drops the z part on hover, and hover:scale-3d would only bring back 110%, so repeat hover:scale-z-150 to keep it. scale-3d is in the docs table; translate-3d is not.

Variables in 3D: (--var) and calc()

v4.0

The parenthesis shorthand turns any 3D utility into a variable reader: rotate-x-(--rx), translate-z-(--tz), perspective-(--p). A few lines of script that only call style.setProperty can then drive a whole scene, and Tailwind never has to recompile because the class names do not change.

  • rotate-x-(--rx)
  • rotate-y-(--ry)
  • translate-z-(--tz)
  • scale-z-(--sz)
  • perspective-(--p)
  • rotate-y-[calc(var(--s)*-55deg)]
  • pointer-fine:rotate-x-(--rx)
  • bg-radial-[at_var(--gx)_var(--gy)]

Docs: rotate, custom value

Give every variable a unit and a default ([--rx:0deg]): a unitless value makes the whole transform invalid, and an unset variable drops that axis, so the element snaps flat either way. Add a short transition-transform duration-150 ease-out to smooth pointer tracking, and motion-reduce:transition-none. Do not put overflow-hidden on a tilting transform-3d card; round and clip the leaf layers instead. pointer-fine: (v4.1) keeps the tilt off touch screens, where there is no hover to track.

3D loops with @theme keyframes

v4.0

Define --animate-* and its @keyframes inside @theme and Tailwind generates an animate-* utility. Production builds only emit the keyframes when the animation is used. Keyframes that animate transform or rotate give you spinning cubes, rings and coins.

  • --animate-cube-spin
  • motion-safe:animate-cube-spin
  • motion-reduce:animate-none
  • hover:[animation-play-state:paused]
  • animate-[ring-spin_20s_linear_infinite]

Docs: animation, theme

A keyframe that sets transform overrides rotate-x-* and rotate-y-* on the same element, because animations beat normal declarations. Three ways out: bake the tilt into the keyframes (the cube), put the tilt on a parent (the ring), or animate rotate: and translate: instead (the turntable). To reuse the same keyframes with other timing, write animate-[ring-spin_20s_linear_infinite]; a production build keeps the keyframes for it too. Always pair loops with motion-safe: so people who ask for less motion get a still scene; the cube falls back to a fixed tilt.

3D entrances with starting:

v4.0

The starting: variant wraps a utility in @starting-style, so an element that was just inserted or shown can transition from a rotated, transparent state to its resting state with no animation code. Combined with 3D rotation it gives fold-in toasts, swing-open dialogs and unfolding popovers.

  • starting:-rotate-x-90
  • starting:rotate-y-90
  • starting:opacity-0
  • starting:open:opacity-0
  • transition-discrete
  • open:

Docs: @starting-style

Browser support: @starting-style works in Chrome and Edge 117+, Safari 17.5+ and Firefox 129+; the popover attribute is in all current browsers. Without it the element simply appears at its resting state. The resting state has to be explicit in the base classes (rotate-x-0, opacity-100), or there is nothing to transition to. Ancestor perspective does not reach top-layer elements, so each popover and dialog carries its own perspective-near wrapper. Dialogs have no exit animation here; the entrance runs each time showModal() is called.

Separate rotate, scale, translate

v4.0

In v4, rotate-45, scale-110 and translate-x-2 write the standalone CSS rotate, scale and translate properties instead of one big transform. Each can be transitioned, reset and timed on its own, and an arbitrary rotate value can carry an axis for 3D.

  • rotate-45
  • scale-110
  • translate-x-2
  • rotate-none
  • scale-none
  • translate-none
  • rotate-[x_45deg]
  • rotate-[1_1_0_45deg]
  • transition-[opacity,scale]

Docs: upgrade guide

Since v4, transform-none no longer clears rotate-45, scale-110 or translate-x-2; it only clears rotate-x/y/z, skew-* and arbitrary transform values. Reset the individual properties with rotate-none, scale-none and translate-none. A custom transition-[opacity,transform] no longer animates them either: write transition-[opacity,scale]. On one element the browser composes translate, then rotate, then scale, then transform. rotate-45 and rotate-z-45 both turn around z but live in different properties.

Shear: skew-*

v4.0

2D shear. skew-x-* and skew-y-* work as in v3; the both-axes skew-* shorthand is new in v4. They still write transform, so they compose with rotate-x/y/z and are cleared by transform-none. The skew helper variables do not inherit, so a child can apply the opposite skew and keep its text upright.

  • skew-3
  • -skew-x-12
  • skew-y-3
  • skew-[3.142rad]
  • skew-x-(--sx)
  • md:-skew-y-2

Docs: skew

Bare skew values must be whole degrees: skew-x-12.5 generates nothing, so write skew-x-[12.5deg]. transform-none removes skew, but rotate-none, scale-none and translate-none do not. The counter-skew trick needs inline-block on the label, since a transform does not apply to a plain inline element.

The transform-* family

v4.0

The old transform helpers still exist, but transform-none changed in v4 (see the last example), and the docs now list arbitrary and (--var) values for transform-*. transform-gpu adds translateZ(0) to the composed rotate-x/y/z and skew transform as a compositing hint, transform-cpu is the plain composition, and transform-none clears transform. An arbitrary value writes any transform list, including a per-element perspective().

  • transform-gpu
  • transform-cpu
  • transform-none
  • transform-[perspective(600px)_rotateY(-18deg)]
  • transform-(--t)
  • md:transform-none

Docs: transform

An arbitrary transform-[…] replaces the whole composed transform on that element, so rotate-x-* and skew-* classes beside it stop having any effect. Computed values show the same matrix for transform-gpu and transform-cpu; only the declared list differs. Resize the window across 768px to see the last example change.

Pivot box: transform-box utilities

v4.0

Sets the box that origin-* keywords and percentages are measured against. An SVG shape starts with the whole viewBox, so origin-center turns it around the middle of the drawing; add transform-fill and it turns around the shape itself. On HTML elements the choice is the border box or the content box. These five utilities are in the engine but not on a docs page yet.

  • transform-view
  • transform-fill
  • transform-stroke
  • transform-content
  • transform-border
  • transform-fill origin-center

Docs: transform-origin · MDN: transform-box

transform-box only picks where origin-* measures from. It changes nothing unless the element also turns, scales or spins, and the origin is a keyword or percentage; an origin-[88px_60px] point is typed in directly. It is not inherited, so put it on the element that has the transform. SVG shapes start at transform-view, with a pivot at the top-left corner of the viewBox. On SVG, transform-content acts like transform-fill and transform-border like transform-stroke. HTML elements start at transform-border; there transform-fill and transform-content both mean the content box, while transform-stroke and transform-view mean the border box. Checked in Chromium. These classes do not touch the transform property, so they are unrelated to transform-gpu and transform-none. Every current browser supports transform-box. With reduced motion on, the spinners stay still.

Your own depths, hinges and angles in @theme

v4.0

Name a camera distance, a hinge, an angle or an easing once, and use it as a utility everywhere. --perspective-* and --ease-* are documented. --transform-origin-* and --rotate-* are not in the theme docs table, but the utilities read them and they work in 4.3.3. Skip --perspective-origin-*: its name sits inside --perspective-*, which breaks the camera (see below).

  • --perspective-remote
  • --transform-origin-hinge
  • --rotate-flip
  • --ease-flip
  • rotate-y-flip
  • origin-hinge

Docs: perspective, theme

Theme variableMakesBuilt inIn the theme docs
--perspective-* perspective-* dramatic 100px, near 300px, normal 500px, midrange 800px, distant 1200px Yes
--perspective-origin-* perspective-origin-*, and also perspective-* None (the keywords are built into the utility) No. Avoid it: the same class also writes perspective
--transform-origin-* origin-* None (the keywords are built into the utility) No, works in 4.3.3
--rotate-* rotate-*, rotate-x-*, rotate-y-*, rotate-z-* None No, works in 4.3.3
--ease-* ease-* in, out, in-out Yes

Theme variables are CSS variables, so you can read the defaults in your own CSS (var(--perspective-near)) or override them site-wide. The extra perspective line in that last block is real: perspective-origin-stage matches both utilities, and because it sorts after perspective-near (and every built-in size) it wins and turns the camera off. Checked in 4.3.3 with perspective-near perspective-origin-stage: the computed perspective is none. Use perspective-origin-[50%_20%] or perspective-origin-(--po) instead. Only --perspective-* and --ease-* are documented here, so treat --transform-origin-* and --rotate-* as an implementation detail that could change.

Scroll-driven tilt with a custom @utility

v4.0

Tailwind has no scroll-timeline utilities, but one @keyframes plus one @utility that sets animation-timeline: view() is enough. Cards in a scroll-snap row tilt and scale by their position in the scroller, with perspective on the scroll container and no JavaScript.

  • @utility cf-view
  • animation-timeline: view(inline)
  • snap-x snap-center
  • perspective-[800px]
  • supports-[animation-timeline:view()]:*

Docs: @utility

Browser support: Chrome and Edge 115+, Safari 26+. Firefox has scroll-driven animations behind a flag at the time of writing, so check caniuse. The @supports inside the utility keeps cards flat and readable elsewhere; without it an unsupported browser would jump every card to the last keyframe. The keyframes animate transform, so do not also put rotate-y-* on the cards. Each card also has motion-reduce:animate-none, so with reduced motion on the row stays flat. perspective-* goes on the scroll container, whose cards are its direct children. For a version that works everywhere with a little JavaScript, see the variable-driven coverflow above.

zoom-* next to scale-*

v4.3

New in v4.3: utilities for the CSS zoom property. Unlike scale-* and the 3D transforms, zoom changes the element's layout size, so neighbours move out of the way and text stays crisp. It is not a 3D transform; this card is here to show where each one fits.

  • zoom-75
  • zoom-125
  • zoom-[1.1]
  • zoom-(--preview-zoom)
  • hover:zoom-125

Docs: zoom

zoom-* shipped in v4.3, and the v4.3 post notes it is now supported in all major browsers. The default transition list covers scale but not zoom, so animate it with transition-[zoom]. Zoom reflows the layout, so reach for it when a preview or a density switch should take real space, and for scale-* when you want a paint-only effect. More on the v4.3 utilities is on the Scrollbars, zoom & tabs page.
